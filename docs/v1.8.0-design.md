### 0.1 廉价替代原型验证结论（item C，已通过）

`/tmp/roi/cancel_proto.py` + `cancel_proto2.py`（本地 SSE 服务端中途 stall，另一线程取消）：

| 取消机制 | 客户端解除阻塞 | 时延 | 判定 |
| :--- | :--- | ---: | :--- |
| `response.close()`（另一线程） | ✅ 但等满 socket 超时 | **29.08 s** | ❌ 不达标 |
| **`resp.fp.raw._sock.shutdown(SHUT_RDWR)`** | ✅ 立即 | **0.0002 s** | ✅ **PASS** |
| `resp.fp.raw._sock.close()` | ❌ 不解除 | >5 s | ❌ 不达标 |
| `socket.fromfd(resp.fileno()).shutdown(...)` | ✅ 立即 | 0.0051 s | ✅ PASS |
| `http.client conn.sock.shutdown(...)` | ✅ 立即 | 0.0051 s | ✅ PASS |

**关键结论（设计约束）：** 只有 `shutdown(SHUT_RDWR)` 能打断阻塞读；`close()` 与
`response.close()` 都**不能**。因此实现必须用 `shutdown`，不能退化为 `close`。
三种 socket 句柄获取路径均可用（`resp.fp.raw._sock` / `socket.fromfd(resp.fileno())` /
`http.client conn.sock`）——实现采用**分层获取 + 失败降级**（见 §3.4）。

降级产物当然能过 `bash -n`。按**原始转换产物**口径，PS 侧实测为 **45/60 = 75.0%**。

### 1.2 v1.8.0 口径（正式定义）

| 指标 | v1.8.0 定义 | 备注 |
| :--- | :--- | :--- |

| 崩溃类 | 转换器抛出未捕获异常的脚本数 | 必须 = 0 |

### 1.4 双口径必须同时被测出（验收标准第 5 条）

新增 `tests/test_real_corpus_metrics.py`：断言两个口径的数字**都被测出并按约定门槛判定**，

### D1 — `try` 块内 `elseif` 开链整段丢失

**现象：** `try { if (…) {…} elseif (…) {…} else {…} } catch {…}` 转换后，
`if`/`elseif` 开链整体消失，只剩孤立的 `else`/`fi`，产物 `bash -n` 失败；
`$path` 等分支内赋值随之丢失，引用处报 `unbound variable`。

**最小复现（已验证）：**
```powershell
try {
    if ($x)     { $a=1 }
    elseif ($y) { $a=2 }
    else        { $a=3 }
} catch { $b=3 }
```
```bash
# 现状输出（`bash_check=False`）
set -euo pipefail
else
fi
    b=3
fi
```
对照：去掉 `try` 包裹后，同一 `if/elseif/else` 转换**正确**。

**根因（已定位）：** `python/bat2sh/core/powershell.py`
- `_close_block_line` 的 `elseif` 分支（`:3249-3254`）先执行 `closing = self._stack.pop()`
  （弹出前一 `if` 分支臂），随后调用 `_emit_condition_block(..., "elseif", ...)`；
- `_emit_condition_block`（`:1444-1446`）对 `keyword == "elseif"` **再次** `self._stack.pop()`；
- **顶层**（栈内只有该 `if`）时第二次 pop 命中空栈 → 无害，缺陷潜伏；
  **`try` 内**时栈内还有 `try` 块 → 第二次 pop 把 `try` 块弹掉 → 块栈与 `catch` 锚点失同步
  → `catch` 找不到 `try` 块 → 结构崩坏。

这也解释了「为何 `try { if/else }` 正常、`try { if/elseif/else }` 崩坏」。

**修复策略：**
1. `elseif` 的 pop 责任**唯一化**：由 `_emit_condition_block` 独占；`_close_block_line`
   改为**窥视**（`self._stack[-1]`）做空分支判定，不再预先 pop。
2. 增加不变量断言（仅测试期）：块栈深度在 try/catch 处理前后守恒。
3. 回归点：`tests/test_powershell_try_dispatch.py`（既有）+ 新增
   `tests/test_powershell_block_stack.py`，覆盖「顶层 if/elseif」「try 内 if/elseif/else」
   「try 内 if/else」「嵌套 try」四组，每组断言结构完整 + `bash -n` 通过。

**真实语料回归用例：** `cd-jenkins.ps1`、`check-admin.ps1`、`cd-repo.ps1`。

**风险：** 块栈是全转换器最热的共享状态；改 pop 责任可能影响 `switch`/`while`/`forEach`
的收尾。缓解：先补覆盖既有块结构的回归测试，再改；全量 pytest 强制。

### D2 — 独立字符串语句未转 `echo`

**现象：** PS 中作为语句的裸字符串（含插值）被原样发出，bash 将其当**命令名**执行
→ `command not found`（rc 127）。例：`cd-up.ps1` 的 `"📂$path"` → 沙箱报
`📂/tmp/roi/runs: No such file or directory`。

**最小复现（已验证）：**
```powershell
$path = "/tmp"
"📂$path entered"
```
```bash
# 现状输出（warn: 未知命令 '📂$path entered'）
path="/tmp"
"📂${path} entered"        # ← 被当命令执行
```

**根因（已定位）：** `powershell.py::_convert_cmdlet_line`（`:2392` 起）把首 token 当作命令名；
引号字符串不在任何映射表中，落到文件末尾的**未知命令兜底透传**（`:2437-2439`）：
```python
self._warn(lineno, f"未知命令 {name!r}，请确认 Linux 下可用", text, category="command")
return self._convert_expression(text, lineno)   # 原样透传
```

**修复策略：**
1. 在未知命令兜底**之前**增加判定：若整条语句是**纯字符串字面量/插值**
   （去空白后首尾均为引号，且引号外无其它 token），按 PowerShell 语义（写入管道 → 打印）
   转换为 `echo <字面量>`（保持插值改写）。
2. 仅匹配「整条语句就是一个字符串」，不做任何自由文本猜测（守纪律 1、7）。
3. 保留 `# TODO` 语义：若字符串内含无法转换的表达式（如 `$($files.Count)`、内嵌 cmdlet），
   仍走 TODO，不强行 echo。

**回归点：** 新增 `tests/test_powershell_bare_string.py`：纯字符串、带变量插值、带
`$()` 子表达式（应 TODO）、单引号（不插值）四组。
**真实语料回归用例：** `cd-up.ps1`、`cd-up2.ps1`、`cd-up3.ps1`、`cd-up4.ps1`。

**风险：** 可能把「本应报未知命令的非法语句」误判为字符串输出。缓解：判定条件严格
（整条就是引号包裹的字符串），并有负向测试（如 `foo "bar"` 不得转 echo）。

### D3 — 命令/函数调用作赋值 RHS 未转换【静默错误】

**现象：** `$path = GetTempDir`（无参函数/cmdlet 调用）被转换为 `path="GetTempDir"`
——赋成了**字面字符串**，产物是合法 bash 且**零告警指向该语义错误**。
`cd-temp.ps1` 运行时因此报 `The temporary folder at 'GetTempDir' doesn't exist`。

**最小复现（已验证）：**
```powershell
function Foo { return "x" }
$v = Foo
```
```bash
# 现状（warn: 无法确定右值类型，已按字符串处理）
Foo() { echo "x"; return 0 }
v="Foo"        # ← 应为 v="$(Foo)"
```

**根因（已定位）：** `_emit_assignment`（`:1890`）的通用 RHS 回退——`rhs` 首 token 是
已登记函数（`self._function_map`）或已知 cmdlet 时未走「命令替换」路径，而是按字符串字面量发射
（伴随 `无法确定右值类型` 警告，`category=misc`）。

**修复策略：**
1. RHS 为**单个标识符**（无空格、无操作符）且该标识符在 `_function_map` 或命令映射表中时，
   发射 `name=$(<converted command>)`。
2. 若函数/cmdlet 需要参数但未给，仍按命令替换（调用方约定由函数体负责）。
3. 无法判定为调用时，保持现状（按字符串处理）——**不做猜测**。
4. 升级告警：当 RHS 形如已知函数名却按字符串处理时，警告升级为显式「疑似函数调用未转换」，
   避免静默。

**回归点：** 新增 `tests/test_powershell_assignment_call.py`：已知函数、已知 cmdlet、
未知标识符（保持字符串）、带参数调用四组，均含 `bash -n` 与断言。
**真实语料回归用例：** `cd-temp.ps1`、`cd-logs.ps1`、`cd-screenshots.ps1`。

**风险：** 可能把「本意就是字符串」的赋值误改为命令替换。缓解：仅在标识符**已登记为函数
或已知命令**时转换，并在语料上验证无回归。

### D4 — `-like` 通配模式含空格未加引号

**现象：** `$Name -like "*-generic *"` 转换为 `[[ ${Name:-} == *-generic * ]]`——
RHS 模式被去掉引号后含空格，bash 解析为两个词 → `syntax error in conditional expression`。
`check-cpu.ps1` 即此例（`:25`）。

**最小复现（已验证）：**
```powershell
if ($Name -like "*-generic *") { "match" }
```
```bash
# 现状（语法错误）
if [[ ${Name:-} == *-generic * ]]; then
```

**根因（已定位）：** `_like_operands`（`:1585-1588`）对 RHS 执行 `right.strip("\"'")`
去引号以便通配，但**未处理模式内含空格**的情况。

**修复策略：**
1. 去引号得到通配模式后，若模式含空格/特殊字符，转换为**带引号**的右侧
   （bash `[[ … == "pat" ]]` 中引号内通配符仍生效）：`[[ ${x:-} == "*-generic "* ]]`。
2. 或改用 `[[ ${x:-} == *-generic\ * ]]` 转义空格——二选一，实现时以「引号」为准（更清晰）。
3. 保持 `-notlike` 同步（取反对应在完整比较式上施加）。

**回归点：** 新增 `tests/test_powershell_like_pattern.py`：无空格模式（不改变现状）、
含空格模式、`-notlike`、开头/结尾通配 四组，均断言 `bash -n` + 匹配行为。
**真实语料回归用例：** `check-cpu.ps1`。

**风险：** 引号化可能破坏既有的无空格通配匹配（`== *.txt` 不受影响，需测试守护）。

### D5 — 未定义变量在 `set -u` 下 unbound

**现象：** PowerShell 中引用未赋值变量展开为空串；转换产物由 `set -euo pipefail` 保护，
`"${path}"` 在未赋值时**中止脚本**（`path: unbound variable`）。语料中 `cd-home`、`cd-root`、
`check-bios`、`check-gpu`、`check-independence-day` 等均因此失败。

**最小复现（已验证）：**
```powershell
if (-not(Test-Path "$path" -pathType container)) { throw "Folder at $path missing" }
```
```bash
# 现状：条件里用了 ${path:-}（安全），但 throw 的 echo 里用了 ${path}（unbound）
if [[ !(-d "${path:-}") ]]; then
    echo "Folder at ${path} missing" >&2; exit 1
fi
```

**根因（已定位）：** `_replace_vars`/`_replace_var_at`（`:333`、`:383`）对普通变量统一发射
`${name}`，无「可能未定义」判定；而 `_test_path_expr`（`:1598`）等个别路径已用 `${name:-}`——
**同一变量在两条路径下不一致**。

**修复策略：**
1. 引入**保守可用性判定**：若变量在当前作用域内**没有已知的赋值前驱**，发射 `${name:-}`
   （空默认，符合 PS 语义）。
2. 已知赋值（同作用域先赋值/函数参数/`foreach` 变量）时维持 `${name}`，保留 `set -u` 的
   真实拼写错误保护。
3. 判定必须保守：**宁可 `${name:-}`（偏安全）**，不得漏判导致 unbound。
4. 该改动同时消除「PS 允许未定义变量」与 bash `set -u` 的语义冲突，属规则级、非激进映射。

**回归点：** 新增 `tests/test_powershell_undefined_var.py`：先赋值后引用（维持 `${x}`）、
未赋值引用（`${x:-}`）、函数参数、循环变量、条件与字符串两处引用一致 五组。
**真实语料回归用例：** `cd-home.ps1`、`cd-root.ps1`、`check-bios.ps1`、`check-gpu.ps1`。

**风险：** `set -u` 拼写保护会被部分削弱（无法区分「未定义」与「拼错」）。缓解：只对
**预扫描未见赋值**的变量使用 `:-`；并保留 `--no-strict` 路径不变。

### D6 — `+=` 复合赋值丢失基值【静默错误】

**现象：** `$path += "\AppData"` 转换为 `path="\AppData"`——**覆盖**而非追加，
丢失原值。`cd-crashdumps.ps1` 即此例（`:23`）。

**最小复现（已验证）：**
```powershell
$path = Resolve-Path "~"
$path += "\AppData\Local\CrashDumps"
```
```bash
# 现状
path=$(realpath "~")
path="\AppData\Local\CrashDumps"     # ← 应为 path+="…"
```

**根因（已定位）：** `_emit_assignment` 接收 `op` 参数但通用路径忽略它，统一按 `=` 发射。

**修复策略：** `op == "+="` 时发射 `name+="<converted rhs>"`（字符串拼接语义），
并保留既有的算术 `+=` 判定（若右侧为数值表达式，走 `name=$(( … ))`）。

**回归点：** 新增 `tests/test_powershell_plus_assign.py`：字符串追加、数值追加、数组追加
（若支持）三组，含运行断言。
**真实语料回归用例：** `cd-crashdumps.ps1`、`check-apps.ps1`（`$reply += …`）。

**风险：** 低。`+=` 语义在 PS 中即「追加」。

### D7 — `Get-ChildItem -attributes Directory/!Directory` 过滤语义丢失【静默错误】

**现象：** `-attributes Directory`（只要目录）与 `-attributes !Directory`（只要文件）
**被转换为同一个 glob** `${p}/*`，两者产出相同，`$files`/`$folders` 语义错误。
`cd-desktop.ps1`、`cd-users.ps1` 等。

**最小复现（已验证）：**
```powershell
$folders = Get-ChildItem $p -attributes Directory
$files   = Get-ChildItem $p -attributes !Directory
```
```bash
# 现状：两者完全相同
folders=("${p}"/*)
files=("${p}"/*)
```

**根因（已定位）：** `cmd_get_childitem`（`:2520`）/`_parse_childitem`（`:2126`）解析
`-attributes` 后未把「只要目录 / 只要文件」映射到不同的 glob 表达式。

**修复策略：**
1. `-attributes Directory` → `for` 项仅目录：使用 `"${p}"/*/`（glob 以 `/` 结尾匹配目录）
   或 `find -maxdepth 1 -type d`（二选一，优先纯 glob 以保持无外部依赖）。
2. `-attributes !Directory` → 仅文件：`"${p}"/*` 但排除目录（glob + `[[ -f ]]` 过滤）。
3. 无法安全表达的属性组合（如 `Hidden+System`）保持 TODO + 警告，不猜测。
4. 该修复需保证 nullglob 语义与既有「无匹配时数组为空」行为不变。

**回归点：** 新增 `tests/test_powershell_childitem_attributes.py`：目录/文件/无过滤/
不可映射属性四组，含真实临时目录的运行断言。
**真实语料回归用例：** `cd-desktop.ps1`、`cd-users.ps1`。

**风险：** glob 目录匹配在空目录/权限受限时行为差异；用运行断言 + 沙箱语料守护。

## 3. 主体二：廉价替代根治遗留项 1（socket 阻塞读可中断）

### 3.1 目标行为契约（验收标准第 5 条）

| 契约 | 要求 |
| :--- | :--- |
| **「停止」即时生效** | 从用户按键（GUI「停止」/ CLI Ctrl+C）到在途请求进程退出 **< 1s** |
| 在途请求标记 | 被取消的任务状态置 **`skipped`**（非 `failed`） |
| 期间不写盘 | 取消过程中**不写任何文件**（写盘仍只在用户确认「应用」之后） |
| chunk 间 30s 空闲超时 | **不变**（`provider.py` socket timeout 语义原样保留） |
| `enable_thinking` 降级 | **不变**（400/422 → 去掉参数重试 + 记忆 + 告警） |
| 不引入 asyncio | 保持线程模型；stdlib-only（无新第三方依赖） |

### 3.2 设计决策：为何不用 asyncio

依据 `docs/v1.8.0-roi.md` §4：asyncio 需重写 `provider.py`（447 行）+ `parallel.py`（444 行）
+ GUI/CLI 桥接 + 4 个测试文件，高风险、与主体一零协同；而 `<shutdown>` 方案
（原型已 PASS）以约 1 个文件的改动达成同一用户可感知目标。故**不按裁定表执行 asyncio**。

### 3.3 机制设计：Cancel-aware Transport

**核心：** 让 transport 记录每条在途请求的 socket 句柄；取消时对所有在途 socket 执行
`shutdown(SHUT_RDWR)`。

```
┌────────────┐  request_stream()   ┌──────────────────────┐
│  Provider  │ ──────────────────► │ CancelAwareTransport │
│            │ ◄──── (status, it)  │  registry: set[resp] │
└────────────┘                     └──────────┬───────────┘
       ▲                                      │ cancel_in_flight()
       │ cancel_in_flight()                   ▼
┌──────┴──────┐                     shutdown(SHUT_RDWR) × N
│ parallel /  │  ← GUI _request_stop / CLI KeyboardInterrupt
│ GUI / CLI   │
└─────────────┘
```

**接口（新增，`core/api/provider.py`）：**

1. `class TransportCancelledError(TransportError)` —— 标记「因取消而中断」，非网络错误。
2. `class CancelAwareTransport(UrllibTransport)`（或给 `UrllibTransport` 增加注册表）：
   - `request_stream(...)`：在 `urlopen` 成功后 **立即获取并登记 socket**，返回
     `(status, iterator)`；迭代结束（`finally`）时**注销**。
   - `cancel_in_flight() -> int`：对所有登记 socket 执行 `shutdown(SHUT_RDWR)`，返回命中数；
     已 shutdown 的句柄标记为 cancelled，后续读取若抛出则分类为 `TransportCancelledError`。
3. `OpenAICompatibleProvider.cancel_in_flight()` —— 委托给 transport（`Provider` 协议增补可选方法）。

**socket 句柄获取（分层，全部经原型验证）：**
```python
def _socket_of(response) -> socket.socket | None:
    raw = getattr(getattr(response, "fp", None), "raw", None)
    sock = getattr(raw, "_sock", None)
    if isinstance(sock, socket.socket):
        return sock
    try:                                    # 公开 API 回退（原型 PASS）
        return socket.fromfd(response.fileno(), socket.AF_INET, socket.SOCK_STREAM)
    except OSError:
        return None
```
- 主路径 `resp.fp.raw._sock`（无 fd 复制，无泄漏）；回退 `socket.fromfd`（**需在使用后
  `close()` 该副本**，实现时必须处理）；两者都失败 → 记录并退化为「协作式取消」
  （现状行为，最坏等一个空闲超时），**不得崩溃**。

**取消语义（关键，避免误判与重试）：**
- `shutdown` 在 `urllib` 下表现为**流正常结束（EOF）**（原型观察 `raised=None`），
  无法仅凭异常区分「取消」与「正常完成」。
  ⇒ transport 维护 `cancelled` 标记；`_iter_lines`/`_consume_stream` 在
  「流结束但未收到 `[DONE]`/`finish_reason`」时，若 `cancelled` → 抛
  `TransportCancelledError`，而**不是** `ProviderProtocolError`。
- `complete_stream`：捕获 `TransportCancelledError` → 抛
  `ProviderCancelledError(ProviderError)`（新增），该异常**不在 `RETRYABLE_ERRORS`**
  ⇒ 不会退避重试。
- `parallel.execute()`：`except ProviderError` 分支**先判 `cancel.is_set()`** → 置
  `STATUS_SKIPPED` 并 `return False`（不评估建议、不写盘）。

### 3.3.1 硬约束：取消机制**绝不可退化为 `close()`**

**原型已证（`/tmp/roi/cancel_proto.py`，本地 3.14.7 实测）：**

| 机制 | 能否打断阻塞读 | 实测时延 |
| :--- | :--- | ---: |
| `sock.shutdown(SHUT_RDWR)` | ✅ **只有它能** | 0.0002 s |
| `resp.fp.raw._sock.close()` | ❌ 不能 | > 5 s |
| `response.close()` | ❌ 不能（只是提前触发超时） | 29.08 s |

**因此：** 取消路径**必须**使用 `shutdown(SHUT_RDWR)`；任何情况下**不得**用
`close()` / `response.close()` 代替（它们会让「停止」退回 30s 空闲超时，等同遗留项 1 复现）。

**该约束必须由显式断言测试守护**（防止未来重构误改），见 §3.6 第 8 条：
- 断言取消实现调用了 `shutdown` 且**未**调用 `close`（以 spy/monkeypatch 记录调用）；
- 断言把 `shutdown` 替换为 `close` 时，`<1s` 断言**必然失败**（负向对照，锁定语义）。

> **v1.7.0 遗留项 1（socket 阻塞读不可中断）在本版本关闭。**
> 关闭后的行为契约：用户触发停止后，在途请求的阻塞读被 `shutdown(SHUT_RDWR)` 立即打断，
> 任务置 `skipped`，进程在 **< 1s** 内结束；chunk 间 30s 空闲超时与 `enable_thinking`
> 降级逻辑保持不变。若某 socket 句柄无法获取（分层获取全部失败），退化为协作式取消并

### 3.6 测试点（验收标准第 5 条）

新增 `tests/test_api_cancel.py`（本地 `FakeTransport` + 真实 stall 服务端两种）：

1. **停止 < 1s**：stall 服务端 + 另一线程 `cancel_in_flight()` → 断言任务 `skipped`
   且耗时 < 1.0s（原型已证 0.0002–0.005s，留足裕量）。
2. **在途请求标 `skipped`**：断言状态为 `STATUS_SKIPPED` 且**非** `FAILED`。
3. **期间不写盘**：以 spy 包装写盘入口，断言取消路径零调用。
4. **30s 空闲超时不变**：既有 `test_api_provider.py` 回归 +
   新增「无取消时 stall 超过空闲超时仍报超时」用例。
5. **`enable_thinking` 降级不变**：既有降级测试回归（400/422 → 去参数重试 + 记忆 + 告警）。
6. **句柄获取失败降级**：注入无 socket 的假响应 → 断言不崩溃、退化为协作式取消并告警。
7. **无重试**：断言取消后不进入退避重试。
8. **绝不能退化为 `close()`（硬约束，§3.3.1）**：
   - spy/monkeypatch 记录取消路径的 socket 调用，断言**调用了 `shutdown`** 且**未调用 `close`**；
   - 负向对照：把实现换成 `close()` 时 `<1s` 断言必须失败（锁定语义，防止未来重构误改）。
