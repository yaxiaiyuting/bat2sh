## 4. 回滚策略（每 Stage 可回滚）

| 情形 | 动作 |
| --- | --- |
| 某 Stage 触发 D1/D2/D4 失败 | **立即 `git reset --hard <该 Stage 前 commit>`**，分析后重试 |
| 某 Stage 触发 053 覆盖文件变化且无法解释 | 回滚该 Stage |
| 某 Stage 引入静默错（产物行为错 / 丢行 / 无诊断蒸发） | 回滚该 Stage |
| **连续 2 个 Stage 回归无法修复** | **放弃实现**，写报告（回滚到 `5da34eb`） |
| A1 回归（`__bat2sh_snap_*` 语义变化） | **停**，回滚，报告 |
| 改动 > 10 模块 | **停** |
| HEAD 变化（并发写入） | **停**，报告 |

**HEAD 回滚点 = `5da34eb`**（= `main` = `origin/main`）。
每个 Stage 结束（commit 后）记录该 Stage 的 commit hash，作为下一 Stage 的回滚锚点。

## 5. 为什么本设计「不需要触碰 053/A1 也能达成目标」

- §2 的实现面（`_prescan` / `_convert_goto`）**不在** 053 的块栈发射层，也**不在** A1 的
  `env_repl`/marker 热路径。
- Stage B（若落地）对不可达区间做**注释化**：只产生 `#` 行，**不 push/pop 任何 `_Block`**，
  因此不改变 `_pop_block`/`finish_parent`/marker 的行为。
- 反之：任何需要「在标签处发射 `while`」或「把块内 goto 映射为 break/continue」的形态
  （`backward_loop` / `in_block_goto` / `label_in_block`）**必然**触碰 `_label_line`/块栈
  → 本 session **不做**，给显式诚实 TODO（见 review 裁定）。
