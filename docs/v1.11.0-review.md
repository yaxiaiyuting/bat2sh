### 1.2 不做什么（明确排除）

- **不触块栈核心**：`_convert_for` 头部正则（LF-1）、`_pop_block`、`if`/`for` 头部条件（B1 已知限制）。
- **不触 A1 热路径**：`_expand_vars` / `env_repl` / 占位符与 snaphot 机制。
- **不改词法层**：引号/命令替换/重定向切分（`utils.py`）。
- **不做解析级输出适配**（1.x 红线，B2）：`ipconfig`/`dxdiag` 输出取位。
- **不映射注册表写**（L4/2.x）；**不发明映射**（纪律 7：缺 evidence 拒绝）。
- **不动 `sc`/`goto`/`regsvr32`**（v2.0 / 终态）。
- **不改版本以外的打包/发布脚本以外的任何产品行为**（除下述逐项映射）。

### 1.3 范围与任务书的差异（关键）

任务书预期「保守翻转 21，理想 46（达成 ≤41）」。实测**可做子集 A 档仅 2 项**、
A+B+C 档合计 **≤7 项**（冷启动 §3.3/§3.4）。**范围必须整体收窄。**

## 2. 风险（逐项）

| 项 | 改动 | 具体风险 | 缓解 |
| :--- | :--- | :--- | :--- |
| `for /r` → `find` | `batch.py` `_convert_for` 新增 `/r` 分支 | ① `for /r %%i in (.)` 语义是「递归列目录（含目录本身）」；`find` 默认只列**路径**不列内容，`-type f/-type d` 需选择 → 可能造「看似对」的错译；② `for /r "C:\tmp" %%a in (.)` 带根路径形式；③ 递归深度/隐藏目录差异 | 仅在**可静态确定**的窄形态转换（`in (.)` + `do` 为单命令）；其余保持现 TODO；examples 零漂移为准；**新增测试断言语义**（纪律 14） |
| `for /f` 字符串形式 | `batch.py` `_convert_for` 新增 `in ("字面量")` | ① cmd 的 `tokens/delims`/`skip` 切分语义需精确复刻，否则错译；② `!vtd!` 延迟展开与外层变量的交互 | 仅支持**字面量/单一变量**且无 `usebackq` 歧义；`%%x` 切分用 `IFS` 显式建模 + 测试锁定 |
| `net user X /delete` → `userdel` | `rules.py`/`windows_tools.py` + `batch.py` | ① `userdel` 需 root，沙箱内 rc≠0 → 可能把 degraded 变成 rc≠0（**指标倒退**）；② `net user` 其他形态（`/add`、无参列出）语义不同 | 仅映射 `/delete` 单一形态；**其余保持 TODO**；语料 `删除用户.bat` 的运行 rc 需实测确认（沙箱无权限 → 可能不翻转，见 §4 止损） |
| `attrib` → `chmod` | `rules.py` | `attrib +s/-h/-a` 在 Linux **无对应属性位**（`+s` 系统文件、`+h` 隐藏、`+a` 归档）= 语义不可等价（路线图 §5.1 已评「中」）；`+r/-r` → `chmod ±w` 可近似 | 只映射 `+r/-r`（`chmod -w/+w`）；`+s/+h/+a` 保持诚实 TODO；**不追求翻转**（宿主另有 goto） |
| `at` → `systemd-run` | `rules.py` | confidence **C**；`/every:` 周期语义、`at` 时间格式 vs `OnCalendar` 不等价 → 造「看似对」 | 保持 TODO + hint（现状已如此）；**不实现转换** |
| `rasdial` → `nmcli` | `rules.py` | confidence **C**；凭据/连接名不可静态迁移 | 保持 TODO + hint；**不实现转换** |
| hint 文案纠错（`net user`） | `rules.py` 提示串 | 现 hint「请改用 systemctl/ss 等 Linux 命令」对 `net user` **语义错误**（用户管理≠服务/网络） | 纯文案，零行为风险；仅在有 `evidence` 时改 |
| registry（全部） | — | 写类 = L4 语义近似，易造「看似对」的配置写入 | **退回**，不改 |

**总体风险**：低。真正的风险不在改动本身，而在**若按任务书原口径硬凑翻转**，会违反纪律 1/7。

## 4. 止损点（逐设施）

| 设施 | 止损条件（触发即放弃该设施） |
| :--- | :--- |
| `for /r` | 改动 > 2 个模块 **或** 151 语料产物 diff > 0（除目标文件）**或** 任一 `examples/` 漂移 **或** 回归 > 0 测试 **或** wine 黄金对照下降 |

| `attrib` | 仅 `+r/-r` 可做；若 `chmod` 语义需猜测 → 退回 |
| 任一项 | 单设施改动 > 5 模块 / 超范围 / 引入「顺手改」→ 停 |

## 8. 裁定

### 8.1 逐类裁定

| 类 | 裁定 | 依据 | 行动 |

### 8.2 总体裁定：**前提已变 → 暂停**

**理由（按任务书 §十一「冷启动发现前提已变 → 停」）**：

1. 任务书的核心量化前提——**(a) 46 文件 / (b) 36 单设施翻转 / (c) 86→≤41**——**一致地不可复现**，
   且 (b) 的 11/36 与项目自身 L4/2.x 分类**直接冲突**（冷启动 §3.2–§3.4）。
2. 按真实可做子集，**无论怎样执行都无法达成 ≤41**（乐观上限 ≤7 翻转，degraded ≈79–84）。
   即：**本会话不可能达成「1.x 收尾」**，产出 v1.11.0 也不改变该结论。
3. 若照原口径硬凑，将违反纪律 1（保守 TODO 优于激进转换）与纪律 7（不发明映射）。

**因此**：不进入「按 36 翻转实现」；**提请用户裁定**下面三选一后，再决定是否实现方案 A 的收窄子集。
