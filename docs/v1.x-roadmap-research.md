### 0.2 本轮发现的真实缺陷（高价值产出）

1. **A1 是静默错且被计为「功能完好」**：`%v%` 在块体内被译成运行时活引用，
   与 cmd「块解析时冻结一次」语义相反（wine 对照 g05：wine `i=1 i=1`，bat2sh `i=2 i=2`）。
   产物**无任何 TODO/警告**（probe：`todo=0 err=0 warn=0`）→ 现有严格口径把它算作功能完好。
2. **A10 的归因结论需要更正**：`075`「标签位于控制块内」经 `_error()` 登记进 **errors 层**，
   因 `--fail-on-todo` 统计 `todo_count + error_count`（`cli.py:855`），**它会被命中**，
   并非 v1.9.1 归因所称「不会命中」。详见 A10。
3. **X5 是误诊**：`echo 2.1>nul` → `echo "2." 1>/dev/null` 与 cmd 语义一致（数字即 fd）。
   原 X5「末位数字被吞」实为**正确行为**，应从待办移除。

## 1. 逐项可行性分析

> 维度说明：**可行性** = 可直接用 / 需适配 / 不可用 / 终态 / 已满足；
> **难度** = 人日（含测试与回归）；**收益** = 影响的语料/ TODO / 静默错；
> **风险** = 是否触及核心路径 + 回归面；**依赖** = 前置项；**证据** = 文档/代码行/实跑。

### A. 已知缺陷

#### A1 `%VAR%` 立即展开冻结语义丢失 —— **最高价值项**

| 维度 | 结论 |
| :--- | :--- |
| **可行性** | **需适配（可做，且是本会话判定最高 ROI 的正确性修复）** |
