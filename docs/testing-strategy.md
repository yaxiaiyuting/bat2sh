# 测试策略与发布门槛

## 三层语料

### 1. 自建 fixture
- 位置：tests/
- 覆盖：转换器已知能力的单元/集成测试
- 数量：核心测试集

### 2. AI 语料
- 位置：~/下载/deepseek_*（不入 repo）
- 覆盖：基础语法广度探针
- 用途：诊断参考，**不作为频次证据**

### 3. 真实语料（发布门槛依据）
- 位置：tests/fixtures/real-corpus/（有许可的）
- 来源：
  - CC0-1.0: fleschutz/PowerShell（ps1）
  - 自建"拟真实"语料（bat，规避许可风险）
- 要求：≥ 50 个独立脚本
- 用途：交叉验证、静默错误检测

## 发布门槛（v1.3 起硬性）

发布前必须全部满足：

1. **pytest 全绿**
   - 必须有**运行时断言**，不能只 bash -n
   - 不得回退

2. **真实语料交叉验证**
   - ≥ 50 个独立脚本（非项目自建、非 AI 生成）
   - 语法通过率 ≥ 95%
   - **静默错误率 < 20%**
   - 崩溃类缺陷 = 0

3. **examples 全量刷新**
   - 无意外回退（已知正确行不被错误覆盖）

4. **CI 三版本全绿**
   - 3.12 / 3.13 / 3.14

## 不达标的处置

- 任一硬门槛不达标 → 不发布
- 或明确降级为 **preview 版本**，release note 显著标注
- 不允许"先发再修"——那会破坏项目第一纪律

## 教训记录

- v1.2.3 发布时 bat 侧"88% 通过率"是**假信心**：
  直到 bat-master 交叉验证才发现 70.6% 静默错误
- 根因：测试语料 = 转换器已知能力，真实输入未覆盖
- 修复：v1.3 起加真实语料交叉验证（第 2 条门槛）
