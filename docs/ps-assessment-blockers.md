## 2. 逐项说明（证据锚定）

### B1 对象模型（**最主要的缺口**）

- **实测规模**：`objects` TODO **2056/4324 = 47.6%**；含对象管道构造的文件 **462/664**。
- **为何不可等价**：PS 管道传**结构化对象**，`$_` 的属性名/类型是语言级语义；bash 只有文本。
  `Get-Process | Where-Object CPU -gt 10` 需先有「进程对象 + CPU 属性」——bash 的 `ps` 输出列
  与 PS 对象属性**不同名、不同单位、不同语义**。
- **「看起来对、实际错」**：把 `$_.CPU` 近似成 `ps` 的某列文本，会在边界（名称含空格、单位、
  排序、空对象）静默偏离。**高风险**。
- **可做的有限子集**：个别**读类** cmdlet 的**特定属性**可映射（如 `Get-Process` → `ps`），
  但需**逐条 evidence**（纪律 7「不发明映射」），且必须**显式降级**为「近似」而非「等价」。
- **判定**：**通用拒绝（D）**；仅允许「具名 cmdlet + 具名属性」的白名单近似（需真实需求驱动）。

### B2 CIM / WMI

- **实测规模**：含 `Get-CimInstance|Get-WmiObject` 文件 **18/664**（源码级；运行时影响更广）。
- **Linux 对应**：信息散在 `/sys`、`/proc`、`lscpu`、`lsblk`、`dmidecode`（需 root）等，
  **无统一的类/实例/查询模型**。
- **判定**：**拒绝（D）**。任何「把 `Get-CimInstance Win32_LogicalDisk` 映射成某条命令」都是
  「看起来对、实际错」。

### B3 `.NET` / COM

- **实测规模**：`::` 静态调用 **186/664**；`New-Object`（含 COM）**113/664**。
- **环境事实**：本机无 `dotnet`（`command -v dotnet` 无输出）。
- **判定**：**拒绝（D）**。COM（`-ComObject Shell.Application`）在 Linux 概念缺失；
  实测用例 `cd-downloads.ps1` 即因 COM 返回空而失败。

### B4 注册表

- **实测规模**：`registry` TODO 17 条；源含 `HKLM:`/`Get-ItemProperty` 文件 **9/664**。
- **Linux 对应**：`~/.config` / dconf / gsettings，**键空间与语义不同**（无 `HKLM` 概念）。
- **判定**：**通用拒绝（D）**。逐键映射需逐条 evidence，且写侧语义（生效方式）不可等价。

### B5 远程管理

- **实测规模**：含 `Invoke-Command`/`New-PSSession` 文件 **5/664**（样本小但语义重）。
- **Linux 对应**：SSH 可做「远程执行」，但 WinRM 的对象序列化/会话语义无对应。
- **判定**：**拒绝（D）**；若未来有刚需，仅可做「单次非交互远程命令」的受限近似。

### B6 PS 专有 cmdlet（分档）

| 档 | 例 | 可转换性 |
| :--- | :--- | :--- |
| 可映射 | `Get-ChildItem`→`find/ls`、`Remove-Item`→`rm`、`Test-Path`→`test`、`Join-Path`→拼接 | **部分**（已有实现） |
| 近似 | `Where-Object`/`Select-Object`/`Sort-Object`/`Measure-Object` | 对象管道 → 文本近似，**语义不等价** |
| 拒绝 | `Import-Module`/`Add-Type`/`Get-EventLog`/`Get-Service`（属性） | **D** |

## 3. 关键判断：PS 转换的上限是什么？

### 3.1 上限是「语法」还是「语义」？—— **语义**

| 事实 | 数字 | 含义 |
| :--- | :--- | :--- |
| 语法通过（664） | 550/664 = **82.8%** | 尚有 114 个**可修**的 A 类发射缺陷 |
| strict（rc0 且无 `# TODO`） | **0/664 = 0.0%** | **零**功能完好产出 |
| 含硬 D 构造文件 | **277/664 = 41.7%** | 近半文件触及 Linux 无对应构造 |
| `objects` TODO 占比 | **47.6%** | 最大缺口是对象模型 |

- **语法上限**：修完 A 类发射缺陷，语法通过率**可**从 82.8% 提升（bat 侧经验支持；
  v1.8.0 已把 60 子集从 75%→93.3%）。
- **语义上限**：**不可达**。即便语法 100%，strict 仍会因 D 档而接近 0——
  因为对象模型/.NET/CIM/注册表/远程**没有等价物**。
- **结论**：**PS 的根本障碍是语义，不是语法。** 语法是可攻的工程问题；语义是原理性边界。

### 3.2 bat 侧的教训是否在 PS 重演？—— **更极端**

| 口径 | bat 151 | PS 664 |
| :--- | ---: | ---: |
| 语法通过 | 149/151 = 98.7% | 550/664 = 82.8% |
| **strict（功能完好）** | 19/149 = 12.8% | **0/664 = 0.0%** |
| degraded | 82 | 214 |

- bat 的教训：**语法通过 ≠ 功能完好**（149 语法 vs 19 strict，82 degraded）。
- PS **完全同构且更极端**：语法 82.8% 而 strict **0**——因为 PS 的 D 档占比（41.7%）远高于 bat。
- 即：**PS 解冻即使修好全部语法，产出仍只能是「可运行但含 TODO 的高级草稿」**，
  与现状定位（v1.3 起「实验性」）**没有质变**。

### 3.3 附加障碍：**运行时 oracle 缺失**

- v1.8.0 用便携 pwsh 7.4.6 做语义对照（14/19 = 73.7%）；**本机现已无 pwsh / dotnet**。
- 后果：任何 PS 语义工作**在本机不可验证**（无法测静默错误、无法做行为对照），
  违反纪律 9/10（可复现、实测优先）。
- 要恢复验证能力，需**引入 pwsh 运行时设施**（便携 pwsh 或 `pacman -S powershell`）——
  这是一项**新设施/依赖**，且 CI 中同样缺失（CI 无 pwsh 时 PS 语义测量会 skip）。

## 4. 诚实拒绝清单（PS 的 D 档，Linux 无对应）

> 以下方向**不做**（除非出现具名真实需求 + 逐条 evidence），一律**显式 TODO**，不发明映射：

1. **对象模型属性访问**（通用）：`$obj.Prop`、对象管道 `$_` 的任意属性。
2. **`.NET` 静态/实例方法**：`[Type]::Method()`、`New-Object`、COM。
3. **CIM / WMI**：`Get-CimInstance`/`Get-WmiObject`/`Invoke-CimMethod`。
4. **注册表**：任意键的读/写（`HKLM:`/`HKCU:`/`*-ItemProperty`）。
5. **远程会话**：`Invoke-Command`/`New-PSSession`/`Enter-PSSession`（WinRM 语义）。
6. **PS 模块/类型系统**：`Import-Module`/`Add-Type`/`Import-PSSession`。
7. **Windows 专有工具**：`winget`/`TaskKill`/`tskill`/`rundll32` 等（无 Linux 对应）。
8. **平台假设**：`$IsWindows` 分支、Windows 路径/盘符（`C:\`）语义。

> 这些在实测中合计覆盖**绝大多数**失败/TODO（objects 47.6% + misc/command 等）。
> **诚实拒绝=显式 TODO**，而非激进近似（纪律 1）。

## 5. 可攻的子集（若解冻）

> 并非「全不可做」。有一类**低风险、可验证（语法层）**的工程项：

| 子集 | 内容 | 价值 | 可验证性（无 pwsh） |
| :--- | :--- | :--- | :--- |
| **A 类发射缺陷** | 修 114 个语法失败（for 头 30 / 表达式 32 / 词法 15 / try-catch 15 / param 8 / 其他 14） | 语法 82.8%→预计 95%+；消除**整文件降级** | ✅ `bash -n` + bwrap |
| **报告少计缺陷** | try/catch `# TODO` 未计入 `todo_count` → `--fail-on-todo` 静默失效（reality §4） | 恢复 CI 门真实性 | ✅ 确定性断言 |
| **对象读类白名单**（需需求） | 具名 cmdlet + 具名属性 → Unix 命令（逐条 evidence） | 有限可用性提升 | ⚠️ 需 pwsh 才能证等价 |
| **运行时可验证性** | 引入便携 pwsh 作为 oracle | 恢复语义测量 | 需新设施 |

> 这些子集**不改变语义上限**：strict 仍≈0。它们提升的是**「语法干净 + 报告诚实」**，
> 而非「功能完好」。

## 6. 障碍评估小结

1. **根本障碍 = 语义**（对象模型/.NET/CIM/注册表/远程），**bash 无等价物**，**未缓解**。
2. **PS 上限 = 「可运行 + 诚实 TODO」的高级草稿**；**语义等价不可达**（41.7% 文件含硬 D 构造）。
3. **语法可攻**（114 个 A 类缺陷）但**不改变 strict=0** 的语义现实。
4. **运行时 oracle（pwsh）缺失** → 语义工作**不可验证**，违反可复现纪律。
5. **诚实拒绝清单**（§4）应作为 PS 路径的**显式 D 档**，不发明映射。
