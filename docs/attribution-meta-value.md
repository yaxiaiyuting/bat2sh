### 2.3 为什么「可泛化」= 0（而不是「没测」）

判据三步，全部实测：

| 步 | 测量 | 结果 |
| :--- | :--- | :--- |
| ① **结构上界** | 「全部 TODO 同一 signature」且「该 signature 跨 ≥2 文件」的 degraded 文件 | **43 个**（结构上看似可泛化） |
| ② **规则分解** | 把 signature 按 `reason` 拆开（一条规则 = 一个 (signature, reason)） | 命中 ① 的 43 个文件，其 signature 内部的 reason 数：`for` **6 种**、`set` 4 种、`start` 4 种、`echo` 4 种、`reg` 2 种、`if` 2 种 → **不是一条规则** |
| ③ **忠实性过滤（纪律 7）** | 对 ② 剩下的多文件规则逐条核对是否已有安全映射 | **0 条**：`reg`/`regedit` = Linux 无注册表；`regsvr32` = 无 COM；`goto` = 终态；`if` = 词法未转义 `>/<`；`for` 残余 = 变量选项 / `%%1` 非法；`csty`/`cido`/`finfo`/`keyprs`/`beenotice` = 语料自带 exe；`devcon`/`wmic`/`mshta`/`rundll32` = Windows 对象模型 |

> **①→③ 的落差本身就是结论**：signature 级看起来「泛化」（`reg` 跨 15 文件、`for` 跨 14 文件），
> **一按规则拆解就退化成一条规则一个文件**。一个只做 signature 级聚类的归因矩阵
> **会系统性高估泛化度**。

## 5. 结论

1. **「可泛化性」不是新维度**——`v1.11.0-reclassification.md` §0 的「涉及文件 / 单设施文件」两列
   与 `v2.2.0`/`v2.3.0-reality-check.md` 的「可翻转文件数」列，就是它的等价测量。
2. **「Generalization Ratio」不是新信息**——本 session 只读算出：现存 **0.96 文件/规则**，
   历史 **0.60（strict）/ 1.00（处置）文件/规则**。该标量**只会证实**项目已知的「规则爆炸」结构。
3. **可泛化项实测 = 0**（< 判据阈值 3）→ 按任务书 §3.2 判据，**矩阵价值低**。
4. **预期翻转实测 = 0**——结构、目标物、指标三条独立实测一致。
5. 唯一「新」的东西是**一个标量名**，而它指向的结论项目已经在 `v2.2.0` 用「不数 TODO，
   数可翻转文件」处理过了。
