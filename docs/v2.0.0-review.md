## 3. 最小复现（全部本 session 实测，可复现）

> 复现命令（只读，输出在 `/tmp/opencode/`）：
> ```bash
> python3 -c "import sys;sys.path.insert(0,'python');from bat2sh.core.engine import convert_file;from bat2sh.core.settings import ConvertSettings;print(convert_file('FILE',ConvertSettings(bash_check=False),write=False).text)"
> ```

### P1 — `今天访问过的程序文件所在目录.cmd`
源（gbk）：
```bat
for /f "delims=" %%i in ('dir /s/b/a/ad') do (
    dir /ta/a "%%i"\*.exe 2>nul|findstr /r "^%today%" && (
        echo ^<a href="%%i" target="_blank"^>%%i^</a^> >>list.htm
        echo ^</br^> >>list.htm))
start list.htm
```
生成（错）：第 37 行 `    echo "</br>" >>list.htm))` → `bash -n`: 未预期的记号 `)`。
根因：`_pipeline_todo` 把第 25 行降级为 3 行注释，**丢掉 `&& (` 的开括号登记**；第 27 行 `))` 多出一个 `)`。

### P2 — `文件归类整理器.bat`
源（gbk，行 102）：`if exist "%source_path:"=%" (`
生成（错）：
```bash
61:     if [ -e "%source_path:" ]; then
62:         =%" (                 <- bash -n: 未匹配的 "（EOF）
```
根因：`_parse_condition:1836` 的 `(".*?"|\S+)` **非贪婪**，`"%source_path:"` 即止，剩 `=%" (` 泄漏为语句体。
（注：源行 172 `move /-y %2"%nx_name%"` 的 `\"` 产物实测**引号平衡**，非语法失败根因。）

### P3a — `史上最牛X…bat`
最小复现：
```bat
@echo off
echo  # Checking DHCP ...
ipconfig | find /i "Lease" > nul
if errorlevel 1 (
  rem trying other method for DHCP
  ipconfig | find /i "DHCP-Server" > nul
  if errorlevel 1 (
    echo no dhcp
  )
)
```
生成（错）：`    if ! if ! echo "# Checking DHCP ..."; then; then` → `bash -n`: 未预期的记号 `;`。
根因：`_take_previous_command`（`:1926`）只拒绝 `{`/`(`/`|`/`&`/`&&`/`||`/`;` 结尾行，**未拒绝 `; then`**，
于是把先前发射的 `if ! echo …; then` 当作「上一条命令」，`_errorlevel_condition:2007` 拼出 `! {previous}`。
（注：简单连续 `if A if B cmd` 实测正确，rc=0。）

### P3b — LF-1（退回项，仅供参考）
最小复现：`for %%j in (a) do (for %%s in (b) do echo %%j %%s)` →
`for j in a) do (for %s in (b; do`（贪婪 `\((.*)\)` 吃到内层 `)`）。

### 9.2 P1 的止损过程（关键披露）

P1 的第一版实现（**V1/V2**：改 `_manual_block_line` 净深度 + 注释块整体计数 + 尾部重派发 + 中央 TODO 注册）
**触发止损**——两个既有文件产物非预期变化：

| 文件 | 基线 | V1/V2 后 | 判定 |
| :--- | :--- | :--- | :--- |
| `批量重命名  （按指定拓展名）.bat` | degraded（rc=0, todo=2） | **rc=2** | ❌ 回归 |
| `文件备份器/文件备份器V2.3修改版2.cmd` | rc=1（todo=76） | rc=1（todo=**116**, +40） | ❌ 非预期 |

**根因（实测）**：既有 `comment` 块机制是**载荷性**的——`批量重命名` 依赖「注释块永不闭合」（其 `set /a n+=1)` 行以 `)` 结尾，会提前闭合注释块，暴露本应注释掉的行）；`文件备份器` 依赖「行首 `)` / 行尾 `(`」的近似计数。故**任何**改动通用 `comment` 块的方案都会回归。

**收窄（V4）**：为管道降级新增**独立块类型 `pcomment`**（仅 `_pipeline_todo` 使用），
采用引号感知计数 + 配平后重派发尾部；**既有 `comment` 块逻辑零改动**。
结果：**仅 2 个目标文件变化，零回归**（见 §9.3）。

### 9.4 degraded +2 是定义性位移，非回归（重要）

`measure.py` 的 `degraded` 口径 = **rc==0 且含 TODO**；**语法失败文件不计入 degraded**。
2 个文件由「语法失败（产物不可用，整体降级为注释）」变为「rc==0 + 诚实 TODO」 →
**从 unusable 桶移入 degraded 桶**。即：**没有任何文件变差**，degraded 增加是修好语法失败的**必然结果**。

> **规格冲突披露**：任务书「语法失败 4→1」与「degraded 不倒退（≤83）」在**该口径下数学上互斥**——
> 每修好一个含 TODO 的语法失败文件，degraded 必 +1。若要两者同时成立，须改 degraded 口径
> （把 syntax-fail 计为更差类别），或把目标改为「unusable 桶 4→1」。本版如实记录，未强凑。
