## 一、关键拓扑事实（与任务书假设的偏离，主动披露）

**三分支不是「各自从 main 并行分叉」，而是「累积/堆叠（stacked）」关系**：

```
main (7048e6c)
  └─ session-b1b2 (7e645db)              # 8 commits
       └─ session-c4 (68dfbdd)           # +5 commits
            └─ session-lex (37e3564)     # +5 commits
```

证据（只读）：

- `git merge-base main session-{b1b2,c4,lex}` **全部** = `7048e6c`（三者都能追到 main）；
- `git merge-base session-b1b2 session-c4` = `7e645db`（= b1b2 HEAD）；
- `git merge-base session-b1b2 session-lex` = `7e645db`；
- `git merge-base session-c4 session-lex` = `68dfbdd`（= c4 HEAD）。
- `git rev-list --left-right --count main...session-lex` = `0  18`，`18 = 8 + 5 + 5`。

> 三份会话报告亦各自明记「累积模式」：`session-c4-report.md` §八、`session-lex-report.md` §七。

**影响**：每一支都是前一支的后代 → `git merge --no-ff <后代分支>` **在构造上不可能产生文本冲突**。
任务书「三分支都改过的文件 → 理论冲突 0，但必须核实」的结论**成立且更强**：不仅理论 0，机械上也是 0。

## 五、合并策略

- **策略**：`git merge --no-ff`（保留分支历史，禁止 linear fast-forward 掩盖三分支结构）。
- **顺序**：`session-b1b2` → `session-c4` → `session-lex`（祖先到后代，最小化无谓的三方合并）。
- **冲突处理**：出现任何冲突 → **立即暂停**，不自行解决，向用户报告（任务书 §七）。
- **每支后必跑**：`pytest -q`（全量）。冲突/失败 → 停。
- **HEAD 锁定**：合并前记录 `main` = `7048e6c`；每次写操作前校验，异常即停。

## 六、发布流程（合并通过后）

```
1. scripts/release-preflight.sh（必过）
2. bump commit：pyproject.toml + __init__.py → 1.10.0
3. tag v1.10.0 打在 bump commit（annotated）
4. push main + tag
5. 确认 tag 上 CI 3.12/3.13/3.14 全绿
6. tarball sha256（refs/tags/v1.10.0.tar.gz）→ 同步 PKGBUILD
7. makepkg --printsrcinfo > .SRCINFO
8. 独立 commit + push
9. GitHub Release（正式版，勾 latest）
10. 本机安装验证（install.sh + makepkg 产物）
```

### 6.1 AUR 事实核对（重要偏离披露）

只读核查结果：

- AUR RPC v5：`/rpc/v5/info?arg[]=bat2sh` 与 `/rpc/v5/search/bat2sh` 均 **resultcount=0** → AUR 上**不存在** `bat2sh` 包；
- 本仓库无 AUR remote（仅 `origin github.com`）；
- `~/.ssh/` **无任何私钥**，`ssh aur@aur.archlinux.org` → `Permission denied (publickey)`。

→ 因此「**AUR 同步**」在本环境**只能完成仓库侧同步**（`PKGBUILD`/`.SRCINFO` 对齐 1.10.0 + sha256），
**无法执行真正的 AUR push**（无包、无 SSH 凭据）。历史「sync PKGBUILD」commit 亦仅改仓库内文件。
本项将如实记录为「仓库侧已同步 / AUR push 未执行（缺凭据）」，不阻塞发布。
