## 1. 原标准与问题

路线图 `docs/v1.x-roadmap-research.md` §4 标准 3：

> **标准 3**：`degraded ≤ 理论下界 41`（= 86 − 45；45 = §3.4 的 46 个可做文件去掉 A10 的 075）；
> 剩余**全部**属 `goto`/终态类别，**无「本可做而未做」**。

**问题（v1.11.0 实测证伪）**：≤41 的前提是「1.x 可解文件 = 46」，而该 46 不可复现：

| 依据 | 结果 |
| :--- | :--- |
| `v1.9.1-attribution.md` §2.1「最高层 L1/L2 = 14+32 = 46」 | 用同文件**表 A** 逐文件重算 = **25**；且重算「L1 层文件数 = 0」与 §2.1「L1=14」矛盾 → **§2.1 内部不一致** |
| 路线图 §3.4 设施桶口径「1.x 可解 46」 | `other` 桶**无定义**，且自注「含 C/D 级条目」；本会话显式定义后重算「所有 TODO 属可做设施」= **19**（或含 registry 写类 = 29），**均非 46** |
| C2 单设施翻转「36」 | 实测 = **35**（for 7 + registry 11 + other 17）**≈ 36**，但构成：**registry 11 = 注册表写类（L4/2.x）**、other 17 中可做仅 1、for 7 中可做 2 → **真可做 = 3** |

→ **≤41 建立在错误的 C2 估算（46 文件）之上，必须修订。**

## 2. 修订后的标准 3

### 2.1 实际可达值（**仪器实测，非估算**）

| 阶段 | strict（功能完好） | degraded |
| :--- | ---: | ---: |
| v1.10.0 基线 | 16 | **86** |
| Commit 1 `for /r` → find | 17 | 85 |
| Commit 2 `for /f` 字符串形式 | 18 | 84 |
| Commit 3 `net user /delete` → userdel | 19 | 83 |
| Commit 4 `attrib ±r` → chmod | 19 | **83** |
| Commit 5 hint 纠错（纯报告文案） | 19 | 83 |

**可做翻转 = 3**（`以文件夹名为名建立文本文件.cmd`、`注册表/reg转bat.bat`、`删除用户.bat`）。
`attrib ±r`（Commit 4）为**质量项、零翻转**（宿主 `修改GB搜索引擎.bat` 另有 `goto`）。

**实际可达下界 = 86 − 3 = 83**（已在 §2.1 实测）。剩余 83 个 degraded 的归属见
`docs/v1.11.0-reclassification.md`（逐条：`goto`/`regsvr32`/`sc`/第三方 exe/L4 对象/注册表写/
复杂 `if`/区域设置/重定向未赋值变量/源畸形）。

### 2.2 新标准

> **标准 3（v1.11.0 修订）**：`degraded ≤ 83`（= 86 − 3 个 1.x 可做翻转），
> 且**剩余 83 个全部有明确归属**（2.x 或终态，逐条见归属重判文档），**无「本可做而未做」**。

| | 原标准 | 修订后 |
| :--- | :--- | :--- |
| 阈值 | `degraded ≤ 41` | **`degraded ≤ 83`** |
| 构成假设 | 46 个 1.x 可解文件 | 25（重算）/ 真可做 3 翻转 |
| 依据 | 路线图 §3.4（不可复现） | 本会话仪器实测 + 逐条归属重判 |

### 2.3 与标准 1 的关系（关联披露）

路线图 §4 **标准 1**（语法通过 ≥150/151，剩余 1 为 B 类源畸形）**当前仍不成立：147/151（4 失败）**。
v1.11.0 首次给出 4 例的**逐条机制归因**（见 `docs/v1.11.0-1x-closure-final.md` §2）：

| 文件 | 机制 | 归属 |
| :--- | :--- | :--- |
| `运行剪贴板中的bat.bat` | 源文件含原始二进制/混淆字节（`3ÒÃèüÿÿ…`） | **B 类源畸形（终态，cmd 亦失败）** |
| `今天访问过的程序文件所在目录.cmd` | 降级为 TODO 的 `\| … && (` 行丢失开括号配平 → 尾部 `))` 失配 | **2.x（解析层/块平衡；B5/LF-1 同域）** |
| `史上最牛X…bat` | 嵌套 `if` 发射出 `if ! if ! echo "…"; then; then`（畸形） | **2.x（if/块栈解析层）** |
| `文件归类整理器.bat` | 双引号内 `\"` 转义致 `mv "…\"…\"…"` 引号失配 | **2.x（引号/词法层；A9/LF-2 同域）** |

> **本项不属标准 3 修订范围**（任务书仅授权修订标准 3）；如实披露，留待裁定（见收尾评估 §4）。

## 3. 纪律 9 强化条款（本版新增）

> **纪律 9（强化，v1.11.0 起）**：测量工具必须**可复现**；**不可复现的数字视为无效**。

落实：

| 措施 | 证据 |
| :--- | :--- |
| 测量仪器**固化进仓库**（原 `/tmp` 版随会话消失） | `tools/corpus-analysis/measure.py`（CLI：`--corpus/--out/--json`） |
| 口径与既有 `analyze.py` 一致（bwrap/fixture/stdin） | 代码复用 `fixture_names`/`stdin_mode`/`sandbox_cmd` 口径 |
| **确定性**：两次独立全量运行逐字段一致 | `docs/v1.11.0-instrument-verify.md` §2（R1/R2 逐文件 0 差异；R3 仓库版与 `/tmp` 版 0 差异） |
| 与历史基线逐项吻合 | 151/147/102/16/86/894/崩溃 0 |
| 输出可审计 | `measure.json`（summary + 逐文件 `rc`/`todo_count`/`markers`/`todos`） |

**本版所有数字均出自该仪器**；引用格式统一为「语料 / 语法 / rc==0 / strict / degraded / TODO / 崩溃」。
