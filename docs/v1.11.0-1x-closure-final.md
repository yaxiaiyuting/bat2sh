## 6. 2.x 启动条件（可证伪触发器，需求驱动）

> 本版起采用**需求驱动**启动（**取代**路线图原「每版必做」的版本序列）。
> **无触发则不启动**（避免为理论收益投入）。

| 触发 | 说明 |
| :--- | :--- |
| **T1 出现真实需求（非理论）** | 有明确真实语料 / 用户目标要求某 2.x 主题（例：实际迁移中遇到大量 goto 脚本、需要 PS 侧支持） |
| **T2 1.x 维护期发现回归** | 1.x 维护期内发现由 2.x 主题导致的回归或高危缺陷 |
| **T3 外部触发** | 生态变化（工具/接口变更）或 PS 侧出现刚需（明确 PS 目标/语料） |

**任一触发 → 启动对应主题的只读评估**，沿用「只读诊断先行 + 可证伪闸门 + 逐条 evidence + 回滚即停」纪律。
