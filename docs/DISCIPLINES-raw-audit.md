# bat2sh 项目纪律（1–22）—— 核实记录

> ⚠️ **本文件是「核实记录」，不是权威注册表。**
>
> 核实结论：**仓库中不存在统一的纪律编号注册表**。纪律编号在不同时期被**重新编排过至少三次**，
> 且各会话任务书自带一套编号。因此「纪律 N」在不同文档里可能指向**不同概念**。
>
> 每条**保留用户提供的原始措辞**（未擅改，纪律 2），并附文档核实结果。
> **8 条编号存在冲突、4 条仅概念可考、10 条完全一致** —— 详见 §0 与附录 A/B。
>
> 核实方法：`grep -rnE "纪律[ ]*N([^0-9]|$)" docs/ --include="*.md"` 穷尽扫描
> （已排除 gitignore 的本地副本 `src/bat2sh-2.6.0/`）。

## 0. 核实结论摘要

| 判定 | 条数 | 编号 |
| :--- | ---: | :--- |
| ✅ **一致** —— 用户措辞与该编号在文档中的用法相符 | **10** | 1, 4, 7, 9, 10, 12, 14, 16, 17, 18 |
| ⚠️ **仅概念可考** —— 概念在文档中有，但该编号**从未被标注过** | **4** | 11, 13, 15, 21 |
| ❌ **编号冲突** —— 文档中「纪律 N」指向**另一个**概念 | **8** | 2, 3, 5, 6, 8, 19, 20, 22 |

**另有两项结构性发现**：

1. **没有统一注册表。** 单个文档最多只提到 8 个编号，且互不一致；
   不存在任何一份「纪律 1–N 一览」。
2. **至少三套编号体系并存**（见 §0.1）。

### 0.1 三套并存的编号体系（核实证据）

**体系 A** —— `docs/v1.x-roadmap-research.md:918` 「## 7. 纪律对照」（v1.11.0 时期，**7 条**）：

| 该文档编号 | 含义 |
| :--- | :--- |
| 1 | 保守 TODO |
| 2 | 只读诊断先行 |
| 3 | 主动披露偏离 |
| 4 | 不发明映射 |
| 5 | 仪器先验证 |
| 6 | 硬闸门 |
| 7 | 锁定 HEAD（r2 新增） |

**体系 B** —— 各版本报告内联使用（v1.8.0–v2.7.0，编号 1–22，**含义随 session 漂移**）。
例：`纪律 13` 在 `v2.1.0/v2.2.0/v2.3.0` 指「**不硬凑**」，而在
`docs/session-lex-design.md:114` 指「**语义正确性与 rc==0 并列**」。

**体系 C** —— 各会话**任务书自带**的一套编号（每个 session 重新从 1 开始）。
例：Android 会话任务书是 1–7（1 core 零改动 / 2 主动披露 / 3 不合并 main / 4 仪器先验证 /
5 锁定 HEAD / 6 API key 谨慎 / 7 并行错误隔离）；可发现性会话任务书是 1–6。
**`docs/android-api-report.md` 与 `docs/discoverability-report.md` 中的「纪律 N」用的是体系 C。**

> **用户清单与体系 A/B/C 均不完全吻合** —— 它更像是对三者的一次人工归并。
> 本记录如实并列，**不代为裁定**。
