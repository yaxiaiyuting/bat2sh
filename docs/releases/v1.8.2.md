### 仪器修正说明（纪律 9：仪器先验证再报数字）

**v1.8.1 报告的「静默错误 61/145 = 42.1%」是仪器缺陷**：原「仪器 1」扫描的是**源文件**
（`X1 @echo off&setlocal`、`X5 \d>nul`、`X9 一行两个 %var%`），大量命中**正常且已正确转换**
的源码。改为扫描**转换产物**的非注释行后，命中由 61 降为 6，其中**真实转错 3 个 = 2.1%**
（详见 `docs/v1.8.1-attribution.md`）。

本版沿用修正口径，并在重跑前**先做仪器验证**：用 v1.8.1 已列出的 6 个已知 artifact 盲测，
本仪器 **6/6 复现**，且语法 145/151、崩溃 0 与 v1.8.1 完全一致 → 数据可信。
（背景同源事故：v1.2.3「88% 假信心」与 v1.8.1「42.1% 假静默」。）

### Errata（v1.8.3 更正：`rc==0` 口径）

> **本版初版报告的「运行 rc==0 = 105（+18）」是错误口径。**

- **错误性质**：**口径定义不清**（分母错误），非脚本/仪器错误。
  `105 = 151 − 46` 把 **6 条语法失败（无产物、根本不参与运行）** 也算进了分母。
- **正确口径**：**145 条语法通过者中 rc==0 = 99**（99 + 46 = 145）。
- **连带更正**：
  - 相对 v1.8.1（rc==0 **87**）的真实变化是 **+12**，不是 +18；
  - rc≠0 为 **58 → 46**（v1.8.1 的 rc≠0 = 145 − 87 = 58），不是「~64 → 46」；
  - 语法通过率 **145/151 = 96.0%** 不变（该口径本就以 151 为分母，正确）。
- **来源**：v1.8.3 阶段一「仪器先验证」（纪律 9）复现基线时抓出。
  详见 `docs/v1.8.3-attribution.md` §0.2。

### 已知限制

1. **A-7 三条 backlog（本版未修，均有证据）**：空重定向（`备份服务.bat:12`）、
   引号/命令替换（`批处理生成的CMD命令帮助清单.bat:24`）、内容生成多行
   （`多功能系统优化设置.cmd:151`）。均触及重定向发射/命令替换深水区，回归风险高。
2. **6 例语法失败仍在**（多结构深度嵌套），默认整体降级为注释，绝不产出坏 bash。
3. **`//` 与 `\/` 外观残留**：`%systemdrive%`→`/` 后再接 `\`（`换马甲.bat`）与
   UNC 式 `\\`（wmic 行）呈现双斜杠，属 Windows 专有命令，不影响 rc。
4. **结构化表 27 条**；既有 `rules.py` 映射仍未迁移（backlog）。
5. **`partial`/`C` 类映射只给建议、不自动采用**（保守 TODO 优于激进转换）。
6. 危险脚本在沙箱内运行；沙箱边界见 `docs/sandbox-audit.md`。

### CI 流程修正说明（v1.8.1 教训的落实）

- **背景**：v1.8.1 的「tag 打在 bump commit 上」时 CI **为红**（`test_real_corpus_block_forms`
  依赖仓库外语料，CI 无该目录），tag 推完才发现；该 tag 自身 CI 记录为红。
- **本版落实**：
  1. tag 前必跑 `./scripts/release-preflight.sh`（空 `HOME` 类 CI 环境 + 工作区干净门禁）；
  2. **tag 推送后先确认 CI 3.12/3.13/3.14 全绿**，再同步 PKGBUILD / 发布 Release；
  3. 不 force-push 已发布 tag。
- 本版 preflight 结果：**1177 passed, 2 skipped**（外部语料用例在缺失时 skip，`f35c3c1` 已修）。
