## bat2sh v1.7.0

### New features

- **TODO 多选并行修复（C 阶段）** —— `--fix-todos` 从"逐条串行"改造为"多选并行 + 聚合确认"。
  动机：开启 `enable_thinking` 后单条 TODO 修复实测约 214 秒，多条串行不可接受。
  - **并发数默认 3**，配置优先级 **CLI > 环境变量 > 文件**：
    `--max-concurrency N` / `--parallel N` > `BAT2SH_MAX_CONCURRENCY` > `api.json` 的
    `max_concurrency`（范围 `1-16`；非法/0/负数回退默认 3）。
  - **多选**：列出全部可修复 TODO，可用 `1,3-5` 形式选择子集（回车=全部，`q`=取消；
    单条时自动选中不提示）。
  - **隐私提示合并为一次**：`发送 N 条到 {endpoint}？[y/N]`，并列出将发送的条目清单；
    不逐条询问，`--yes`/`--force` 依旧**不可**绕过（延续 v1.5 决策）。
  - **聚合面板**：CLI（TTY 原地刷新 / 非 TTY 追加）与 GUI 均为「每条 TODO 一行」实时刷新
    `pending / running / done / failed / skipped`；并发下每条流式正文按 `#序号` 标注归属。
  - **429 自适应**：指数退避（1s→2s→4s…上限 30s）+ **主动降并发**（下限 1、上限为初始并发数），
    并提示当前并发；`Provider.complete_stream` 新增 `on_rate_limit` 回调使限流可观测。
  - **错误隔离**：一条失败不阻塞其它；失败条目单独列出，可在合并前**重试**（最多 3 轮）。
  - **从后往前应用**：全部收完后按 `out_line` 降序合并，避免多行替换造成的行号偏移；
    每步再过一次整脚本 `bash -n` 闸门，保证叠加后产物依然语法合法（never emit broken bash）。
  - 全部收完后展示**聚合 diff**，确认一次后一次性写盘（`--print` 只输出；绝不自动写盘）。
  - GUI「API 修复 TODO」同步改造：可勾选条目、聚合状态面板、聚合 diff、重试失败项；
    设置页新增「修复并发数」（默认 3，范围 1-16）。

- **`# TODO[REG]` 语义明确** —— 注册表写类标记是**结构化 TODO，不自动修复**，仅作为
  `--fix-todos` / API 的处理输入；该说明已写入 `--fix-todos` 帮助文本、README §4.5 与 §8.5。

### Fixes

- GUI 设置页保存时不再把 `max_concurrency` 静默重置为默认值 3（设置页现可读写该项）。
- 并发下 `enable_thinking` 参数不被端点支持时的自动降级告警**只发一次**（此前每个并发请求都会告警）。

### 兼容性与已知限制

- `--fix-todos` 的交互语义变化（破坏性）：由「逐条发送确认 + 逐条 diff 确认」变为
  「一次隐私确认 + 一次聚合 diff 确认」；非交互终端仍直接拒绝（退出码 1）。
- **停止/中断的延迟**：阻塞中的 socket 读无法被其它线程打断，因此点击 GUI「停止」或 CLI
  `Ctrl+C` 后，在途请求最坏要等到当前**空闲超时**（默认 30s）才完全结束；期间不写盘。
- 并发下非 TTY 日志的流式正文按 `#序号` 标注，多条会交错出现（TTY 下用聚合面板 + 尾部预览，不交错）。
- **未改动转换管线**：`core/batch.py`、`core/powershell.py`、`core/rules.py`、
  `core/registry_map.py`、`core/engine.py`、`core/syntax.py` 在本版本**零改动**，
  因此 examples 与真实语料的转换结果与 v1.6.0 完全一致。
