## bat2sh v1.5.0

### New features

- **API 修复支持流式（SSE），解决长思考模型的读超时**
  - 根因：Qwen3 等混合思考模型在非流式响应下，思考期零字节输出 → 30s 读超时必然触发
    （实测复现 62s = 30s 首超 + 1s 退避 + 30s 重试超时）。改为统一 `stream: true` 逐行消费 SSE 后，
    socket 超时语义变为「两次数据之间的空闲超时」（默认 30s），生成总时长不再受限
    （实测 chunk 最大间隔 0.653s，余量约 46×）。
  - Provider 新增 `complete_stream(prompt) -> Iterator[str]`；`complete()` 保留为其拼接封装，
    对外行为不变；**已产出内容后不重试**；端点忽略 `stream` 返回纯 JSON 时同响应回退解析（零额外请求）。
  - CLI `--fix-todos`：模型正文**实时流式**显示（stderr；stdout 始终保留给 `--print`）；
    思维链仅以「思维链 N 段」状态行提示、不显示内容；Ctrl+C 取消不写盘、不应用部分输出。
  - GUI：TODO 修复对话框新增只读「模型输出（流式）」面板与「停止接收」按钮
    （思考阶段点击亦立即生效；关闭窗口自动取消本次接收）。
  - 保守边界：净截断 → 「流式响应意外中断」，**绝不返回可能截断的建议**；坏 JSON / 仅思维链 → 明确错误。

- **`enable_thinking` 思维链开关（默认关）**
  - CLI `--enable-thinking` / `--no-thinking`、环境变量 `BAT2SH_ENABLE_THINKING`（`0/1/true/false/yes/no/on/off`）、
    `api.json` 字段 `enable_thinking`；优先级 **CLI > 环境变量 > 文件 > 默认（关）**。
  - 默认关：首次体验优先（实测同一提示词：关 3.6s vs 开 62.3s，约 **17×**）。
  - 兼容：端点不支持该参数（HTTP 400/422）时**自动降级**（去掉参数立即重试）并警告一次，
    之后本会话不再携带；其它 4xx 不降级。
  - GUI 设置页新增「启用思维链（更准但更慢）」复选框，与配置文件同步。

- **超时错误提示改进**：超时错误附带当前 `timeout` / `context_lines` 配置值、调大建议与备选方案
  （减小发送上下文），并保留底层原因；非超时错误不受影响。

### 研究结论摘要

- **B1 动态追踪：值得做（作为静态转换的补充，而非替代）**。便携 pwsh 7.4.6 + bwrap 沙箱跑通
  （10 个 CC0 脚本：RAN 7 / FAILED-ENV 3 / 补充探针 MISSING-CMDLET 1）；追踪给出静态不可见的信息：
  运行时分支选择、原生命令（`sudo ufw` / `dmidecode`）、别名/版本差异（pwsh7 `sort` → `/usr/bin/sort`；
  `Get-Content -Encoding Byte` 已移除）、动态脚本调用、死代码确认（`check-gpu` Linux 下执行 0 条命令）。
  但 Linux 沙箱下 Windows/WMI/注册表面不可执行 —— **无法替代静态 TODO 生成**。
  翻译率（15 个追踪命令）：mapped 73.3% / unknown 20%（`Write-Progress`、`ConvertFrom-Csv`、`sudo` 无规则）。
  MVP ≈ 1.5–3 人周。
- **B2 注册表：读可做、写一律拒绝**。实测 474 次构造，**读:写 ≈ 1:11**；可做清单 P0–P5
  （重启检测 8 / 服务 6 / 系统版本 3 / 硬件 2 / 安装检测 1 / 文件关联读；读类合计仅 38 次）；
  拒绝 431 次写类（Linux 无统一可写注册表，同键写入目标互不相同）。
  另发现两处**前置缺陷**：cmd `reg` 的 TODO handler 返回 `None` 导致**整行静默丢弃**；
  PS 注册表路径被**静默误译**为文件系统操作（`ls -la "HKLM:/…"`、`rm -r "HKLM:/…"`）。
- **B3 PS 块结构：4 缺陷全部静默损坏**（105 `[ordered]@{}` / 109 try-catch / 111 begin-process-end /
  114 switch+`[version]`；`error_count` 全为 0 且 `bash -n` 全部通过 —— **`bash -n` 是语法网，不是语义网**）。
  建议先做**统一块栈加固**（构造头注册表 + 未知 `{`/`@{` 安全注释容器兜底），
  再 109 多臂 → 114 cast → 105 哈希表语义。语料证据：CC0 语料 57/60（95%）使用 try/catch，
  且测试套件只覆盖同行 `} catch {` 形态（用户语料中出现 0 次）。

### v1.6 方向

- **PS 块结构统一加固（最高优先级）**：一次修复 111 + 105 泄漏 + 114 switch 泄漏，并对新构造防回归；
  随后 109 多臂语义、114 `[version]` cast、105 哈希表/`.Keys` 语义。
- B2 前置缺陷修复（`reg` 静默丢行、注册表路径误译）与读类映射 P0–P2。
- B1 动态追踪：先全量语料评估 ROI，再决定是否作为可选验证环节。
