## 二、tag 自洽性（一次**主动纠正**）

**问题**：首版 tag 打在 `5287f6b`（bump 提交），而 `docs/releases/v2.11.1.md` 是**之后**才写的。
按 v2.11.0 的先例，**发布说明应当位于 tag 之内**（v2.11.0 的说明即随 bump 提交入库）。

**处置**：补一个发布说明提交 `695a79c`，**把 tag 移到该提交**（`git tag -d` + 重新 `-a`，
远端 `--force` 推送）。该 tag 当时**尚未被任何下游消费**（CI 刚起、无 Release、无外部引用）⇒ 移动安全。

**验证（tag 内自洽）**：

```
$ git rev-parse v2.11.1^{commit}   → 695a79c
$ git show v2.11.1:python/bat2sh/__init__.py | grep __version__  → "2.11.1"
$ git show v2.11.1:PKGBUILD | grep ^pkgver                       → 2.11.1
$ git ls-tree -r v2.11.1 --name-only | grep docs/releases/v2.11.1.md → 命中
```

> 移动 tag 使 tarball 内容变化 ⇒ sha256 也随之变化（`c8955ad3…` → `9ffdafb6…`），
> 已由第 5 步重新同步 ⇒ **PKGBUILD 哈希与 tag tarball 一致**（D-1 门要求）。

| `echo [%~n0]`（脚本名**无扩展名**） | 同上形态 | `[norext]` | `[my]` | ✅ |
