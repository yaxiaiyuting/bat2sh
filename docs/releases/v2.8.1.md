# bat2sh v2.8.1 发布说明 —— PS 报告诚实性修复

> **性质**：`2.8.1` **patch**。修复 **PS（PowerShell）路径的报告诚实性缺陷**：
> `try/catch` 等自定义 `# TODO` 标记未计入 `ConvertReport.todo_count`，导致
> `--print --fail-on-todo` 对含 TODO 的 PS 产物**静默退出 0**（应 3）。
> **不改变 PS 定位**（仍为实验性支持）；**不引入新依赖**；**AUR 不进**。

---

## 1. 修复说明

### 现象（修复前）

PS 转换器在 `try/catch`、`finally`、复杂哈希表、`elseif` 解析失败、未闭合 here-string 等场景，
会在产物中发射自定义 `# TODO` 标记，但**只登记为 warning**，不计入 `todo_count`。后果：

1. **CI 门静默失效**：`bat2sh --cli x.ps1 --print --fail-on-todo` 对含 `# TODO` 的产物**退出 0**。
2. **报告少计**：GUI「转换报告」在 `error_count==0 && todo_count==0` 时显示
   「所有语句均已自动转换」——**误导**。

**复现（逐字）**：

```
$ bat2sh --cli cd-up.ps1 --print --fail-on-todo ; echo $?      # 修复前
0
$ bat2sh --cli cd-up.ps1 --print | grep -E '# TODO' | grep -v '带有 # TODO 标记'   # → 2 个标记
```

### 修复

- 新增 `PowerShellConverter._register_todo()`（`_todo()` 复用其登记逻辑）。
- 在 **7 处**自定义标记点登记 todo：
  `try/catch` 简化、catch-without-try、`finally`、哈希表（复杂 / 未闭合）、
  `elseif` 无法解析、here-string 未闭合。
- 效果：`todo_count >= 1`，`--fail-on-todo` **正确返回 3**。

### 规模（全量 664 CC0 语料，实测）

| 指标（排除脚本头，`measure.py` 口径） | 修复前 | 修复后 |
| :--- | ---: | ---: |
| **markers>0 且 `todo_count==0`（defect）** | **8 / 664** | **0 / 664** |
| markers > `todo_count` | 262 / 550 | 10 / 550（多标记同属一个 todo，非缺陷） |
| 60 子集 defect | 6 | 0 |

> 缺陷文件（修复前）：`cd-repo.ps1`、`cd-up*.ps1`(4)、`check-file.ps1`、`list-ssh-key.ps1`、`vi.ps1`。

### 同类参照

与 **bat v2.6.0 A-1**（`cfg_state.emit` 丢弃子 converter report → `--fail-on-todo` 静默失效）
**同模式**；本修复为 **PS 路径的独立、既有**问题（v1.8.0 起的报告 taxonomy）。

## 2. PS 评估结论（引用）

本版随附 PS 解冻只读评估（4 份文档）：

- **判定：继续冻结**（维持 PS 实验性定位）。依据：
  - 根本障碍 = **语义**（对象模型/`.NET`/CIM/注册表/远程，bash 无等价物），实测 **41.7%** 文件触及；
  - **PS strict = 0/664**——即便修好全部语法，语义等价仍不可达；
  - **无真实需求**（T1/T2/T3 未触发）；**pwsh oracle 缺失**（语义不可验证）。
- 详见 `docs/ps-assessment-history.md`、`ps-assessment-reality.md`、`ps-assessment-blockers.md`、
  **`ps-assessment-verdict.md`**（核心）。

> **边界声明（纪律）**：本版修 **报告诚实性**（`todo_count` 如实反映产物中的 `# TODO`），
> **不是「PS 解冻」**，也**不改变 PS 转换逻辑**（对象模型等 D 档仍为显式 TODO）。
