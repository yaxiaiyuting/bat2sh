## bat2sh v2.10.0

> **性质**：`2.10.0` **minor**。新增两项**行为告警**，都来自行为追踪的实测发现：
> ① 检测 **LF-only / 混合行尾** 的 `.bat`/`.cmd`（cmd.exe 会解析错乱）；
> ② 检测 `start` 的**模态框挂死风险**目标（找不到会弹框、批处理永不退出）。
> **不改变任何转换产物**（151 语料 + examples 共 157 个文件逐字节比对 = **0 变化**）；
> **不改变退出码口径**（未新增 TODO）；**不引入新依赖**；**AUR 不进**。

## 1. New features

### 1.1 LF-only / 混合行尾告警

**来源**：VM 行为采集的实测发现（`research/behavior-tracking/batch-result.md` §4.1）。

**实测证据**：

| 样本 | 编码 | CRLF | 单独 LF | 结果 |
| :--- | :--- | ---: | ---: | :--- |
| s01 | UTF-8 | 0 | 72 | ❌ `rc=255`，stderr 满屏"不是内部或外部命令" |
| s02 | UTF-8 | 0 | 55 | ❌ `rc=255`（同上） |
| s10 | GBK | 0 | 23 | ❌ `rc=1` + 垃圾产物 |
| s03 / s04 | GBK | 2 / 1 | 0 | ✅ `rc=0` |

**A/B 对照（决定性）**：把 s02 **只做 LF → CRLF 转换**（内容一字不改）重跑：

| | 原始（LF） | 仅转换行尾（CRLF） |
| :--- | :--- | :--- |
| `exit_code` | **255** | **0** |
| stdout | （空） | 完整输出（354 ms 跑完） |
| stderr | 满屏"不是内部或外部命令" | **空** |

语料普查：**206 个文件里 55 个（26.7%）是 LF-only**。⇒ 这些脚本**在真 Windows 上也跑不对**，
不是 VM 的假象。bat2sh 现在在转换时如实提醒。

**行为**：

| 项 | 说明 |
| :--- | :--- |
| 触发 | 源文件（`.bat`/`.cmd`）**只有 LF 换行** → 告警；**混用 CRLF+LF** → 另一条告警；纯 CRLF → 不报 |
| 范围 | **只对批处理**。PowerShell 解析 LF 正常，不报（实测口径不同，不搞一刀切） |
| 强度 | **只警告**：不阻断转换、不自动改写源文件、不新增 TODO（退出码口径不变） |
| 位置 | 进 `report.warnings`，行号 `0`（整个文件的属性，与"输入编码无法解码"同口径） |
| 出口 | CLI `--report` / `--report-json`、GUI 报告面板、库调用 `convert_file()` 都能看到 |

```
$ bat2sh --cli legacy.bat --report
...
── 警告 ─────────────────────────────────
  [其他]
    第 0 行: 此脚本只有 LF 换行，Windows cmd.exe 解析会出错（实测：命令行首被逐行吃掉、
             报"不是内部或外部命令"）；建议把源文件转为 CRLF（bat2sh 不会自动改）
```

**影响面**（在 **224** 个真实文件上实测：非常批处理 151 + bat-master + 下载根目录 + examples）：
**71 个文件**（31.7%）会看到这条提醒 —— bat-master 55 / 下载目录 12 / examples 4；
其中 1 个是"混合行尾"版本。**它们的转换产物字节完全不变**。

### 1.2 `start` 的模态框挂死风险告警

**来源**：同一批采集的实测发现（`research/behavior-tracking/batch-result.md` §4.2）。

**实测证据**：两个样本把 120 s 执行超时烧满 ——

| 样本 | 结尾动作 | 后果 |
| :--- | :--- | :--- |
| s13 `HOTFIX.CMD` | `start "" "E:\软件\…\打开系统自带命令行参考.bat"` | `start` 找不到目标 ⇒ **弹模态错误框** ⇒ 156.9 s 超时 |
| s16 `范例.bat` | `start "" "BalloonTip.exe" …` | 同上 ⇒ 150.1 s 超时 |

这两个脚本**不含 `pause`/`set /p`**（静态"非交互"筛选通过），但模态框需要一个"人"去点确定 ——
采集环境里没有，于是进程**永不退出**。这是"非交互筛选"漏掉的一整类脚本。

**行为**：`start` 的目标**无法在 Linux 侧验证是否存在**，所以 bat2sh **不猜**，只如实声明
"无法确认 + 失败方式不同"：

| 目标形态 | 告警要点 |
| :--- | :--- |
| 字面量路径（含盘符/分隔符/扩展名） | "bat2sh 无法在 Linux 侧确认它在 Windows 上是否存在；实测目标不存在时 start 会弹模态框并一直卡住（转换后 xdg-open 只会立即报错）" |
| 裸程序名（`BalloonTip.exe`，无路径） | 同上（"转换后只会立即报错"） |
| 含变量（`%mydir%\a.exe`） | "静态无法判断它在 Windows 上是否存在……（转换后不会卡住，行为不同）" |

**刻意不做**（保守优先）：

- ❌ **不**断言"目标不存在" —— Linux 侧没有 Windows 文件系统，任何"检查存在性"都是假检查；
- ❌ **不**因为它新增 TODO —— "无法确认存在"不等于"需要人工改写"，而 TODO 会改变
  CLI 退出码（`--print --fail-on-todo`）与批量报告口径；Windows 专有命令（如 `START REGEDIT`）
  仍走既有的 TODO 路径，未受影响；
- ❌ **不**改产物：`start <路径>` 依旧转成 `xdg-open … &`，`start <程序>` 依旧 `nohup … &`。

**影响面**：224 个被测文件中 **26 个**新增告警（合计 **74** 条：字面量路径 23 / 裸程序名 25 /
含变量 26；最大单文件 +45 —— 那是一份 45 处 `start` 的工具箱菜单脚本）。

### 1.3 附带的一致性修复：CLI 路径补上"输入编码无法解码"告警

`--print-only` / `--run` / `--fix-todos` 三条 CLI 路径过去**不报**"输入编码 X 无法解码全部字节，
已用替换字符代替"（只有库调用 `convert_file()` 报）。三条路径统一收敛到新的
`convert_decoded()` 之后，这个告警在 CLI 也如实出现：

```
$ bat2sh --cli gbk 文件.bat --encoding utf-8 --dry-run --report-json
  警告: 输入编码 utf-8 无法解码全部字节，已用替换字符代替
```

**只影响报告，不影响产物与退出码**（告警不改变转换结果）。

## 2. 已知限制

| # | 限制 | 说明 |
| :-- | :--- | :--- |
| 1 | 行尾告警是**文件级** | 行号固定 0，只报"存在 LF 行尾"，**不定位到具体行**（要定位得做逐行对照，成本高且易误报） |
| 2 | `start` 告警**不是存在性断言** | 它说的是"无法验证 + 失败方式不同"。目标确实不存在时它是对的；目标存在时它也只是提醒（不误报为错误） |
| 3 | 裸程序名告警会覆盖系统自带程序 | `start notepad.exe` 也会告警 —— 因为"PATH 上有没有"同样无法静态判断。**宁可多说一句，不可假装知道** |
| 4 | 行尾判定只看 `\n`/`\r\n`/`\r` | 单独 `\r`（老 Mac 风格）与 LF 合并计；这类文件极罕见 |
| 5 | 不覆盖缺行尾的最后一行 | `foo`（无换行结尾）不计入任何类别；不影响 `lf`/`crlf`/`mixed` 判定 |
