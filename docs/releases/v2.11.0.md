## bat2sh v2.11.0

> **性质**：`2.11.0` **minor**。修掉**运行时 oracle**（真机 cmd.exe vs 产物沙箱的差分）
> 发现的 **3 个真实转换缺陷**（F1/F2/F3），外加诊断期新发现的同类缺陷 **F5**。
> **其中 F2/F3 原本是完全静默的**（`rc=0`、stderr 空、无 `# TODO`）——
> 既有语料仪器判它们"**功能完好（严格）**"，而 oracle 问的是"**和真机做的一样吗**"。
>
> **两处产物行为变化**（因此取 minor 而非 patch）：
> ① `for /r` 的 `%%i` 由相对路径（`.`/`./a`）改为**完整路径**（与 cmd 一致）；
> ② `type` 与"变量接变量"的路径分隔符由字面 `\` 改为 `/`。
> **不引入新依赖**；**退出码口径不变**（151 语料 `todo_count` **0 变化**）；**AUR 不进**。

## 1. 缺陷与修复

### 1.1 F1 —— `type` 的 `\` 未转换

**来源**：运行时 oracle（V3 `poc-02-fileops.bat`、V4 `copy.bat`）

```bat
set "W=%~dp0sub"
mkdir "%W%"              →  mkdir -p "${W}"          ✅
echo data>"%W%\f.txt"    →  echo "data" >"${W}/f.txt" ✅
type "%W%\f.txt"         →  cat "${W}\f.txt"        ❌ 反斜杠保留
del "%W%\f.txt"          →  rm -f "${W}/f.txt"      ✅
```

`cat "${W}\f.txt"` 在 bash 里是**字面文件名** `…/sub\f.txt`（反斜杠是合法文件名字符）⇒ 必然读不到；
又因 `set -euo pipefail` 触发提前中止，把后续 `del` 等操作一起吞掉。**半静默**：rc 被污染、无 `# TODO`。

**根因**：`type` 同时登记在 `BATCH_SIMPLE_MAP`（`"type": "cat"`）与 `BATCH_HANDLER_MAP`
（`"type": "cmd_type"`），**handler 优先** ⇒ `cmd_type` 直接返回参数，绕开了
`BATCH_SIMPLE_MAP` 那条会做 `convert_backslashes` 的分支。
handler 全量审计（41 个）确认：**取文件路径的 handler 里只有 `cmd_type` 两者皆无**。

**修复**：`cmd_type` 补 `convert_backslashes(args)`，与该分支**逐字同构**。

### 1.2 F2 —— `for /d` 集合的**末元素**被当成通配符 ⚠️ 完全静默

**来源**：运行时 oracle（V1 `快速创建文件夹.bat`）

```bat
for /d %%i in (樱野,王子变青蛙,其他) do md %%i
```
```bash
shopt -s nullglob                  # ← 被误判为需要
for i in 樱野 王子变青蛙 其他/*/; do   # ← 末元素被追加 /*/
    mkdir -p ${i}
done
```

`nullglob` 下 `其他/*/` 若无匹配 ⇒ **整个词被静默删除** ⇒ **`其他` 从未被建**。
真机 cmd.exe 建出 **3 个**目录。**完全静默**：rc=0、stdout/stderr 全空、无 TODO。

**根因**：`_convert_for` 的 `/d` 分支对 `items` 做 `rstrip(" *") + "/*"` 与 `+= "/"`，
而 `items` 是 `_convert_for_set` 返回的**已拼接好的单个字符串**（`"aa bb cc"`）——
两次都是**字符串尾部操作**，**只能命中最后一个 token**（纯位置性，与随机无关）。

**修复**：**逐元素**判定 —— 含 `*`/`?` 的元素追加尾 `/`（bash 侧"只匹配目录"），
字面元素原样保留。规则由**真机指纹**导出：那三个目录在循环开始时都不存在，
说明 cmd 对不含通配符的元素**按字面产出、不查存在性**。
附带效果：不再注入误导性的 `shopt -s nullglob`。

### 1.3 F3 —— `for /r` + `%%~ni` 建出字面文件 `.\.txt` ⚠️ 完全静默

**来源**：运行时 oracle（V5 `以文件夹名为名建立文本文件.cmd`）

```bat
for /r %%i in (.) do (cd.>"%%i\%%~ni.txt")
```
```bash
while IFS= read -r i; do
    cd "." >"${i:-}\\$(basename "${i%.*}").txt"
done < <(find . -type d)
```
实际建出 **6 字符文件 `.\.txt`**，应为 `samples.txt`。**完全静默**。

**根因是两个独立机制**（只修任一个都不够：只修 B ⇒ `.\samples.txt`；只修 A ⇒ `.txt`）：

| | 机制 |
| :--- | :--- |
| **A** | `\` 后接变量展开 ⇒ 见 §1.4（F5） |
| **B** | `_modifier` 把 `%%~n` 映射成 `basename "${v%.*}"`，对 `for %%f in (*.txt)` 的值 `a.txt` 正确；但 `_emit_for_r` 用 `find . -type d`，值域是 `.` 与 `./sub` —— **每个值都带前导点**，`${v%.*}` 从那个点剥起 ⇒ **恒为空串** |

**修复**：`find .` → `cd <root> && find "$PWD"`。
① 同时修好 `%%~n` 与 `%%~nx` 且**不碰 `_modifier`**（A1 邻域）；② 更接近真机 ——
cmd 的 `for /r %%i in (.)` 给的本来就是完整路径。
写法上**不用** `find "$PWD"/<root>`：后者在 root 本身是绝对路径时会退化成
`<cwd>/<绝对路径>`（cmd 完全允许绝对 root）。

### 1.4 F5 —— `\` 后接变量展开时未转换为路径分隔符

**来源**：本 session 只读诊断期发现（oracle 未报）。这是 F3 机制 A 的**全量面**。

`convert_backslashes` 在 `_expand_vars` **之后**运行，而展开会把变量名换成 `${VAR}` / `$(cmd)`：
源里 `\` 紧跟变量名，展开后紧跟 `$` ⇒ 被判为"转义序列"而保留，产物指向**字面反斜杠文件名**。

**151 语料实测（产物签名，14 文件 / 48 处）**：

| 文件 | 修复前 |
| :--- | :--- |
| `文件备份器V2.3修改版2.cmd` | `}"${destination}\${name_log}_log.log"` |
| `一键转移桌面…` | `"${partition}:/Personal\${USER}"` |
| `提取IE缓存的指定文件.bat` | `"$(pwd)\${filetype}\$(basename \"${i}\")"` |

**修复**：让 `convert_backslashes` 认识"展开插入的替换"（`${` / `$(` / A1 块内冻结占位符）。

落点选择有讲究：**不**在 `_expand_vars` 顶部做通用预转换 —— 那样会把
`# TODO[REG]` 里的**注册表键路径**（`HKLM\SOFTWARE\…\%input%`，那里 `\` 才是正确分隔符）
一起改成 `/`。`convert_backslashes` 只在转换器**已判定为路径**的调用点生效，天然避开。
对照实测：预转换写法漂移 **17/155**，本写法 **13/155**。

**三类显式排除**（保守，均有实测理由）：

| 排除 | 理由 |
| :--- | :--- |
| **反斜杠连写** `\\` | UNC / 字面反斜杠，交给原有规则整体保留 |
| **`\\?\` / `\\.\` 前缀** | Windows 扩展长度/设备前缀，Linux 无对应物。若转换，`_convert_path_token` 的通配符回退会产出**未加引号的** `rm -rf \/?/${1:-}`（`?` 是活通配符，可能误删根下单字符目录）⇒ 属"不做映射"（同盘符/UNC） |
| **单个 `$`**（`\$5`） | 不是替换 |

**残留（有意保留，已逐条核对）**：48 处 → **16 处 / 4 文件**。
其中 7 行是 `# TODO[REG]` 注册表键路径、2 处是 `全删.bat` 的 `\\?\` 前缀、其余为 `\\` 连写。
**可执行代码里再无"该转而未转"的 `\${`。**

## 4. 已知限制

| # | 限制 | 影响 |
| :-: | :--- | :--- |
| **L1** | `%%~n` 的通用表达式仍是 `basename "${v%.*}"`，未加固 | 绝对路径后，只有**父目录某段含点**（如 `~/my.project/`）时才截错 —— 比修复前（恒坏）严格更好但**未根除**。彻底加固需改 `_modifier`（A1 邻域） |
| **L2** | `for /r` 的 `%%i` 由相对变**绝对** | 依赖 `%%i` 文本形态的脚本行为会变（这是**向 cmd 靠拢**，故取 minor） |
| **L3** | `\` 后接变量仍有 3 处可执行残留 | 均为**有意排除**（`\\?\` 前缀 2 处、`\\` 连写 1 处），属"不做映射" |
| **L4** | F4/盘符行为**对用户无告警** | 把日志写到 `C:\logs\` 的脚本，在 Linux 上静默写进 `./C:/logs/`。是否加告警属产品决策 |
| **L5** | oracle 的覆盖边界未变 | 纯差分 oracle 的可判定面仍只有 A 类 4/151（2.6%），且两侧盲区相同。**本轮只证明"这 5 个样本上缺陷已消除"，不能外推整体正确率** |

## 5. 关于"运行时 oracle"的定位（**必须说清**）

**来源**：本版修的是**运行时 oracle**（`research/behavior-tracking/`）发现的缺陷。
该设施把同一脚本分别在**真机 cmd.exe**（QEMU + QGA，固定时间/隔离网络/全盘 CoW 回滚）
与**产物沙箱**（bwrap `--unshare-all`）里跑一遍，只做**净差分**，
再按"最小规则集 + 每条规则写明掩盖了什么"做三分类。

**定位：深度抽检，不是 CI 门禁。**

| | 运行时 oracle | 既有语料仪器 `measure.py` |
| :--- | :--- | :--- |
| 问的问题 | **和真机做的一样吗** | **跑通了吗** |
| 成本 | W 侧 **44–53 s/样本**（冷启动 + 回滚 + QGA） | 151 语料全跑一遍可接受 |
| 覆盖 | **5 个样本** | 151 个 |
| 能否当回归门 | ❌ 成本结构不匹配 | ✅ |

**它发现的东西，既有指标结构上发现不了**：V1 与 V5 在本版之前被
`measure.py` 判为"**功能完好（严格）**"（`rc=0`、`todo=0`），而行为是错的。
本版没有改变这个覆盖边界 —— 它证明的是"**这 5 个样本上的差异现在只剩下可归因项**"，
不是"bat2sh 更正确了 X%"。

## 6. 升级建议

- **建议升级**：F2/F3 **完全静默**，用户不会从任何现有信号知道产物是错的。
- **可能出现的行为变化**：
  1. 若脚本用 `for /r` 且依赖 `%%i` 是相对路径，产物会变为完整路径；
  2. 若脚本用 `%VAR%\%VAR2%` 形式拼路径，产物由字面 `\` 改为 `/`（这是**修复**，
     旧产物在 Linux 上根本打不开那个文件）。
- 其余转换产物字节不变；`TODO` 数量不变。
