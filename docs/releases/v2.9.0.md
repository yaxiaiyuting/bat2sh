## bat2sh v2.9.0

> **性质**：`2.9.0` **minor**。新增 **Android 版 API 修复能力（含并行修复）** ——
> 在既有的 Flet + 内嵌 Termux 运行时之上，接入 `core/api/` 的 OpenAI 兼容修复链路，
> 并给出适配手机屏幕的并行面板。
> **`python/bat2sh/core/` 零改动**（`git diff` = 0 行）；**桌面 CLI/GUI 行为不变**；
> **不引入新依赖**（Android 侧仅 Flet + 标准库）。

---

## 1. New features

### 1.1 Android：API 修复（OpenAI 兼容，SSE 流式）

在 Android 应用内新增：

| 能力 | 说明 |
| :--- | :--- |
| **API 设置** | endpoint / key / model / enable_thinking / max_concurrency / timeout；key 以 `password` 字段遮蔽，**从不写入日志或错误信息** |
| **TODO 检测** | 复用 `core/api/fixer.py::scan_todo_markers`，转换后自动统计并在工具栏下方显示「报告里 TODO N 条」 |
| **隐私提示** | 每次发送前 `AlertDialog` 确认（`将把 N 条 TODO 发送到：<endpoint>` + 离开本机提示），**不记忆** |
| **并行修复** | 复用 `core/api/parallel.py`，默认并发 3，429 自动退避降并发 |
| **逐 chunk 流式** | 每条独立显示模型输出，边收边渲染 |
| **错误隔离** | 一条失败不阻塞其余；失败条目就近「重试这一条」 |
| **聚合 diff → 应用** | 全部收完后合并（降序 + 逐步 `bash -n` 闸门）→ 展示 diff → 确认 → 写回产物 → **重新 `bash -n`** → 落盘 |

**配置路径**：Flet 层在 `main.py` 首条语句注入 `XDG_CONFIG_HOME`，
`core/api/config.py` 的 `api_config_path()` 自动跟随，落点
`<FLET_APP_STORAGE_DATA>/config/bat2sh/api.json`（0600）。
**core 因此无需任何改动。**

### 1.2 Android：并行面板（方案 B：可展开列表）

手机屏幕约束下的设计（详见 `docs/android-api-assessment.md` §4.5）：

- **聚合头**：`x/N 完成 · y 进行中 · z 失败` + 进度条，全程可见全局态势；
- **可展开列表**：折叠行只显示状态；点击展开该条的流式正文；
- **按需渲染**：流式正文**只写进被展开的那一条**的控件（折叠行只更新一行状态串），
  使每轮 `page.update()` 需序列化的控件树小一个量级；
- **自动展开首条 running**，之后不再抢焦点；
- **大差异摘要**：聚合汇总基于**全部任务**，不因单条重试而退化。

### 1.3 关键实现：Termux 语法闸门（P1 同型缺陷的关闭）

`core/syntax.py::bash_syntax_error()` 在 `shutil.which("bash")` 为 `None` 时
**`return None`（判通过）**。Android 上 Termux 的 bash 不在 PATH，
于是并行修复的每一处「建议未通过 `bash -n`」闸门都会**静默假通过** ——
坏合并会被写进产物且用户看不到任何错误。

本版在 Flet 侧注入 Termux 版 `syntax_checker`（`api_bridge.make_syntax_checker`），
契约不变但**「未执行」一律判失败**，并**同时注入** `run_parallel` 与
`merge_replacements` 两处。**core 一行未改**（`syntax_checker` 本就是为注入而设计的参数）。

### 1.4 关键实现：刷新节流（线程纪律）

工作线程**只入队**（`on_event=q.put`），唯一调用 `page.update()` 的是
`page.run_task` 调度在事件循环里的 drainer，每轮把已到达的事件全部吃掉再刷新一次。
实测批量比 ≈28:1；给 `page.update` 装线程 ident 探针验证：**15 次刷新，工作线程越界 0 次**。

既有 `_say` / `_log` 也从「后台线程直接 `page.update()`」改为经 `UiPump` 投递，
消掉了「转换线程与并行 drainer 同时改控件树」的隐患。

## 2. Fixes（Android 侧）

| # | 现象 | 根因 |
| :--- | :--- | :--- |
| 1 | 语法闸门构造即 `TypeError` | 工厂函数提前求值 `tx.work`，此时运行时可能尚不可用 |
| 2 | 聚合 diff 深底深字、几乎不可读 | `ft.Text` 未显式给 color，浅色主题默认前景为深色而落在 `GREY_900` 上 |
| 3 | **失败条目的流式框塌成一条竖线** | `ExpansionTile.controls` 不横向拉伸子元素，失败条目无 chunk → 正文为空 → Text 宽 0 → `Container` 塌缩（与 `docs/android-poc-v2-report.md` §4.6 bug#2 同型） |
| 4 | 单条重试后汇总退化成「共 1 条」 | 误用重试作业的 `ParallelResult`，应按面板全部任务汇总 |

> bug 1 由桌面 smoke test 发现；bug 2/3/4 由**实机截图**发现。
> bug 3 尤其隐蔽：成功行因正文长而「看起来正常」，只有失败行才暴露。

## 3. 发布工程

- **`scripts/release-bump.sh` 纳入第五处版本号**：`packaging/android/pyproject.toml`。
  它是独立 Flet 工程、决定 APK 的 `versionName`；不同步即 D-1 翻版
  （「tag 说 A、发布出去的 APK 自称 B」）。`--check` 现在校验**五处**一致。
- **`docs/release-process.md` §6.3 结论被推翻**：原文「Android APK 不可行，原因在上游」
  针对的是 **PySide6** 路线（Qt 未发布匹配的 Android wheel）。本版走的是
  **Flet + 内嵌 Termux bootstrap** 路线，已实际产出可安装 APK，该节已更新。
- **本版起 Release 附 Android APK 资产**（首个二进制 Android 产物）。

## 5. 已知限制

| # | 限制 |
| :--- | :--- |
| 1 | **arm64 真机执行未验证**：全部执行验证在 x86_64 模拟器完成；arm64 仅验证了构建产物。**请以实机为准。** |
| 2 | 并行面板列表为固定高度 + 内部滚动：展开一条后，正文框与「重试」按钮可能需在列表内再滑一次（嵌套滚动）。功能不受影响，小屏略绕。UI 重构留待后续版本。 |
| 3 | 只能修单个文件；无连接测试；不暴露 `context_lines`（沿用 core 默认 3）。 |
| 4 | API key **明文存储**（决策，用户自担风险）：0600 + 应用私有目录隔离实测生效。 |
| 5 | 应用内「运行」以同 UID 执行任意 bash，**因而能读到 `api.json`**。请只运行可信脚本。 |
| 6 | `android:allowBackup` 未声明（默认 true），Flet 不暴露该开关。 |
| 7 | **targetSdk 28**：不满足 Google Play 上架要求（侧载无影响），是 Phase A 拿回完整 shell 能力的硬要求。 |
| 8 | APK 约 87 MB（Termux bootstrap 占 32 MB）；**debug 签名**。 |
| 9 | 产物首行 `#!/usr/bin/env bash` 在 Android 上无效，不能 `./x.sh`，应用内一律 `bash <script>`。 |
