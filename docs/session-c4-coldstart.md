## 三、用自己的话复述（非任务书复读）

### 3.1 C4 是什么

C4 = **批处理 `goto`/标签控制流的静态翻译子系统**。cmd 的 `goto :label` 是**任意跳转**
（可前跳、可回跳、可跳出/跳入控制块、可跨函数），而 bash 没有 `goto`：只有
`while`/`for`/`if`/函数/`break`/`continue`/状态机。要把 goto 译对，必须先做
**控制流图（CFG）分析**：确定标签位置、可达性、循环/分支结构，再改写成结构化控制流。

路线图把它记为 **1.x 单点最大工作量**（15–25 人日）、**风险最高**，并明确排到 **v2.0**（§1.C4、§2.2、§3.1、F1）。它同时被列为「TODO 多、文件翻转少」的典型：
设施 ROI 表记 `goto 235 TODO / 16 文件 / 单设施翻转 1`。

### 3.2 路线图对 C4 的假设

| 假设 | 路线图原文 | 本会话实测 |
| :--- | :--- | :--- |
| 规模 | `~250 TODO`（§1.C4）、`235 TODO / 16 文件`（§3.4） | **degraded 内 goto TODO = 252 / 22 文件**（与 ~250 吻合，**文件数 22 ≠ 16**） |
| 全语料规模 | 未给（只统计 86 degraded） | **goto 语句 1600 条，涉 45 文件**；goto TODO 全量 1362 |
| 宿主 | `135 系统优化.bat`（439 TODO、横跨 10 类） | ✅ `135` degraded todo=443、其中 goto=194 |
| 收益 | 单设施翻转 **1** 文件 | 实测**唯一阻塞=goto** 的 degraded 文件 **3**（038/039/040），其中 `039` 实为 `for /f` 选项不可解析所致，**非 goto** → 真实翻转 ≈ **2** |
| 归属 | v2.0（F1）、需 B3 黄金对照 + B5 解析层 | 一致 |
| 风险 | 与 v1.8.1 B1/B1b 块闭合同域、`%%i` 回归高危区 | 一致（同域：`_prepass`/`_label_line`/`_convert_for`/`_convert_if`/块栈） |

### 3.3 C4 与 053 的关系（同域？已修部分？遗留部分？）

- **同域**：两者都属「块栈/控制流」核心。053 的根因是 `_convert_if` 对行尾未配平的
  `else (` 错误 `pop`+补 `fi`，与 `_close_block_line` 不一致 → 块栈失同步 → `%%i` 逸出循环。
- **已修部分**：053 **已在 v1.9.0 修复**（commit `61a4b44`，5 hunk 非词法层补丁；
  见 `docs/research/chenpi11-cmd-reference.md` §0.1/§2.3，g01–g03 全 MATCH）。
  **v1.9.2 并未"修 053"**——v1.9.2 的 C1 修的是 `%ERRORLEVEL%` 默认 `map` 与相邻 `%…%%…%`
  嗅探，把 L1「逸出」由 13 条压到 4 条（任务书「v1.9.2 修了 053」为前提偏差，见 §四）。
- **遗留部分**：v1.9.2 明记剩余 **4 条「真块失同步」**（`docs/v1.9.2-rounds.md:99-102`），
  本会话在语料中逐条复现（产物 TODO 消息含「逸出 for 循环（块结构失同步）」）：

  | id | 文件 | 产物行 | 形态 |
  | :--- | :--- | :--- | :--- |
  | 044 | `备份文件/备份服务.bat` | L15 | `%%j`/`%%s` 逸出（`echo sc config %%j start= %%s >>"%FILENAME%")`） |
  | 059 | `打开快捷方式指向的目录.bat` | L21 | 内层 cmd 字符串内 `%%i`（`cmd /c "… &for /l %%i …"`） |
  | 135 | `系统优化.bat` | L4228 | `%%j`/`%%k` 逸出（`echo sc config %%j start= %%k >>"%filename%")`） |
  | 138 | `获取U盘盘符和可用容量.bat` | L29 | `%%%%` + `%~1`（`set /a m3=%m3%%m:~0,1%%%%~1`） |

  → 这 4 条**不是 goto 问题**，是块栈/词法层残余；属 C4 的**更大「控制流」域**，但**不是 C4 的 goto 靶子**（见 §四.3）。

- **推导**：C4（goto）与 053（块栈失同步）**同域不同机制**。改 goto 会经过 053 曾失稳的
  同一批函数（`_label_line`、`_convert_for` 的 `goto` 守卫、`_prepass`），因此**任何 goto
  语义转换都必须把 053 复位后的块栈测试当作回归闸门**（B3 黄金对照 + 全量 pytest）。

## 四、前提核对（任务书 §四.3）

### 前提 1：v1.9.2 修了 053 → **不准确（前提偏差，需披露）**

- **事实**：053 于 **v1.9.0**（`61a4b44`）修复；v1.9.2 未再动 053。
  v1.9.2 的 C1 把 L1 的 `%ERRORLEVEL%`（25）与「逸出」（13→4）收尾。
- **影响**：不影响 C4 判断（053 域确已复位，块栈不再是「已知失稳」状态），但**任务书该句
  须更正**。已在 `docs/session-c4-report.md` 与 release notes 披露。

### 前提 2：v1.9.2 剩余 4 条「真块失同步」= C4 的靶子吗？ → **否**

- 4 条（044/059/135/138）均为**块栈/词法层残余**（循环变量逸出、`%%%%`+`%~1`、内层 cmd 串），
  与 goto **无关**；它们仍是 `L3b`（控制流/块结构）但**不是 goto 子系统**。
- C4 的 goto 靶子实测为：**22 个 degraded 文件 / 252 条 goto TODO**，其中重度集中在
  `135 系统优化.bat`（194）与 `启动OFFICE.bat`（12）。
- **结论**：任务书把「4 条残余」与「C4 goto」并列为同一靶子，**口径不符**；两者应分开处置。

### 前提 3：路线图 §3.4 的「1.x 下界 46/40」是否仍成立？ → **成立（输入未变）**

- 本会话实测（`/tmp/b1b2/measure.py` 同口径重跑，仪器先验证：`/tmp/b1b2/measure.json`
  与 `baseline_v192.json` 均得 `strict 16 / degraded 86 / TODO 894`）：
  `语法 147/151、rc==0 102、功能完好 16、degraded 86、崩溃 0` —— **与 v1.9.1 基线一致**。
- 46/40 是**文件级设施桶**分类（可做设施 vs 阻塞设施）。v1.9.2 与 B1/B2 **未翻转任何文件**
  （16/86 不变），且 v1.9.2 移除的是**可做设施**（errorlevel）的 TODO、B1/B2 触及的是
  非 degraded 文件（031/077/135 既有）→ **不改变 46/40 的划分**，下界仍成立。
- ⚠️ **披露**：本会话独立统计的「goto 阻塞 degraded 文件」= **22**，而路线图 §3.4 记 **16**。
  差异源于「阻塞文件」口径（是否计入混合设施文件）；**不影响结论**（goto 翻转 ≈ 2 文件）。

### 前提 4：是否有「可证安全」的 goto 子集可先做？ → **否（已实测）**

| 候选安全子集 | 实测 | 结论 |
| :--- | :--- | :--- |
| 冗余 goto（目标 = 紧邻下一非空行） | 全语料仅 **8 条**，**全在 `031`（syntax-fail）** | 翻转价值 0 |
| `goto :eof`（顶层） | 96 条，**已由 `_convert_goto` 处理**（→ `exit 0`/`return`） | 已做 |
| `goto :eof` 在块体内 | 仅 `039` 一处形态，但该行**先**因 `for /f` 选项不可解析而 TODO | 与 goto 无关 |

→ **没有可证安全且有余量的 goto 子集**。

### 裁定所用模式分布（任务书 §五「评估语料嵌套模式分布」）

goto 语句 1600 条（45 文件）：**backward 704 / forward 781 / 目标缺失 19 / `:eof` 96**；
**条件式（`if … goto`）909**；**位于控制块内 462 / 顶层 1042**。
按「位置 × 方向 × 条件 × 目标」组合 → **≥ 十余种形态（数十种细分）**。
→ 依任务书判据「几十种 → **必须状态机**」，**撞库只能当兜底**。
