## 3. 必须回答的四个问题（任务书 §4.2）

### 3.1 ChatGPT 的建议有多少是项目已知的？

> **四分之三已知，四分之一是可导出的标量。**

| 建议要素 | 已知度 | 证据 |
| :--- | :---: | :--- |
| root cause 聚类 | **100%** | v1.8.3 A/B/C/D/S + v1.9.1 L1–L5 + v1.11.0 十桶 + 产物 51 reason |
| 可泛化性分类 | **100%**（换名） | v1.11.0 §0「单设施文件」列 = 「这个文件能否被单一规则翻转」 |
| 预期影响（files） | **100%** | v1.9.1 §5.1–5.4 覆盖 TODO 列；v2.2/v2.3「可翻转文件数」 |
| Generalization Ratio | **0%（未命名），但 100% 可导出** | 本 session 只读算出 0.96 / 0.60 / 1.00 |

**同时必须指出建议的一处事实错误**：建议书称「85 个 degraded」（任务书正文写 82）——
**当前实测 = 82**（v2.5.0 起 86→82 的定义性 `rc0` 位移；85 是 v2.3.0 时点）。

### 3.2 「可泛化性」分类能揭示什么新东西？

> **实测：0 项。**

三处已实测的塌缩：

1. **signature 级泛化是假象**。`reg` 跨 15 文件、`for` 跨 14 文件、`if` 跨 10 文件——
   一旦按 `reason` 拆成真实规则，`for` 内部就是 **6 条不同规则**，一条规则回到一个文件。
2. **多文件规则 26 条，可实现的 0 条**。全部落在已判终态（无注册表 / 无 COM / 无 WMI / 无驱动模型 /
   无设备模型）或已判语义层（未转义 `>/<` / `%date%` 区域格式 / `for /f` 变量选项 / 块结构失同步）。
3. **三分法缺一格**。实测 38 个文件（321 TODO，46.3%）属「语义/词法/解析层」——
   既不是「可泛化」，也不是「环境依赖」或「不可等价」。**矩阵的三分法会把最大的一类挤进错误的格子。**

### 3.3 「规则爆炸」担忧在 bat2sh 上成立吗？（实测泛化比）

> **成立，且比担忧更严重。**

| 口径 | 泛化比（实测） |
| :--- | ---: |
| 现存（82 degraded，84 条规则） | **0.96 文件/规则**（69% 的规则恰好覆盖 1 个文件） |
| 历史已执行（2.x 翻转清单 5 条，strict 口径） | **0.60 文件/规则** |
| 历史已执行（处置口径） | **1.00 文件/规则**（无一条规则影响 >1 个文件） |

**但项目已处理过该担忧**：`docs/v2.2.0-reality-check.md` §0 确立协议
「**不数 TODO，数可翻转文件**」，正是对「TODO 数虚高 / 规则不可泛化」的正面回应；
`docs/v2.3.0-2x-closure.md` §3 用该协议逐项证明「**不是执行失败，而是分辨率受限**」。

> 换言之：**矩阵会再次得出同一个结论，而项目已据此收尾。** 这是「价值低」的最强理由。

### 3.4 如果做矩阵，预期能翻转多少？（必须实测）

> **0（实测）。三条独立证据，方向一致。**

| # | 实测 | 数据 |
| ---: | :--- | :--- |
| 1 | **结构前提** | 82 个 degraded 中，**20 个多桶**（任何单一规则都不可能翻转）；61 个单桶里 **60 个的桶已被判定**（终态/2.x/已做）；**未判定 = 0**；余 1 个是 marker-only（error 层 `label_in_block`，非 todo 层） |
| 2 | **目标物** | `bwrap` 沙箱实测（`ro-bind /usr`）：`beep`/`xdotool`/`lftp`/`nconvert`/`unar`/`at`/`recycle`/`subst`/`devcon`/`wmic`/`cmdow` 全部 **MISSING** → 写出映射也 `rc≠0`，不产生 strict。（`regedit`/`regsvr32`/`notepad` 的 EXISTS 是 **wine 符号链接**，非等价物） |
| 3 | **指标** | strict **v1.9.0 16 → v1.11.0 19（+3，来自 3 条规则）→ v2.0.0–v2.9.0 恒 19**；本 session 在 HEAD 复测 = **19** |

**注意这不是估算**：第 1 条是「61 个单桶文件 ∩ 桶归属」的直接计数；第 2 条是沙箱内 `command -v` 的
直接输出；第 3 条是八个连续版本的发布指标 + 本 session 复测。**没有任何一步用「预计/大约」。**
