## 1. 方法与分层定义

**归因单元**：文件级（86 条）为主，同时给出 TODO 级分布（913–914 条）。
**层的判定依据**：TODO 的**转换类别 + 命令 token + 消息语义**，并对照源行。

| 层 | 定义（本文件口径） | 判据 |
| :--- | :--- | :--- |
| **L1** | 现有设施可修 | 已有映射/发射机制/告警设施即可覆盖（如 `--last-exit-code map`、块栈修复后的循环变量） |
| **L2** | 需**单命令/单构造**映射 | 一条命令或一个构造 → 一个 Linux 等价物（`sc`→systemctl、`attrib`→chmod、`for /r`→find） |
| **L3** | 需**子系统** | 路径/环境语义翻译、控制流重构（goto）、解析歧义消除 |
| **L4** | 需**语义理解** | Windows 对象模型/专有机制：COM、注册表写、WMI、设备模型、MMC |
| **L5** | 源文件畸形 | 输入本身非法（如 `%%1` 非法 for 变量）→ 应**响亮**警告 |
| **S** | 测量 artifact | 交互/`set -e`/fixture 导致 |
| **ENV** | 环境依赖 | 沙箱/systemd/工具缺失 |

> **S / ENV 在本集合中为 0**：86 条全部 `rc==0`；S/ENV 是 rc≠0（45 条）的类别，
> 不适用于 degraded 集合（两者互斥，见 `docs/v1.9.0-rounds.md` 严格口径）。

**归因覆盖**：272 个不同 TODO 签名 → 全部归入 L1–L5，**无「无法归入」项**（未触发暂停条件）。

## 6. 披露与偏离（纪律 4）

1. **任务书 pytest 1207 → 实测 1244**（v1.9.0 基线，1207 为 v1.8.2 数字）。
2. **`075 改名复制文件.cmd` 的 TODO 未登记**（0 登记 / 1 标记）：标记可见，非静默错，
   但 `--fail-on-todo` 不会命中。建议下一版补登记。本版只记录。
3. **层间边界为主观判定**，已在 §1 明示判据。以下三处最易争议，如实标注：
   - `sc` 计入 **L2**（单命令→systemctl），但「Windows 服务名 → systemd unit」实为**名称映射子系统**；
     若按子系统计，应为 L3。**取 L2**（命令层可直接映射，名称映射是附加约束）。
   - `goto` 计入 **L3**（控制流重构子系统）——与 L3 定义中的「路径/环境语义」并非同类，
     但同属「需子系统」。**建议下一版把 L3 拆为 L3a(路径/环境) 与 L3b(控制流)**。
   - `dxdiag`/`perfmon`/`mstsc` 计入 L3/L2（有 Linux 近似），`wmic` 计入 L4（对象模型）：
     同属「系统信息」，但前者是输出契约、后者是对象查询，难度不同。
4. **L4 的 216 条 `regsvr32` 高度集中在少数文件**（`重新注册IE.bat` 99、
   `重新注册所有的dll.bat` 105 等）：**文件级分布 ≠ 工作量分布**，L4 的 30 个文件里
   有 2 个占了 204/291。下一版排序建议以 **TODO 数 × 文件集中度** 双维度排。
5. **未触发暂停条件**：272 个签名全部归入 L1–L5，无「无法归入」项；
   无某条无法定 confidence 的情形。
