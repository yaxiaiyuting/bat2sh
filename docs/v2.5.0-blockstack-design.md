## 0. 一句话结论

完整 CFG 状态机的正确形态是**标签分派状态机**（label-dispatch：`while :; do case $pc in … esac; done`），
它**必然**要替代/绕过 `_label_line` 的「标签只发注释/函数头」假设，并**进入 053 的块栈发射邻域**。
**实测（本 session 只读探针）**：在严格「可证安全子集」判据下，`backward_loop` 的候选为 **0**
（唯一简单宿主 `显示所有分区的剩余空间（以MB为单位）.cmd` 的 `:Main` 区间被 `call` 目标 `:loop` 标签污染），
`in_block_goto` 为**主形态**（`史上最牛X` 126、`系统优化` 52）。→ **只有状态机才能覆盖；子集法已证伪。**
因此本 session 采用 **策略 B（双轨制）+ A（增量收窄）组合**：新建**受门控的 CFG 分派发射路径**，
旧路径对**不合格文件逐字节不变**（= 053 最强保护 + 最简回滚）；合格文件走新状态机。C（全量重写）仅作后备。

## 5.1 当前块栈机制（现状精确描述）

### 5.1.1 `_label_line` 做什么（`batch.py:1692-1724`）

| 分支 | 条件 | 行为 |
| --- | --- | --- |
| ① 块内标签 | `if self._stack:` | `_error_block_line(...)` **响亮拒绝**（`control_flow`；`label_in_block` 现处置） |
| ② goto 目标 | `key in _goto_targets and key not in _call_targets` | 发注释 `# :name（goto 目标，不函数化，主流程继续）`；若有 `_current_func` 则收尾。**不发射任何控制原语** |
| ③ 未使用 + 非函数模式 | `not self._function_mode` | 发注释 `# :name（标签，未使用，保留为注释）` |
| ④ 否则（call 目标） | — | 函数化 `label_xxx() {`，切到 `_func_out` 通道 |

**关键**：`_label_line` 只发**注释**或**函数头**；它假定「标签必在顶层」（靠分支 ① 拒绝块内标签）。

### 5.1.2 块栈发射层如何工作

- `_convert_logical`（`:577-622`）**逐逻辑行**调用 `_convert_line`，产物追加到 `_out`（主流程）
  或 `_func_out`（函数体内 `_function_mode and _current_func`）。
- `_convert_line`（`:1276-1433`）线性分派；块由 `_convert_if` / `_convert_for` / group 处
  **push** `_Block`，由 `)` 行 / `_close_block_line` / `if/for` 尾随处 **pop**。
- `_pop_block`（`:1467-1500`）按栈顶发 `close_word`（`fi`/`done`/`}`）。
- **无图结构**：发射是**线序**的；标签只作为注释；`goto` 不产生跳转（除 `:eof`）。

### 5.1.3 053 修复做了什么

053 = `for /f` + 行尾未配平 `else (` 使 `_stack` **失同步** → `%%i` 逸出 → `cat %i`。
v1.9.0 的 5 组 hunk（见 coldstart §2.2）引入 **`finish_parent` 链式收尾** + **`))` 递归闭合** +
**`else (` 跨行对称 push**，使「块头未闭合」时父块在**内层闭合时**一并收尾。核心是
**让块栈在异常缩进下仍保持同步**——它是**栈**结构修复，不是图结构。

### 5.1.4 当前机制对完整 CFG 的阻碍

| 阻碍 | 具体 |
| --- | --- |
| **无跳转原语** | 发射层只会「顺序 + 结构化闭合」；没有 `pc`、没有 `case`、没有回边 |
| **标签顶层假设** | `_label_line` 分支 ① 拒绝块内标签；而 CFG 要求标签是**任意可达点** |
| **线序 vs 图** | 发射顺序 = 源行顺序；CFG 需要按**边**决定控制转移，可能**逆序/跨块** |
| **块栈同步假设** | 053 修的是「栈同步」；图结构下块边界可能被 goto **中途穿越**（`in_block_goto`），栈模型本身不表达 |
| **函数化假设** | goto 目标**不函数化**（分支 ②）；状态机下标签是**分派臂**，与函数化无关 |

## 5.2 目标机制（完整 CFG 状态机）

### 5.2.1 目标数据模型

在 `core/cfg.py`（已有 `LabelPosition` / `GotoEdge` / `Cfg`）之上，新增**基本块**与**图分析**：

- `BasicBlock`：`[leader, …)` 连续逻辑行；`leader` ∈ {首行, 标签行, goto 后继行}。
- **出入口**：`block|label` 级入边/出边；`entry`（无入边）与 `exit`（跳到 `:eof`/末尾）。
- **循环检测**：回边（`target_index < source_index`）→ 自然循环；识别循环头/循环体区间。
- **多入口**：`incoming(key) > 1`（已有 `summarize_cfg.multi_entry_labels`）→ 该标签是**多入口块**。
- **支配关系**（可选，Stage 3 才需要）：判断某 goto 是否「有条件地穿越块边界」。

### 5.2.2 目标发射模型：标签分派状态机

**核心思想**：保留**块内结构化**（`if/for` 仍发 `if/fi`、`for/done`），但在**标签处切分**为
`case` 臂，用 `pc` 驱动任意跳转：

```bash
__bat2sh_pc=__bat2sh_start
while :; do
  case $__bat2sh_pc in
  __bat2sh_start)
      <从文件头到第一个标签的结构化代码>
      __bat2sh_pc=__L_1; continue ;;
  __L_1)   # :label1
      <从 :label1 到下一标签的结构化代码>
      __bat2sh_pc=__L_2; continue ;;
  __L_2)
      ...
      exit 0 ;;
  esac
done
```

- `goto Lx` → `__bat2sh_pc=__L_x; continue`（**分支 ② 的 `_label_line` 被分派臂取代**）。
- `goto :eof` → `exit 0`（函数内 `return`），沿用现状。
- **回边**（`backward_loop`）→ `pc=L; continue` 天然回到循环头。
- **块内 goto**（`in_block_goto`）：若 goto 在 `if` 块内 → `continue` 回到 `while` 分派，**语义正确**；
  若在 bash `for` 循环内 → 需 `continue 2`（或标志位 + `break`），**这是 Stage 3 的主要难点**。
- `label_in_block`：分派臂要求标签在**顶层**；块内标签须先**提升**（hoist）或**整文件扁平化**（Stage 3/4）。

> **诚实边界**：`label_in_block`（97/4）与「命令-块耦合」意味着**部分文件**须**整块扁平化**
> （每条语句一个状态、`if`/`for` 变为条件式 `pc` 赋值）。那是**编译器级**工作（路线图评 15–25 人日）。
> 本 session 的**务实目标** = 实现**标签分派状态机**并覆盖 `backward_loop` / 一般 `forward_skip` /
> 可表达的 `in_block_goto`；对**平坦化才能覆盖**的部分给**可执行诚实 TODO**（纪律 1/19）。

### 5.2.3 当前机制为什么做不到（对照）

| 目标能力 | 当前机制 | 状态机机制 |
| --- | --- | --- |
| 任意 goto | ❌ 仅 `:eof`/冗余/不可达区间 | ✅ `pc` 赋值 + `continue` |
| 回跳→循环 | ❌ 须标签处发 `while`（无图不知边界） | ✅ 回边 → `pc=L` |
| 多入口块 | ❌ 线序，标签只发注释 | ✅ 分派臂可从任意 pc 进入 |
| 循环检测 | ❌ 无 | ✅ 回边分析 |

## 5.3 重构策略（三选一或组合）

> **经验事实（本 session 只读探针，`/tmp/bat2sh-v250-probe2.py`，未入仓）**：
> 严格「可证安全子集」判据（顶层独立回跳 + 目标顶层标签 + 单入边 + 区间无标签）下
> `backward_loop` 候选 = **0**；`in_block_goto` = 181（`史上最牛X` 126、`系统优化` 52 …）。
> → **子集法无法覆盖目标形态；状态机是唯一路径。**

### A. 增量重构（在现有机制上扩展，保留 053 修复）

| 项 | 评估 |
| --- | --- |
| 内容 | 不加 `pc` 分派；只在 `_label_line`/`_convert_goto` 加「回跳→`while`」等**局部规则** |
| 成本 | 低（约 1 模块、百余行） |
| 风险 | 中（局部规则必须正确判定循环边界，易误判） |
| 053 回归可能 | **低–中**（只局部改 `_label_line` 分支 ②） |
| 回滚难度 | 低（单 commit revert） |
| **可覆盖形态** | 仅「单回跳、无穿越、区间无标签」——**实测 0 候选** → **不达成目标** |

### B. 双轨制（新 CFG 路径与旧机制并存，逐步迁移）—— **[本 session 采用]**

| 项 | 评估 |
| --- | --- |
| 内容 | 新增**独立** `CFG 分派发射器**（新模块 `core/cfg_state.py`）；由**严格门控**（eligibility）决定该文件走新路径还是旧路径。旧路径（含 `_label_line` + 块栈）对**不合格文件逐字节不变** |
| 成本 | 中–高（新模块 ~600–900 行 + 测试；门控 + 集成） |
| 风险 | 中（新路径须自证正确；由 wine oracle + 逐文件 diff 守护） |
| 053 回归可能 | **最低**（旧路径代码**零改动**；新路径仅在门控命中时生效）→ 天然满足「053 不回归」底线 |
| 回滚难度 | **最低**（关闭门控 = 完全回到 v2.4.0 行为；`git revert` 单 commit） |
| **可覆盖形态** | `backward_loop` / 一般 `forward_skip` / `redundant` / `eof_exit` / 可表达 `in_block_goto`；`label_in_block` 视平坦化成本决定（诚实 TODO 兜底） |

### C. 全量重写（重写块栈发射层）

| 项 | 评估 |
| --- | --- |
| 内容 | 用状态机**取代**整条 `_convert_logical`/`_label_line`/块栈发射 |
| 成本 | **高**（路线图 15–25 人日；编译器级：条件/循环变量/块全部扁平化） |
| 风险 | **最高**（静默错面最大；A1 块语义与扁平化根本张力） |
| 053 回归可能 | **高**（直接重写 053 所在函数） |
| 回滚难度 | 高（改动面大，跨多文件） |
| 可覆盖形态 | 理论全覆盖（含 `label_in_block`），但 **0 翻转收益**（纪律 1） |

### 裁定

**采用 B（双轨制）为主，A 作为 B 内的「增量收窄」**：
- 新建门控 CFG 分派发射路径；**不动**旧路径（053/A1 最强保护）。
- 先实现**可自证正确**的形态；`label_in_block`/平坦化依赖 → **可执行诚实 TODO**。
- **C 仅在 B 被证伪**（即 B 无法覆盖目标且 053 防护仍成立）时，作为**明确降级决策**再评估；
  触发「连续 2 次回归」时**强制退回 B**（§5.5）。

> 说明：B 与任务书「必须触碰 053 已修路径」的关系 —— B 通过**门控替换**（而非改写）触碰
> `_label_line`/块栈**行为面**：合格文件**不再经过** `_label_line` 分支 ②/①，改由分派臂处理；
> 这是「绕过式触碰」。相比改写函数体，它把 053 回归面压到**最小**，且**可一键回滚**。
