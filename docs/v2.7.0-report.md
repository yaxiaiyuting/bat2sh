### 2.1 着色优先级（最终语义）

```
--no-color（恒关） > --color（恒开） > NO_COLOR（关） > TERM=dumb/未设置（关）
                > FORCE_COLOR（管道强制开） > 自动检测 TTY
```

### 2.2 不变式

1. `color=False` 路径与 v2.6.0 **逐字节相同**（`_diag` = 原 `print(..., file=sys.stderr)`）。
2. **ANSI 只写 stderr**；stdout（`--print` 脚本 / `--report-json`）始终纯净。
3. `to_text()` / `report_blocks()` 结构零改动（GUI 共用 + `test_report_blocks_reconstructs_to_text`）。
4. 退出码语义零改动。

## 4. 偏离与如实披露（纪律 4 / 21 / 22）

1. **色彩基础设施已存在**（§1）：任务书假设「从零搭建」，实测为「补齐 + 扩展」。**不发明既有事实**。
2. **进度条 vs 进度指示**：单文件转换为瞬时操作，**per-byte 进度条不适用**；本版实现的是
   多文件批量 `[i/N]` 指示。**不硬造**无意义进度条。
3. **报告格式扩展方式**：为守住 GUI 共用与逐行等价不变量，选择**追加摘要行**而非重排结构。
4. **`--color` 为额外交付**：任务书仅要求 `--no-color`；对称提供 `--color`（恒开）以便管道/测试，
   属低风险增强，已在此披露。
5. **未着色保留项**：交互 prompt、`[dry-run]` 信息行、逐条选择/重试列表保持无色（避免污染
   管道语义），仅状态/诊断/摘要着色。
