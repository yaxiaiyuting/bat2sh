## 二、合并结果（含拓扑偏离披露）

### 2.1 合并命令与 commit

```text
git merge --no-ff session-b1b2 → 29fc7e3  (B1 名称映射 + B2 输出契约)
git merge --no-ff session-c4   → a239ae6  (C4 goto 控制流台账 + CI 修正)
git merge --no-ff session-lex  → 94b8855  (词法层残余额账)
```

### 2.2 冲突：**0**（且是构造性 0）

- **关键偏离（主动披露）**：三分支并非「各自从 `main` 并行分叉」，而是**累积/堆叠**：
  `main(7048e6c) → session-b1b2(7e645db) → session-c4(68dfbdd) → session-lex(37e3564)`。
  证据：`merge-base(main, 任一支) = 7048e6c`；`merge-base(b1b2,c4)=7e645db`；
  `merge-base(c4,lex)=68dfbdd`；`main...session-lex` = `0 18`（8+5+5）。
- 因此每支都是前一支的后代 → `--no-ff` **在构造上不可能产生文本冲突**。
  任务书「理论冲突 0，但必须核实」的结论**成立且更强**。
- 三支均改动的文件仅 `pyproject.toml`/`__init__.py`（version 行）与 `docs/PROJECT-OVERVIEW.md`，
  因线性堆叠而被后者自然覆盖，无冲突。`batch.py` **仅** b1b2 改动（c4/lex 未触碰）。
- 合并后树与 `session-lex` 树 **`git diff` 为空**（逐字节一致）。

详见 `docs/v1.10.0-merge-plan.md`（含逐支 commit 范围与预判冲突清单）。

| 检查 | 结果 |

| AUR RPC `info`/`search bat2sh` | `resultcount = 0` → **AUR 上不存在 `bat2sh` 包** |

| `~/.ssh/` | **无任何私钥**；`ssh aur@aur.archlinux.org` → `Permission denied (publickey)` |
| 历史做法 | 「`chore(pkg): sync PKGBUILD hashes`」commit 仅更新**仓库内** `PKGBUILD`/`.SRCINFO` |

**处置**：本版完成**仓库侧同步**（`pkgver=1.10.0` + tarball sha256 + `.SRCINFO` 重生成），

如需真正发布到 AUR，需：注册/授权 `bat2sh` AUR 包 + 本机配置 AUR SSH 私钥，再 `git push` AUR remote。
**该项不阻塞 tag/Release**，如实记录为「仓库已同步 / AUR push 待凭据」。

## 六、1.x 收尾评估结论（**继续 / 未达成**）

> 完整论证见 **`docs/v1.10.0-1x-closure.md`**（本次核心产出）。

| 收尾条件 | 判定 | 依据 |
| :--- | :--- | :--- |
| (a) 所有剩余失败有明确归属 | **不成立** | 46 个「全 L1/L2」文件中的 L2 非 `sc`/非第三方部分（**C2**）**无归属**（路线图 §2.1 归 v1.9.4、§3.4 「文件翻转主力批」，从未执行） |
| (b) 无「可修而未修」 | **不成立** | C2 小设施批 `for`(10)/`registry`(11)/`other`(15) = **36 单设施翻转（严格子集 21）**未做；不需 CFG、不触块栈核心、不触 A1 热路径 |
| (c) 指标稳定且 1.x 无提升空间 | 前半成立、后半**不成立** | 稳定（自 v1.9.0 恒为 102/16/86/894）；但路线图 §4 标准 3 要求 `degraded ≤ 41`，当前 **86** |

- **不满足路线图 §4「接近完美」6 条验收**：标准 1（语法 ≥150）当前 147；标准 3 当前 86。
- **v1.10.0 的准确定性 = 1.x 功能冻结版（feature freeze）**，**不是**「1.x 完成」。
  ⚠️ 发布说明 `docs/releases/v1.10.0.md` 早期草案曾写「不存在可修但未修」，经核**已更正**。
- 归属明确项：goto（~250 TODO）/ `sc`（169）→ **v2.0**；`regsvr32`/COM、第三方 exe、L4 对象、
  B 类源畸形、ENV/S 类 → **终态**；LF-1/2/3、B2 解析级、062/A9 → **2.x**。

### 6.1 待裁定（1.x 延续 vs 改挂 2.x）

C2 是**1.x 可做项**，建议二选一并记录理由：
1. 作为 **1.x 延续版（v1.10.1 / v1.11）** 执行（路线图原定 v1.9.4，目标 46 翻转 / 保守 21）；或
2. 经**显式裁定**改挂 2.x「命令映射扩展」——**不得静默算作 2.x**。

### 6.2 2.x 范围与启动条件（可证伪触发器）

## 七、已知限制

1. **1.x 未收尾**：C2 小设施批（~77 TODO / 36 单设施翻转）可修而未修（§六）。
2. **AUR 远端未发布**：仓库侧已同步，AUR 无包/无凭据（§五）。
3. 本版**零转换改动**：指标与 `v1.10.0rc1` 逐字节持平——价值在基础设施 + 台账固化，**不宣称提升**。
4. goto 无语义转换（仅 `goto :eof`）；无解析级输出适配（1.x 红线）；PS 仍为实验性高级草稿。
5. 四个只读子系统均 `integrated=False`，不驱动转换。
