## 2. 判定 1.x 是否收尾

`docs/releases/v1.10.0.md` §4 已单方面声明「所有剩余失败均有明确归属，不存在可修但未修」。
**本文件的独立判定与之不符**，三条收尾条件逐条如下：

| 条件 | 判定 | 依据 |
| :--- | :--- | :--- |
| **(a) 所有剩余失败有明确归属（v2.0/终态）** | **不成立** | L1/L2 文件（14+32=46）中的 L2 非 `sc`/非第三方部分（for/registry/other/office/attrib/单命令/start/管道 ~77 TODO）**无 v2.0 归属，也无终态标注**；路线图 §2.1 原定 **v1.9.4**、§3.4 定为「文件翻转主力批」。`session-c4-coldstart.md` §前提3 明记 46/40 仍成立 |
| **(b) 无「可修但未修」的项** | **不成立** | 同 (a)：可做设施 {`for`,`registry`,`other`,`errorlevel`,`path`,`office`,`attrib`} 中，仅 `errorlevel` 于 v1.9.2 归零；`for`(10)/`registry`(11)/`other`(15) 的单设施翻转 **36 个（严格子集 21）**从未执行（路线图 §3.4） |
| **(c) rc==0/degraded 数字稳定、1.x 无提升空间** | **前半成立，后半不成立** | 稳定：102/16/86/894、崩溃 0，自 v1.9.0 未变；但**提升空间存在**——路线图 §3.4 记 1.x 可达 **46 翻转**、理论下界 **40**；路线图 §4 标准 3 要求 `degraded ≤ 41`，当前 **86** |

**结论**：**1.x 未满足自身路线图的收尾标准，不能宣布「1.x 完成」**（MUST NOT：文档中存在可修未修项）。
v1.10.0 的准确定性是「**1.x 基础设施收口 / 功能冻结版**」，而非「1.x 完成」。

## 3. 收尾判定、2.x 范围与启动条件

### 3.1 判定

**不宣布「1.x 完成」。** 若必须给 v1.10.0 一个终点定性：它是 **1.x 功能冻结（feature freeze）版**
——除 C2（§4）外不再向 1.x 增加转换能力，但不满足路线图 §4 的 6 条「接近完美」标准
（标准 3 差距最大：degraded 86 vs ≤41；标准 2 的 A1 已于 v1.9.2 达标）。

| :--- | :--- | :--- |

## 5. 不确定性与偏离披露

1. **degraded TODO 口径差异**：路线图 §0.1.1 记 **913**，本文件与发布说明采用合并后实测 **894**
   （`v1.10.0.md` §2）；`v1.9.1-attribution.md` §0.3 记 913–914。三者系**仪器/口径差**（阶段不同、
   对「degraded 文件内 TODO」的边界不同），文档**未做对账**，已如实并列。
2. **1.x 下界三口径**：路线图 §3.4 给 46/40（主）、45/41（含 A10 的 075）、**21**（严格子集，排除
   异构 `other`）。收尾判定的严格程度取决于采哪一口径；即便取最宽松的 46，当前 0 翻转仍不达标。
3. **goto 阻塞文件数**：路线图 §3.4 记 16，`session-c4-coldstart.md` §前提3 实测 22（混合设施口径差），
   不影响 goto 翻转 ≈2 的结论。
4. **未重跑语料**：本文件按任务约束未运行 corpus/bwrap，§1/§4 的设施 ROI 引用路线图 §3.4 的
   v1.9.0 期 `measure.json`；v1.9.2 归零 L1 后 46 个文件的构成**未重新分类**（可能下移，不会上移）。
5. **发布说明与本文不一致**：`docs/releases/v1.10.0.md` §4 声称「不存在可修但未修」，与本文 §2
   冲突。**以本文为准**（本文给出反例与出处）；建议发布说明据本文更正为「功能冻结」。
