**版本序列建议（拆三版，非一次做完）**：

```text
v2.0.0  解析层/词法层硬化（前置基座）── 关闭 4 个语法失败中的 3 个 + LF-1 块栈失同步
v2.1.0  CFG 数据模型 + goto 简单形态语义转换（redundant / 顶层 forward_skip）

```

**关键前置判断**：`CFG 图 ⊂ 解析层基座`。没有正确的括号/引号/块平衡，任何 goto 边分析都建立在错误块结构上 → **解析层必须先做**。

**是否允许破坏性变更**：**允许「修正错误语义」的产物变化**（语法失败文件、LF-1、goto 文件），
**禁止**「把当前可跑脚本降级」的变化（例：盘符/UNC 诚实 TODO 化 → strict −6）与 **CLI/API 破坏**。

## 3. 关键决策点回答

### 3.1 CFG 和 goto 是一件事还是两件？

**一件工作流、两个层次**：
- **CFG 图**（标签表 + goto 边）＝ goto 专属，**不是**独立设施 → 归 A；
- **解析层/词法层基座**＝ 独立设施（服务 goto 各形态 + 3 例语法失败 + LF-1 + B5）→ 单列，且**必须先于 CFG**。

因此任务书「方向 C」的正确形态不是「又一个 CFG 项」，而是 **v2.0.0 的解析层基座**。

### 3.2 2.0 是一次做完三项，还是拆 2.0/2.1/2.2？

**必须拆。** 理由（三条，均为实测/文档证据）：

1. **体量**：仅 goto 一项即 **15–25 人日**（路线图 §1.C4），远超单 session 上下文预算；含解析层前置为 **20–32 人日**。
2. **前置关系**：CFG 依赖解析层（§2.C）；`sc` 宿主与 goto 宿主重叠（`135`）。存在**真实串行依赖**，不能并行「一次做完」。
3. **需求驱动门槛**：1.x 收尾已把 2.x 启动改为 **T1/T2/T3 触发制**（`v1.11.0-1x-closure-final.md` §6）。
   版本序列应是**触发后的执行顺序**，而非无条件排期。

### 3.3 是否允许破坏性变更？破坏什么？

**允许「修正错误语义」，禁止「指标倒退」与「接口破坏」。**

| 类别 | 判定 | 具体 |
| :--- | :--- | :--- |
| 修正错误语义的产物变化 | **允许** | 3 例语法失败产物、LF-1 的 044/135、goto 受影响文件、sc 的 169 行。这些是**修复**，非破坏 |
| examples tracked 对 | **允许有审查地重基线** | 2.x 语义修复必然改 examples；须逐对评审后重录（不适用 1.x「零漂移」硬门，改「逐对评审」） |
| 把可跑脚本降级（strict 下降） | **禁止** | 例：盘符/UNC 诚实 TODO 化 → strict −6（`session-b1b2` §三）→ **不做** |
| CLI / API / 配置格式 | **禁止破坏** | `--fail-on-todo`、`ConvertSettings`、`api/*`、`gui` 接口保持不变；新增能力须向后兼容 |
| 静默错 | **禁止引入** | 任一修复若把「TODO（安全）」降级为「看似对的错译」→ 停下（纪律 1/13） |

### 3.4 三项的执行顺序 / 依赖关系？

```text
[C 基座] 解析层/词法层（v2.0.0）
   ├──► LF-1（for 头平衡）           ── 直接闭环
   ├──► 3 例语法失败                  ── 直接闭环
   └──► [A] CFG 图 + goto 语义转换（v2.1.0 → v2.2.0）
            └──► [B] sc→systemctl / 服务表（v2.2.0，宿主重叠；本身不依赖 CFG）
注册表写（L4，独立）── 随 v2.2.0（无前置，但语义近似风险高）
```

**关键路径**：`C 基座 → A(CFG) → A(高级形态)`。`B(sc)` 与 `注册表写` 可旁挂，但**收益受 goto 阻塞**（宿主重叠）。

### 3.5 每项独立 session 可行吗？

| 项 | 单 session 可行？ | 拆分建议 |
| :--- | :--- | :--- |
| C 基座（解析层） | **否**（≥3 个独立机制） | S1 引号/转义态词法；S2 `for` 头平衡括号（LF-1）；S3 语法失败①（降级行配平） |
| A goto | **否**（15–25 人日） | S4 CFG 只读数据模型；S5 redundant+顶层 forward pilot；S6 回跳→循环；S7 块内 goto |
| B sc | **是**（受限于 4–6 人日估） | 1 个 session（名称服务表 + 动词映射 + 诚实 TODO） |

## 5. 破坏性变更声明（条款化）

1. **产物语义变更（允许，须评审）**：v2.0.0–v2.2.0 会改变**受影响文件**的生成脚本；
   变更必须满足「修的是错」且经 wine 黄金对照/最小复现确认。examples tracked 对**逐对评审后重基线**。
2. **指标不可倒退（硬门）**：`strict` 不得因「诚实 TODO 化」而下降（盘符/UNC 集成 = −6 → **明确不做**）；
   `degraded` 不得上升；崩溃/超时保持 0。
3. **接口冻结（硬门）**：CLI 参数、`ConvertSettings`、`core/api/*`、GUI 调用保持不变；新增能力必须向后兼容。
4. **报告契约**：新增诊断类别须沿用 `Diagnostic(category, message, original, line)`；`--fail-on-todo` 语义不变。
5. **静默错零容忍**：任何把「安全 TODO」换成「未验证的映射」的改动 = 破坏性缺陷，回滚即停。
6. **不引入新硬依赖**：不得要求外部 Windows 组件/wine 才能转换（wine 仅作测试 oracle）。

## 6. 风险评估与止损

| 项 | 翻车方式 | 概率 | 影响 | 止损 / 前置 |
| :--- | :--- | :--- | :--- | :--- |
| **goto CFG** | 控制流重构回归 `%%i`/块栈（v1.8.1 同域事故） | **高** | **高（静默）** | 强制分 phase；B3 黄金对照 + 最小复现 + churn 上限；任一回滚即 Phase 2C 停下上报（不 shotgun） |
| **解析层（for 头）** | 改 `for` 咽喉正则 → 大面积产物漂移 | 中–高 | 高 | **仅当粗匹配已误切时才回退平衡扫描**（收窄到 4 文件）；churn ≤10 文件 |
| **解析层（引号/转义态）** | 触 `_expand_vars`（A1 热路径）→ 静默错 | 中 | 高 | 2.0 只做**引号态标注的最小闭环**；LF-2（守卫 quote-aware）**明确留 backlog** |
| **sc→systemctl** | 服务名映射错 → 「看似对」的 systemctl | 中 | 中 | 只映射**有 evidence 的**服务名；93 个 Windows 专有服务名**一律诚实 TODO** |
| **registry 写** | 语义近似（配置文件映射）看似对 | **高** | 中 | 逐键规则 + 每条 evidence；不可证近似的一律诚实 TODO；**可考虑永久终态** |
| **CFG 只读阶段** | 读者误以为已实现转换 | 低 | 低 | 明确 `integrated=False` 语义 + 文档标注 |
| **整体** | 为数字激进映射 | 低 | 高 | 纪律 1/7：缺 evidence 拒绝；翻转如实记录 |

**全局止损原则**（沿用）：每 commit 全量 pytest 无回退；崩溃 0；静默错 0；缺 evidence 拒绝；
**任一修复出现回滚 → 停下上报，不 shotgun**。

**最可能翻车项**：**goto CFG（2.1/2.2）** 与 **registry 写（2.2）**。前者影响面最大（块栈同域），
后者最易违反「不发明映射」。**止损点**：CFG 试点若 churn >10 文件或出现 1 例静默错 → 立即停并上报。
