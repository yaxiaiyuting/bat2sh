## 1. A1 目标与语义锚定

### 1.1 缺陷

bat 的 `%VAR%` 在**块解析时冻结一次**（读入整条块命令即展开），`!VAR!` 在**执行时取值**。
bat2sh 把两者都译成运行时活引用 `${VAR}` → `%VAR%` 的冻结语义丢失（**静默错**：跑通、行为错）。

### 1.2 wine 语义锚定（本会话实测，纪律 9）

| 用例 | 构造 | wine cmd（正确） | bat2sh（当前） | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| b1 | 多行 `for` 体 `set v=2 & echo %v%` | `i=1 i=1` | `i=2 i=2` | ❌ 缺陷 |
| b2 | **嵌套** `for`+`if` 体 | `n=1 n=1` | `n=2 n=2` | ❌ 缺陷（冻结于**最外层**块入口） |
| b3 | 单行 `if ( … )` | `x=1` | `x=2` | ❌ 缺陷 |
| b4 | 块外逐行 `set v=1`/`set v=2`/`echo %v%` | `t=2` | `t=2` | ✅ 活引用**正确**（逐行独立解析） |
| b5 | 块内引用但块内不赋值 | `s=9 s=9` | `s=9 s=9` | ✅ 无需快照 |
| b6 | 块内 `!v!` 延迟展开 | `d=2` | `d=2` | ✅ **不动** |

**结论**：冻结时机 = **最外层块入口**；块外引用保持活引用；`!VAR!` 不变。

### 2.2 机制：占位符 + marker + 合成期解析

避免「发射时未知未来赋值」的困难：**引用处只记占位，判定推迟到 `_compose`**。

1. **数据结构**（`_Block` 增字段）
   - `a1_refs: list[str]`：该块作为**最外层**时被引用的用户变量（去重、保序）。
   - `a1_assigns: set[str]`：该块作为最外层时被赋值的变量（`set`/`set /a`/`set /p`）。
   - `a1_marker_id: int | None`：该块头部前的 marker 行 id。
2. **引用改写**（`_expand_vars` 的 `env_repl`，仅用户变量分支）
   - 条件：`self._stack` 非空，且名字非 `BATCH_ENV_MAP`/`ERRORLEVEL`/`DATE`/`TIME`。
   - 产出占位符 `\x00A1:<blockid>:<sanitized>\x00`，并把 `<sanitized>` 记入 `self._stack[0].a1_refs`。
   - `!VAR!` 分支（`:975-1023`）**完全不动**。
3. **赋值登记**（`_register_assigned`）
   - `self._stack` 非空时，把名字追加到 `self._stack[0].a1_assigns`。
4. **marker 行**（块头发射点，见 §2.4）
   - 每个块头**前**插一行 `self._c("\x00B1:<id>\x00")`。
5. **合成期解析**（`_compose` 末尾，`_guard_unset_variable_refs` 之前）
   - marker 行：`needed = [v for v in block.a1_refs if v in block.a1_assigns]`
     - `needed` 非空 → 替换为快照赋值行 `<indent>__bat2sh_snap_<v>="${<v>}"`（按 `needed` 顺序，去重）。
     - 否则 → **整行删除**（净零输出，无 churn）。
   - 占位符：`needed` 含该 var → `${__bat2sh_snap_<v>}`；否则 → `${<v>}`（还原活引用）。
   - **安全兜底**：若块有 `needed` 但 `a1_marker_id is None`（未挂 marker）→ 视为 `needed=[]`，
     全部还原为 `${<v>}`，**绝不产出未定义变量**（`set -u` 安全）。
6. **命名**：快照变量 `__bat2sh_snap_<sanitized>`（沿用 `__bat2sh_*` 前缀，避免撞用户命名空间）。
7. **unset 安全**：快照行 `__bat2sh_snap_v="${v}"` 会被既有 `_guard_unset_variable_refs`
   （`batch.py:670`）按「引用点之前是否赋值」加 `:-`；`v` 仅在块内赋值时 → `${v:-}`（= 空，
   与 cmd 语义一致）。

### 2.3 为什么不用「上界」方案（S1）

S1（所有块内引用一律快照）实现更简单，但 churn 23 文件/17 测试，且 `deploy.sh`/`stress_test.sh`
会漂移、需刷新 examples；S2 以「赋值交集」精确判定，churn 降到 7 文件/4 测试且 examples 零漂移，
符合纪律 1（保守）与验收 #8（examples 零字节漂移）。

### 2.5 范围与已知限制（保守，纪律 1）

- **覆盖**：`for` / `for /f` / `if` / `else` 块（= 实测精确集合的全部块类型）。
- **backlog（不在本版）**：
  - **顶层独立 `( … )` group 块**（`_convert_paren_block` 的 `close >= 0` 路径不 push 块）；
  - **`call` 引起的二次解析/再展开**（cmd 的 `call` 会重新解析，`%VAR%` 会再次展开）；
  - 块内变量被**动态名**（`set s!w!=`）赋值（已由既有诚实 TODO 覆盖）。

### 2.6 为何 group 块不挂 marker（实现期发现的约束）

`_convert_group_tail`（`batch.py:1547/1557`）用 `len(rhs) != 1` 判定「尾部命令是否单行」，
`_convert_paren_block`（`:1520-1521`）用 `len(inner) == len(parts)` + 首字符非 `#` 判定单行。
**marker 是独立行，会把 `len(rhs)` 由 1 变 2**，导致 `&& (` 这类尾部被误判为非单行 → 整行降级 TODO
（实测回归：`文件备份器/文件备份器V2.3修改版2.cmd` 语法失败）。

→ **group 块不挂 marker**：其内部引用回退为活引用（`env_repl` 见 `a1_marker_id is None` 即返回 `${v}`），
与 §2.5 backlog 一致。if/for 的 marker 挂在其**头部行之前**，不进入 `_convert_group_tail` 的单行 rhs
（尾部以 if/for 开头且挂 marker 的构造在本版语料中不存在；若未来出现，该尾部会保守降级 TODO，非静默错）。

## 3. 风险 1 专项：最外层块身份在 else 体处理期间保持

### 3.1 风险描述（churn 计量阶段标记）

`_convert_if` 内联 `else` 路径曾疑似在 else 体处理前 `pop` 掉 if 块，导致 else 体引用
注册到错误（或空）的最外层块 → else 体漏快照（影响 `文件归类整理器.bat` 的 11 处 `else`）。

### 3.2 逐路径核验（只读，本会话）

| 路径 | 行 | pop 与 body 顺序 | 判定 |
| :--- | :--- | :--- | :--- |
| 内联 else（`if (A) else (B)`，同逻辑行） | `:1698-1719` | body 于 `:1714` 转换，`pop` 于 `:1717`（**之后**） | ✅ 安全 |
| 内联 `else if` | `:1694-1697` | `pop` 于 `:1695`，随后递归 `_convert_if` 新建块 | ⚠️ 见 §3.3 |
| 跨行 `) else (` | `:1341-1366` | 先 `pop` 旧块（`:1342`），再 push 新 else 块（`:1355/1369`）后转换 body | ⚠️ 见 §3.3 |
| `if (A` 跨行 | `:1672-1683` | push 后转换 body | ✅ 安全 |

### 3.3 处理

- 内联 else（唯一在实测精确集合中的路径）：**无需改动**，`:1717` 的既有顺序即正确；加**专项测试**锁定。
- `else if` / `) else (`：else（或 else-if）被当作**独立最外层块**，在其入口取快照。
  由于 if 与 else 分支**互斥执行**且其间无顶层赋值，else 入口值与整个 if 语句入口值**相等**
  → 语义等价，**无需额外处理**；加专项测试锁定。
- **兜底**：§2.2 第 5 条的「无 marker → 还原活引用」保证任何未覆盖路径都不会产出未定义变量。

## 4. 函数体输出通道覆盖方案

`BatchConverter` 有两条输出通道：`self._out`（主流程）与 `self._func_out`（`:label` 函数体，
由 `_convert_logical:587` 按 `_function_mode` 选择）。方案：

1. **注册统一**：`env_repl` 登记到 `self._stack[0]`、`_register_assigned` 同理 —— 与所在通道无关。
2. **marker/占位符统一**：marker 行与占位符随行进入所在通道（`_out` 或 `_func_out`）。
3. **解析统一在 `_compose`**：`_compose:869-874` 依次拼接 `_func_out` → body，**在拼接后的整段文本上**
   一次性解析 marker 与占位符 → **两条通道天然覆盖**，无需分支。
4. **两遍转换**：`convert:549-556` 的 probe pass（为 `call` 目标探测）使用独立实例，
   其 marker/占位符不进入最终文本（probe 仅取 `_functions`）。
5. **专项测试**：`:label` 函数体内 `for` + `%VAR%` 断言快照出现在函数体内（而非主流程）。

## 5. `call` 重解析 —— 记为 backlog

cmd 的 `call :label`/`call set` 会**重新解析**目标文本，`%VAR%` 在 call 时**再次展开**，
与「块解析时冻结」是不同机制。本版**不处理**：

- 现状：`call` 相关变量语义已有既有处理（`_call_targets`/函数化）；`call set` 间接引用走诚实 TODO
  （`indirect_repl`，`:890-897`）。
- 记录：**backlog（2.x）**，在路线图 §2.2 的 2.x 组中登记；本版不引入 `call` 再展开建模。
