## 二、用自己的话复述

### 2.1 完整 CFG 状态机是什么

cmd 的 `goto` 是**任意跳转**：前跳、回跳、跳出/跳入控制块、动态目标。bash 是**结构化**语言
（`if/fi`、`for/done`、函数、`break/continue`），**没有「跳到任意行」的原语**。
因此把 goto 译对，本质是先重建**控制流图（CFG）**——标签在哪、每条 goto 指向哪、方向、
是否块内、被几处跳入、跳过哪些行——再**按图决策**。

「**完整 CFG 状态机**」= 不再逐行就地发射，而是把整段脚本视为**状态机**：每个标签/基本块是一个
状态，`goto` 是状态转移，用**顶层 PC 分派**（如 `while :; do case $pc in …) …;; esac; done`）
实现任意跳转。它能覆盖全部 goto 形态（`backward_loop` / `in_block_goto` / 一般 `forward_skip` /
`label_in_block`），代价是**放弃结构化产物**、产物结构大范围变化、且与 A1 块语义（最外层块入口
冻结）存在根本张力。它是「语义完整」路线，不是「翻转数」路线（实测翻转 0，见 §3.4）。

现状：`core/control_flow.py`（C4 台账）+ `core/cfg.py`（v2.1.0 只读数据模型：标签表 + goto 边）
已就位，但 **`integrated=False`，都不驱动转换**。唯一已实现的 goto 语义 = `goto :eof`
（→ `exit 0`/`return`）+ v2.4.0 的两个可证安全子集（`redundant_goto` no-op、`forward_skip`
不可达区间注释化）。

### 2.2 053 修复的具体代码路径（精读 `_label_line`）

053 = 语料 `将所在目录的BAT文件合并成一个BAT文件，通过 选择 运行其中之一.bat`：`for /f` +
行尾未配平 `else (` 使**块栈失同步** → `%%i` 逸出循环 → `cat %i`。v1.9.0 以 **5 处 hunk**
（纯块栈发射层，不动词法层）修复。在当前起点 HEAD `5bdd448` 的落点（行号已随 v2.4.0 漂移）：

| # | 函数/结构 | 当前行 | 053 相关改动 |
| --- | --- | --- | --- |
| 1 | `_Block`（dataclass） | `batch.py:488-500` | `finish_parent: bool = False`（`:496`） |
| 2 | `_pop_block` | `:1467-1500` | `while block.finish_parent and self._stack:` 链式收尾父块（`:1485-1499`） |
| 3 | `_close_block_line` | `:1502-1561` | `rest.startswith(")")` → **递归**闭合（`:1558-1560`，支持 `))`）；`else (` 跨行分支 `:1529-1553` |
| 4 | `_convert_if`（行内未配平 `else (`） | `:1911-1923` | `close2 < 0` → pop if、push `await_paren_close` else 块 |
| 5 | `_convert_for`（body 后继） | `:2221-2313` | 栈顶非本块时 `stack[i+1].finish_parent = True`，不再无条件 pop |
| 5b | `_emit_for_f` | `:2407-…` | 同 5（for /f 版本） |
| 5c | `_emit_for_r` | `:2313-2407` | 同 5（for /r 版本） |

**`_label_line`（`:1692-1724`）是 053 的邻近路径，也是本 session 的核心改动面**。当前行为：

1. **`if self._stack:`**（标签在控制块内）→ `_error_block_line(...)` **响亮拒绝**
   （`control_flow`，bat 危险写法）。—— `label_in_block` 形态的现处置。
2. `key in self._goto_targets and key not in self._call_targets` → **主流程继续**
   （发注释 `# :name（goto 目标，不函数化，主流程继续）`），即 goto 目标**不函数化**。
3. 未使用标签 + 非函数模式 → 注释。
4. 否则（`call :label` 目标）→ 函数化（`label_xxx() {`），并把 `_current_func` 切到 `_func_out`。

关键：`_label_line` 目前**只会发射注释或函数头**，**不会发射 `while`/`case` 等控制原语**；
它依赖 `self._stack` 为空这一**「标签必在顶层」假设**。完整 CFG 要求标签能成为**循环/分派的入口**，
必然要在此处（或一条取代它的新发射路径）发射控制原语并 push/pop 块栈 —— 这正是 053 同域。

### 2.3 v2.4.0 的近失静默错是怎么被捕获的

Stage B 初版用 **ASCII 标签正则**判定「前向跳转区间内是否有标签」。语料
`104 瑞星杀毒软件2008批处理版.bat` 的区间含 **CJK 标签 `:退出`**，源中
`if "%s%"=="6" goto 退出` 会跳入该区间。初版漏判 CJK → 误判不可达 → **注释掉可达代码**
（静默错：无 TODO、`bash -n` 通过、行为错）。

**捕获链**：`measure` 的**逐文件产物字节 diff** 发现 104 产物意外变化 → 立即改为宽松标签判据
`_LABEL_LIKE_RE`（含 CJK：区间内**只要有标签样行即拒绝转换**）→ 104 恢复零变化。
新增保守边界测试 `test_reachable_label_inside_region_blocks_conversion` /
`test_call_target_inside_region_blocks_conversion`。

→ **教训**：静默错**不会**被 `bash -n` 或 TODO 扫描捕获；必须靠**逐文件产物 diff + wine oracle**
两道防线。本 session 全程沿用。

## 五、差距分析（v2.4.0 未做完整 CFG，现在要做的差距）

| 维度 | v2.4.0 现状 | 完整 CFG 状态机需要 | 差距 |
| --- | --- | --- | --- |
| 发射模型 | **逐行就地发射**（`_convert_logical` → `_out`/`_func_out`） | 全局 CFG 分析 → 状态机分派 | 根本性重构 |
| 标签 | `_label_line` 只发注释/函数头；**块内标签拒绝** | 标签 = 分派入口（可有多入口） | 触 `_label_line`（053 邻域） |
| goto | 仅 `:eof` + 两可证子集；其余 TODO | 任意跳转 → 状态转移 | 触块栈发射层 |
| 循环 | bash `for/done` 结构化循环 | goto 回边 → 循环/分派 | 无图遍历/循环检测 |
| 块 | 线序 push/pop（`_stack`） | 多入口/多出口基本块 | 栈同步假设 vs 图结构 |

### 4.1 是否真的需要触碰 `_label_line`？有没有绕过路径？

**结论：要真实实现 goto 语义，无法绕过 `_label_line` / 块栈发射层。** 三条可能路径均触其邻域：

1. **回跳→循环**（`backward_loop`）：须在**标签处**发射 `while`/循环入口 → 必改 `_label_line`。
2. **块内 goto→break/continue**（`in_block_goto`）：须在 goto 处改块栈发射（`break` 只对循环有效，
   `if` 块须特殊处理）。
3. **顶层 PC 分派状态机**：须**取代**整条发射路径（含 `_label_line`），改动面更大。
4. **唯一「不触」路径**是继续 v2.4.0 的**只读注释化子集**——但那只覆盖可证不可达区间，**不满足**
   「完整 CFG 状态机」目标，即任务书 §五 的「诚实 TODO」退路。

→ 本 session **必须**触碰 053 已修路径的**邻域**（`_label_line` + 块栈发射层），这正是最高风险所在。
