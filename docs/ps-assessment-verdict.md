## 3. 为什么不是「部分解冻」或「解冻」

### 3.1 为什么不是「解冻」

- 根本障碍（对象模型等）**未绕过**；无真实需求。**直接违反**解冻定义（§5.1）。

### 3.2 为什么不是「部分解冻」

任务书 §5.1 把「部分解冻」举为「对象模型的**读类**」——即**语义方向**的受限子集。但：

1. **对象读类不可验证**：无 pwsh，无法证明「近似」与 PS 行为一致；正是「看起来对、实际错」
   的高风险区（纪律 1/7）。
2. **A 类语法修复不是「方向」**：114 个发射缺陷是**既有功能的工程质量修复**（把「整文件降级」
   变成「正确或诚实 TODO」），**不改变语义上限**（strict 仍 0）。它更像**维护期缺陷修复**，
   而非「解冻出新能力」。
3. **需求缺失**：部分解冻仍需触发条件（T1/T3）才能启动。

> 因此：**A 类修复登记为「触发后的首选子集」**（§5），但**本 session 不激活**，判定仍为**继续冻结**。
