# bat2sh v1.7.0 设计说明 —— C 阶段：TODO 多选并行修复

本文是 v1.7.0（C 阶段）的实现契约。所有实现（`core/api`、`cli`、`gui`、测试）以本文件的
接口签名与不变量为准；实现与本文件冲突时，以本文件为裁决依据，或先改本文件再改代码。

背景（用户核心痛点）：开启 `enable_thinking` 后单条 TODO 修复实测约 214 秒，多条 TODO 串行
不可接受。本轮把 `--fix-todos` 从"逐条串行"改造为"多选并行"，同时保持项目纪律
（保守 TODO 优于激进转换、绝不产出未通过 `bash -n` 的脚本、不自动写盘、AI 建议必须人工确认）。

---

## 1. 现状（只读诊断结论）

| 层 | 位置 | 行为 |
| :--- | :--- | :--- |
| CLI | `cli.py::_fix_todos_flow` | 逐个 marker：每条隐私提示 → 流式接收 → 单条 `bash -n` → 单条 diff+确认 → 就地 `current_text`/`offset` 更新；全部结束一次性写盘 |
| GUI | `gui/dialogs.py::TodoFixDialog` + `TodoFixWorker(QThread)` | 同上，一次一个 QThread，`_offset` 累积，accept 后写回编辑器 |
| 纯函数 | `core/api/fixer.py` | `scan_todo_markers` / `build_prompt` / `clean_completion` / `apply_replacement` / `replacement_line_count` / `render_diff` |
| Provider | `core/api/provider.py` | `complete_stream`：SSE 流式，socket timeout = **两次数据间空闲超时**（默认 30s），每次调用独立连接 |
| 配置 | `core/api/config.py` | `ApiConfig` 存 `~/.config/bat2sh/api.json`；`resolve_api_config` 逐字段 CLI > env > file |

关键结论：`provider.complete_stream` 是同步生成器且每次调用独立连接，**线程池并发不需要改动
流式层**，chunk 间隔 30s 空闲超时语义原样保留。

## 2. 目标与非目标

### 2.1 目标
1. 并发数默认 **3**，可配置（CLI > env > file）。
2. 429：**指数退避 + 主动降并发**（下限 1、上限 ≤ 初始并发）。
3. 隐私提示**合并为一次**："发送 N 条到 {url}？"。
4. CLI + GUI 聚合面板：每条 TODO 一行状态（`pending / running / done / failed / skipped`），实时刷新。
5. 全部收完 → **聚合 diff** → **从后往前应用** → 用户确认 → 一次性写盘。
6. 错误隔离：一条失败不阻塞其它；失败条目单独列出，可重试。
7. `[REG]` 标记语义在 `--help` 与文档中说明。

### 2.2 非目标（明确不做）
- 不改转换管线（`core/batch.py` / `core/powershell.py`），故 examples / 真实语料转换结果**零变化**。
- 不引入第三方并发/HTTP 依赖（stdlib only）。
- 不自动写盘、不提供"全部同意"绕过隐私确认（延续 v1.5 决策）。
- 不做"记忆隐私确认"。

## 3. 并发模型（决策 D1：线程池 + 可收缩限流器）

选择**线程池**而非 asyncio，理由：
- `provider.complete_stream` 是同步生成器，底层 `urllib.request` 阻塞；asyncio 需要把整条流式路径
  重写为 async，风险高、与"不破坏流式层"冲突。
- 线程模型下每个任务持有独立 socket，空闲超时语义天然保留。
- GUI 侧本就用 `QThread` 跑后台调用，线程模型与之同构。

**并发控制**：`_AdaptiveLimiter`（`threading.Condition` 实现），而非 `ThreadPoolExecutor`：
- `ThreadPoolExecutor` 无法安全收缩工作线程数；429 需要**动态降并发**。
- 限流器维护 `limit`（当前上限）与 `inflight`；`acquire()` 在 `inflight >= limit` 时等待。
- `shrink()` 只降低 `limit`（`limit = max(1, limit - 1)`），**不打断在途请求**，仅节流后续派发。
- 上限恒为初始并发数（只降不升）——最保守选择；避免抖动放大限流。
- 工作线程数 = 初始并发数；每个线程循环 `acquire() → 取任务 → 执行 → release()`。

**任务冻结**：并行模式下所有 prompt 都基于**同一份原始 `current_text`** 构造，
`out_line` 在扫描时冻结，**不存在顺序处理的行号漂移**（`offset` 概念在并行路径中被移除）。
合并阶段统一处理行号（见 §5）。

## 4. 429 自适应（决策 D2）

两层处理，最保守：

1. **Provider 层可观测**：`OpenAICompatibleProvider.complete_stream` 新增可选参数
   `on_rate_limit: Callable[[int], None] | None = None`，**每次收到 429 时**（在内置退避 sleep
   之前）以当前尝试序号回调。默认 `None` → 行为与 v1.6 完全一致（向后兼容）。
   - Provider 内置退避（`1.0 * 2**attempts`）保持不变，即**指数退避**本体。
   - `on_rate_limit` 让编排层在"端点瞬时 429 后被 provider 重试成功"的情况下也能感知并降并发。
2. **编排层响应**：`rate_limit_cb` →
   - `limiter.shrink()`（下限 1、上限初始并发）；
   - 记录 `FixTask.rate_limit_hits` 与全局 `rate_limit_hits`；
   - 发出事件 `running`，`detail="限流 429：降低并发至 N"`。
3. **编排层重试**：若 429 最终以 `ProviderRateLimitError` 冒泡（provider 重试耗尽），编排层
   - `sleep(min(backoff_cap, backoff_base * 2**consecutive_hits) * jitter())`，然后**重新入队**该任务；
   - `FixTask.retries` 超过 `rate_limit_retries`（默认 2）→ 标记 `failed`（限流），不阻塞其它任务。
   - `consecutive_hits` 在任一任务成功后清零；用于让连续限流时退避增长、恢复后回落。

**可测性**：`sleep`、`jitter` 均为可注入参数；测试注入 `sleep=记录器`、`jitter=lambda: 1.0`，
断言退避序列与 `final_concurrency`，无需真实等待。

**参数默认值**（写入 `parallel.py` 常量，不暴露 CLI）：
`RATE_LIMIT_BACKOFF_BASE = 1.0`、`RATE_LIMIT_BACKOFF_CAP = 30.0`、`RATE_LIMIT_RETRIES = 2`。

## 5. 应用策略（决策 D3：从后往前 + 逐级语法闸门）

### 5.1 聚合与合并
- 每个 `done` 任务产出 `replacement`（`clean_completion` 后）与 `out_line`。
- `merge_replacements(text, tasks, syntax_checker)`：
  1. 取 `status == done` 的任务，按 `out_line` **降序**排序；
  2. 逐个 `apply_replacement(current, out_line, replacement)`；
  3. 每一步后跑 `syntax_checker(candidate)`（默认 `bash_syntax_error`）：
     - `None` → 接受，`current = candidate`；
     - 否则 → 丢弃该条（`status = failed`，`detail` 记语法错误），**继续处理其余条目**；
  4. 返回 `(current, dropped)`。
- **为什么降序**：在 `out_line` 更大的行先替换，其行数变化只影响更大行号；后续（更小 `out_line`）
  的替换位置不受影响，因此无需任何 `offset` 补偿。这就是"从后往前应用避免偏移"。
- **为什么逐级校验**：单条 `bash -n` 通过不保证多条叠加后仍通过；逐级闸门保证最终产物
  一定 `bash -n` 通过（never emit broken bash 不变量）。

### 5.2 展示与写盘
- **重试在合并之前**（决策）：先收完一轮，若仍有 `failed` 且是交互终端，询问"重试失败的条目？[y/N]"
  并**仅重跑失败条目**（重置为 `pending`、清空 replacement、重置 retries），最多 3 轮（有界，防死循环）。
  重试先于合并的理由：避免"已应用后又重试"导致二次写盘与状态歧义；合并只做一次，diff 只出一次。
- 全部收完（含重试轮）→ `merge_replacements` → 若 `merged != original`：
  `render_diff(original, merged, "当前", "建议")` 展示**聚合 diff**；
- 用户**一次确认**（`应用全部 N 处修改？[y/N]`）→ 通过才写盘（沿用 `--print` / `--dry-run` / `write_output` 分支）；
- 失败/跳过条目在面板与汇总中单独列出；合并阶段被丢弃的条目标记为 `failed` 并计入失败列表。
- 退出码：只要有 skipped 或 failed，或用户拒绝应用 → `3`。

### 5.3 冲突与去重
- `scan_todo_markers` 每行只取第一个 `# TODO`，故 `out_line` 天然唯一；`plan_tasks` 仍按
  `out_line` 去重（重复时保留首个，后者标记 `skipped`），防御未来变更。

## 7. 核心模块契约：`python/bat2sh/core/api/parallel.py`

纯标准库；不导入 GUI；不直接跑 bash（语法校验经 `syntax_checker` 注入，默认 `bash_syntax_error`）。
`on_event` 可能被多个工作线程调用，编排层用内部锁**串行化**事件回调（消费者无需自带锁）。

```python
STATUS_PENDING = "pending"
STATUS_RUNNING = "running"
STATUS_DONE = "done"
STATUS_FAILED = "failed"
STATUS_SKIPPED = "skipped"

DEFAULT_MAX_CONCURRENCY = 3
MIN_MAX_CONCURRENCY = 1
MAX_MAX_CONCURRENCY = 16
RATE_LIMIT_BACKOFF_BASE = 1.0
RATE_LIMIT_BACKOFF_CAP = 30.0
RATE_LIMIT_RETRIES = 2

@dataclass
class FixTask:
    index: int              # 1-based，面板显示序号（与用户多选编号一致）
    marker: TodoMarker
    out_line: int           # 冻结的有效输出行号（构造 prompt 与合并时使用）
    prompt: str
    status: str = STATUS_PENDING
    replacement: str = ""   # clean_completion 后的建议（可多行）
    detail: str = ""        # 面板详情：跳过/失败原因
    rate_limit_hits: int = 0
    retries: int = 0

@dataclass
class FixEvent:
    index: int
    status: str
    detail: str = ""
    chunk: str = ""         # 流式正文块（status == STATUS_RUNNING 且 chunk 非空）

@dataclass
class ParallelResult:
    tasks: list[FixTask]
    rate_limit_hits: int
    final_concurrency: int

SyntaxChecker = Callable[[str], str | None]

def plan_tasks(markers: Sequence[TodoMarker], source_text: str, source_name: str,
               output_text: str, context_lines: int) -> list[FixTask]:
    """冻结 out_line，构造每条 prompt（复用 fixer.build_prompt）；同一行只保留首个。"""

def evaluate_reply(task: FixTask, raw: str, text: str, *,
                   syntax_checker: SyntaxChecker = bash_syntax_error) -> None:
    """把模型回复落到 task：可用且单条 bash -n 通过 → done；
    空/含 '# TODO'/与原文相同 → skipped；bash -n 失败 → failed。就地修改 task。"""

def merge_replacements(text: str, tasks: Sequence[FixTask], *,
                       syntax_checker: SyntaxChecker = bash_syntax_error) -> tuple[str, list[FixTask]]:
    """§5.1：仅 done、按 out_line 降序、逐级语法闸门。返回 (merged_text, dropped)。"""

def run_parallel(tasks: Sequence[FixTask], provider, *,
                 text: str,
                 timeout: float,
                 syntax_checker: SyntaxChecker = bash_syntax_error,
                 on_event: Callable[[FixEvent], None] | None = None,
                 sleep: Callable[[float], None] = time.sleep,
                 jitter: Callable[[], float] = random.random,
                 max_concurrency: int = DEFAULT_MAX_CONCURRENCY,
                 rate_limit_retries: int = RATE_LIMIT_RETRIES,
                 cancel_event: threading.Event | None = None) -> ParallelResult:
    """并发执行：限流器 + 429 退避降并发 + 错误隔离；就地更新 task.status。"""

def format_status_line(task: FixTask) -> str:
    """面板单行：'#1 第8行 done'（CLI/GUI 各自加装饰）。"""
```

`text` 是**原始生成脚本全文**（`evaluate_reply` 用它构造单条候选并过语法闸门）。
`provider` 为**整个批次共享的单个实例**（见 §7.2）。

### 7.1 不变量（测试必须锁定）
- `final_concurrency` ∈ `[1, 初始并发]`；只降不升。
- 单任务异常（任意 `ProviderError` 或 `Exception`）→ 该任务 `failed`，其余任务照常完成（错误隔离）。
- `on_event` 在每个任务的 `pending→running→(done|failed|skipped)` 迁移时至少各发一次；
  `running` 期间按 chunk 发 `chunk`。
- 初始并发 ≥ 任务数时也正确工作（空闲线程自然退出）。
- 初始并发 = 1 时退化为串行且不降无可降（`final_concurrency == 1`）。
- `merge_replacements` 结果必过 `syntax_checker`；行号偏移在多行替换（含行数增加/减少）下正确。

### 7.2 线程安全与取消
- `OpenAICompatibleProvider` 增加 `threading.Lock` 保护 `_thinking_param_unsupported` 的读改写，
  使单实例可被多线程共享（编排层整个批次共享一个 provider 实例，与原 CLI 行为一致）。
  降级告警只在**首次**真正降级时发一次（并发下不会 N 次刷屏）。
- 编排层的事件回调在锁内调用（消费者无需自带锁）。
- **429 计数去重**：`on_rate_limit` 回调与终止的 `ProviderRateLimitError` 可能描述同一次 429；
  编排层以「本次调用内是否已收到回调」判定，避免同一 429 重复计数/重复降并发。
  不变式：`final_concurrency == max(1, 初始并发 - rate_limit_hits)`（按构造成立）。
- **取消语义（已知限制）**：阻塞中的 socket 读无法被其它线程打断。`cancel_event`（GUI 停止按钮）
  或 `KeyboardInterrupt`（CLI Ctrl+C）置位后，工作线程在**下一次 chunk 边界 / 下一次空闲超时**
  才退出。因此：
  - 工作线程一律 `daemon=True`，保证进程可退出；
  - 中断路径最多额外等待 2s，随后放弃在途线程；
  - 不写盘（结果丢弃），在途任务标记 `skipped`/`已取消`。
  文档与 GUI 提示需说明"停止可能需要等待当前请求返回（最长一个空闲超时，默认 30s）"。

## 8. CLI 交互契约

1. 扫描 markers；无 → 退出 0（文案不变）。
2. 非 TTY → 退出 1（文案不变）。
3. 解析 API 配置（含 `max_concurrency`）；缺失 → 退出 6。
4. **多选**（仅当可修复条目 > 1 时提示；单条直接进入下一步，减少摩擦）：
   打印编号列表，提示 `选择要修复的条目（如 1,3-5；回车=全部；q=取消）[all]`：
   - `q` → 退出 1；解析失败或全不选 → 视为跳过全部，退出 3；回车/`all` → 全选。
5. **合并隐私提示（一次）**：
   ```
   bat2sh: 即将把 3 条 TODO 发送到外部服务：https://…/v1
   bat2sh: 内容将离开本机，可能被服务提供方记录（prompt 不含 API key）。
   ── 将发送的条目 ────────────
   #1 第 8 行: # TODO: 手动检查: for /f ...
   #2 第 9 行: # TODO: 手动检查: ...
   ───────────────────────────
   发送 3 条到 https://…/v1？[y/N]
   ```
   `n` → 全部 skipped，不写盘，退出 3。**`--yes` 不可绕过**（延续 v1.5）。
6. **并行执行 + 聚合面板**：TTY 且着色可用 → ANSI 原地刷新；否则追加式逐状态打印（测试依赖此路径）。
7. **重试失败项**（合并之前，最多 3 轮，仅 TTY）：列出失败条目 → `重试失败的 N 条？[y/N]` → 仅重跑失败条目。
8. **合并 + 聚合 diff + 一次确认**：`merge_replacements` → `render_diff` → `应用全部 N 处修改？[y/N]`。
9. 写盘（`--print` 只输出；`--dry-run` 只提示）。
10. 退出码：`0` 全部修复；`1` 非 TTY/取消/Ctrl+C；`2` 转换/写盘错误；`3` 仍有跳过或失败，或用户拒绝应用；`6` 配置错误。

`[REG]` 语义加入 `--fix-todos` 帮助文本：`# TODO[REG]` 为结构化标记，**仅作为 API 处理输入，不自动修复**。

## 9. GUI 契约（功能优先，Breeze 样式次之）

- `TodoFixDialog` 左栏改为**带复选框**的标记列表（多选，默认全选）；"开始并行修复"启动编排。
- 新增**聚合面板**（`QTableWidget` 或等价的只读列表）：每行 `序号 | 行号 | 状态 | 详情`，实时刷新。
- 流式正文在独立只读面板按 `#N:` 前缀分条显示（保持"流式可见"）。
- 全部收完 → 聚合 diff（复用 `build_diff_html`）→"应用全部修改"（一次确认）→ accept 写回编辑器。
- "重试失败项"按钮。
- 配色一律用 `palette(...)`（现有风格），不硬编码颜色；与 Breeze 若有视觉差异，功能优先并在交付说明标注。

| GUI 多选/面板/聚合应用 | `test_gui_fix.py` | 复选框默认全选、面板状态迁移、聚合 diff 应用 |

## 11. 发布流程与回滚

严格按任务书第五节：全绿 → examples 无回退 → 真实语料交叉验证 → bump commit(1.7.0) →
**tag 打在 bump commit** → push main+tag → sha256 同步 PKGBUILD → 重生成 `.SRCINFO` →
独立 commit + push → GitHub Release → 本机安装验证（`bat2sh --version` → `1.7.0`）。

回滚：本次不改转换管线，若并发层出问题，`git revert` 本阶段 commit 即可回到 v1.6.0 的串行行为
（`--fix-todos` 语义变化是唯一破坏性变更，需在 release notes 标注）。
