## 二、用自己的话复述

### 2.1 v2.5.0 默认开启的残余风险是什么

v2.5.0 把 CFG 标签分派状态机**默认开启**，代表性形态经 wine 黄金对照 **12/12 MATCH**。
但在 v2.5.0 报告中**如实披露的残余风险**：

1. **25 个 eligible 语料文件的组合/边界交互未逐文件 oracle**——仅 6 个代表性形态被证伪。
2. **`label_in_block`（97/4）未覆盖**（须扁平化，编译器级）→ 诚实 TODO。
3. **`missing_label` / `dynamic_target`** → 诚实 TODO。
4. **交互式/无限循环忠实化**：无 stdin 会挂起（有非阻断告警 + 逃生通道）。
5. **`rc0` 定义性位移**（4 文件假通过被修正）。

→ 本 session 的职责：**用全新语料检验 1（组合/边界）是否藏着缺陷，尤其是「无 TODO 但行为错」的静默错**。

### 2.2 新语料验证的目标

- 在**与 151 老语料零重叠**的 79 个新文件上跑**默认开启**的转换，取指标（语法/rc0/degraded/崩溃/交互告警）。
- **逐个 oracle 可 oracle 文件**（wine cmd vs 状态机产物），找 **DIFF**。
- **区分**：bat2sh 缺陷（修）/ 源畸形（记录）/ 环境依赖（单列）/ 交互挂起（已知）/ 测量 artifact。
- **重点找 v2.5.0 引入的静默错**（对比 CFG on/off，隔离状态机影响）。

`2ffa49b72148df41ea223f323aedc1f808802ddb`（`2ffa49b`），分支 `v2.6.0-new-corpus`，工作区干净。
