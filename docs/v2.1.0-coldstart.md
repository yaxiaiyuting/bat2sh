## 3. 用自己的话复述

### 3.1 P4（CFG 只读数据模型）是什么

一条 `goto` 要译对，必须先知道**它在文件里的位置**与**它跳到哪**：目标标签在 goto 之前还是之后（方向）、
目标是否存在、目标是否位于控制块内、被跳过的区间里有没有语句、该标签被几处跳入。
P4 就是把这套信息固化为一个**纯只读的数据模型** `core/cfg.py`：

- **标签位置表**：`:label` → 逻辑行号 / 下标 / 是否块内 / 入边计数；
- **goto→标签边**：每条 goto 的（源行、目标、目标类型、方向、是否块内、是否条件、是否冗余、C4 形态键）；
- **`validate` 守护**：每条 goto 必须落入 C4 台账的 7 个互斥主形态之一；不可归类即报错。

**P4 不驱动任何转换**（`integrated=False`）：转换器不 import 它，产物**零变化**。
它是 P5/后续 goto 高级形态的**前置基础设施**（路线图 §2.A「Phase 1」、C4 design §2 Phase 1）。

### 3.2 P5（goto 简单形态 pilot）是什么

在 P4 的图上，挑**置信度最高、可证安全**的两种简单形态做**第一次真实转换**：

- `redundant_goto`（27/5，置信度 B）：goto 的目标标签就是**下一条语句** → 执行与不执行完全相同 →
  可证 no-op，可自动消除；
- 顶层 `forward_skip`（551/26，置信度 D）：条件式 `if … goto :label` 的 guard 形态 → 尝试转为 `if` 结构。

硬闸门：churn ≤ 10 文件、wine 黄金对照、逐 commit 全量回归、任一静默错即停。

### 3.3 两者的依赖关系

```text
[P4] core/cfg.py（只读：标签表 + goto 边 + validate）   ← 零产物变化
        │  提供：方向 / 目标存在性 / 块归属 / 入边数 / 冗余判定 / 形态键
        ▼
[P5] redundant_goto → 顶层 forward_skip（在图上挑选可证安全子集做转换）
```

P4 不懂转换，P5 不自己重建图。**P4 必须先完成且零漂移，P5 才允许动转换器。**
路线图 §4.4 另有一条上游依赖：**P4/P5 依赖 v2.0.0 解析层**（括号/引号/块平衡）——
v2.0.0 已交付 P1/P2/P3a；P3b（LF-1）退回 2.x，即**解析层只收敛了一部分**。

### 4.2 路线图估算「翻转 ≈ 3–4」是否可靠？

**不可靠——实测为 0。** 这是本 session 最重要的前提核对（纪律 17：禁止估算标准）。

路线图把「翻转 ≈3–4」建立在「**唯一阻塞 = goto 的 degraded 文件**」之上，并点名
`合并文本`×3 + `显示所有分区的剩余空间`。逐项实测（只读探针 + `measure.json`）：

| 文件 | goto 形态（实测） | 该形态属 P5？ | 实测阻塞 | 能否被 P5 翻转 |
| :--- | :--- | :---: | :--- | :---: |
| `合并文本/合并文本.bat` | `for /f … do …&goto next`（**块内**） | ❌（属 `in_block_goto`） | `for /f` 选项 + 块内 goto | **否** |
| `合并文本/合并文本2.bat` | `goto :eof`（函数内，已实现） | ❌ | **`for /f` 选项不可解析** | **否** |
| `合并文本/合并文本3.bat` | 同 `合并文本.bat`（块内） | ❌ | 同上 | **否** |
| `显示所有分区的剩余空间（以MB为单位）.cmd` | `goto Main`、`goto loop`（**回跳**） | ❌（属 `backward_loop`） | 回跳（v2.2） | **否** |

进一步，扫描**全部 85 个 degraded 文件**，找出「所有 TODO 均为 goto 转换类」的文件：

```text
rc==0 且 todo_count>0 且 全部 TODO ∈ {goto 控制流无法自动转换, goto 跨函数跳转…}
→ 仅 1 个：显示所有分区的剩余空间（以MB为单位）.cmd（其 goto 全为 backward_loop）
```

其余「goto 单 category」文件（如 `打开快捷方式指向的目录.bat`、`批量重命名  （按指定拓展名）.bat`）
**category 同为 `control_flow`，但真实机制不是 goto**（分别是复杂 `start`、`for /r`、重定向歧义）。
即：**没有任何 rc==0 degraded 文件会被 P5 的两种形态翻转。**

> **结论**：路线图「翻转 ≈3–4」是**估算错**（与 v2.0.0「语法 4→1」同类问题）。
> 真实预期是 **0 翻转**。P5 的价值只能是「goto TODO 部分转化」，且该转化在可证安全子集上**几乎无收益**（见 §4.3）。

### 4.3 P5 候选安全子集实测

对 `redundant_goto`（27/5）与顶层 `forward_skip`（551/26 扫描器口径）逐条核对：

| 候选 | 实测 | 安全/价值判定 |
| :--- | :--- | :--- |
| `redundant_goto` 中**独立行**无条件 goto（`^goto L$`） | 集中在 `史上最牛X…bat`（**语法失败**，产物整体降级为注释） | 消除后**产物零影响**（该文件最终产物是降级注释块）；其余冗余实例嵌在 `if/else`、`管道 & if` 复合行内，需**行级重写**（非 no-op 删除），风险升 |
| `redundant_goto` 其余宿主 | `合并文本`/`合并文本3`（块内）、`文件备份器V2.3修改版2.cmd`、`瑞星杀毒软件2008批处理版.bat`（复合 `if/else`） | 均非「独立 no-op」；且宿主另有阻塞 TODO（0 翻转） |
| 顶层 `forward_skip` | 532 条 / 26 文件；**无任何宿主是 goto-only degraded 文件** | 0 翻转；且置信度 D（「目标可被多处跳入」），改 `_convert_goto`+块结构 → **053 同域风险** |

**判定**：P5 的两种形态在**可证安全子集**上要么**零产物/零指标影响**，要么**高风险且零翻转**。
继续实现将违反纪律 1（保守 TODO 优于激进转换）与纪律 13（不硬凑），并与 v2.0.0 的
「估算错 + 载荷性回滚」教训相冲突。
