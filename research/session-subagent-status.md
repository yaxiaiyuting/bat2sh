## 1. 探针（capability probe）

按前置检查要求，先跑一个**最小任务**验证 subagent 端到端可用：

| 项 | 内容 |
| :--- | :--- |
| 探针任务 | 「读 `docs/PROJECT-OVERVIEW.md` 并总结（5 bullet，<150 词）」 |
| 返回 | ✅ 正常返回结构化摘要 |
| 摘要质量 | ✅ 正确概括了项目定位（.bat/.cmd → bash 静态转换）、三层报告、`bash -n` 兜底、版本状态 |
| 判定 | ✅ **端到端可用**（不是"能启动但返回空"）|

> 探针选择「读 + 总结」而非「echo」，是为了同时验证 **工具调用能力**（read）
> 与 **结果回传能力** —— 只验证启动会漏掉「起来了但干不了活」。

## 2. 本 session 的 subagent 分工

## 3. 纪律约束（已写入每个 subagent 的任务书）

按纪律 9「**Subagent 输出必须主 session 核验**」，本 session 对 subagent 施加：

| # | 约束 | 落实 |
| :-: | :--- | :--- |
| 1 | **只读** —— 不得改产品代码/测试 | 任务书显式禁止；主 session 用 `git status` 核验改动面 |
| 2 | **不发明映射** —— 结论必须有实测证据 | 要求给出真实产物文本 / `bash -n` / 实际执行结果 |
| 3 | **主 session 不直接采信** | 汇总时**逐条复核**，可疑结论回到源码/实测验证 |
| 4 | 每个 subagent 输出**独立文件** | 避免并发写同一文件 |

> ⚠️ **并发写风险已知**：5 个 subagent 同时写 `research/`。
> 通过**文件名互斥**（`security-audit-<类别>.md`）规避；主 session 汇总文件 `security-audit.md` 由主 session 独占写。
