# 安全审查汇总（Phase A）

> 起点 HEAD：`70a0ddb`（v2.11.0 发布后 main tip）
> 方式：**5 个只读 subagent 并行**，每命令类别 1 个；主 session 负责**去重 / 裁定 / 核验**
> 产物：`security-audit-{del,for-delete,move-copy,path,misc}.md`（5 份，均由 subagent 写）
> 主 session 独立核验：**3 项最高危结论已亲自复现**（§4）
> **本 session 不做修复** —— 理由见 §6（命中暂停条件「高危且修复复杂」）

---

## 0. 一句话结论

> **5 个类别全部发现「高」等级风险，去重后归约为 7 个根因。**
> 其中 **3 个会导致静默的数据销毁或任意命令执行**，且**全部通过了 `bash -n`、无 `# TODO`、无告警**。
> 主 session 独立复现了其中 3 项（§4），**无一误报**。
>
> 根因高度收敛：**「源文本里的字面量被当成 bash 活语法」**（`$` / 反引号 / 通配符）是其中
> 4 个根因的共同机制 —— 4 个互不相通的 subagent 从**不同命令类别**独立报出同一机制（§3.1）。
>
> ⚠️ **结论：修复面横跨 `_convert_path_token` / `_dq_preserving_substitutions` / `_render_redirs` /
> `_errorlevel_condition` / `cmd_findstr` / `cmd_del` / `cmd_rmdir` / `_emit_for_r` / `cmd_taskkill`
> 等核心转换路径 ⇒ 属「高危且修复复杂」⇒ 按暂停条件 §6 **本 session 只报告、不修**（§6）。**

## 2. 高危汇总表（去重后）

| # | 命令 | 输入（.bat） | 产物（.bash） | 风险 | 等级 | 来源 |
| :-: | :--- | :--- | :--- | :--- | :-: | :--- |
| **H1** | `del /s /q` | `del /s /q %WINDIR%\*` | `rm -rf "/"/*` | **根锚定递归删除**；`/*` 形态**不受** GNU preserve-root 保护 | **高** | A-1 |
| **H2** | `del` / `rd` | `rd /s /q \\?\C:\data` | `rm -rf \/?/C:/data` | `?` 是**活通配符** ⇒ 删掉 `bat` 从未提及的 `/x/C:/data`、`/y/C:/data` | **高** | A-1 A-4 |
| **H3** | `del` | `del "a$(touch PWNED).txt"` | `rm -f "a$(touch PWNED).txt"` | **字面 `$()` 变活命令替换 ⇒ 任意命令执行** | **高** | A-1 A-4 A-2 A-5 |
| **H4** | `for /r` + `rd` | `for /r %%i in (.) do rd /s /q "%%i"` | `rm -rf "${i:-}"` ←`find "$PWD" -type d` | **第一个值就是 CWD 自身 ⇒ 整棵工作树含运行中的脚本被删**，`rc=0` | **高** | A-3 |
| **H5** | `for /r` + `rd` | 同上但用 `%%~ni`，**祖先目录名含点** | `rm -rf "$(basename "${i%.*}")"` | `%%~n` 顺序倒置 ⇒ **递归删掉不相干的旁系目录** | **高** | A-3（= Phase C §2.1） |
| **H6** | `findstr` + `if errorlevel` | `findstr "needle" haystack.txt`<br>`if errorlevel 1 del keep.txt` | `if ! grep … \|\| true; then rm -f "keep.txt"; fi` | `\|\| true` 被拼进条件 ⇒ **条件恒真 ⇒ 无条件误删** | **高** | A-5 |
| **H7** | `move`/`copy` | `move "my doc*\f.txt" dst\` | `mv my doc*/f.txt "dst/"` | 中间段通配符 ⇒ 整条**脱引号** ⇒ 词分割**移走无关文件 `my`**（源删除） | **高** | A-2 A-1 |
| **H8** | `echo >` | `echo replaced > log?.txt` | `echo "replaced" >log?.txt` | 重定向目标**当活 glob** ⇒ **静默覆盖无关文件** | **高** | A-5 |
| **H9** | `taskkill /IM` | `taskkill /IM app*` | `pkill -f app*` | 无锚定正则匹配**整命令行**；`/IM .exe` → `pkill -f ""` 实测匹配 **606/609** 进程 | **高** | A-5 |
| **H10** | `xcopy` | `xcopy /e /i /y src dst`（目标已存在） | `cp -r src dst` | `xcopy` 无 `/y` 的覆盖语义丢失 ⇒ **静默覆盖**（`cp`/`mv` 的覆盖**不算**缺陷，见 §5） | **高** | A-2 |
| **H11** | `for` + 空变量 | `for %%i in (%FILES%) do del "%%i\*"` | `rm -f "${i}"/*` | 空值 + 通配尾 ⇒ **根锚定 glob**（实测实参展开为 `/bin /boot /etc …`） | **高** | A-3 |

> **H3 的四个独立来源是本轮最强的信号**：A-1（`del`）、A-2（`copy`）、A-4（路径层 6 个触发面）、
> A-5（`set`/`type`/`set /a`）**各自独立**复现了同一根因 —— 它们互不相通、审查的命令类别不同。

## 3. 去重：11 条高危 → 7 个根因

### 3.1 根因聚类

| 根因 | 机制 | 覆盖高危 | 代码锚点（主 session 复核） |
| :--- | :--- | :--- | :--- |
| **R1 — 字面 `$` / `$()` / 反引号被当活语法** | `_dq_preserving_substitutions` **刻意保留** `$()`；`$` 占位符保护只挂在 `echo` | H3 (+中危多项) | `batch.py:2183-2215`（`2188-2208`）；`$` 保护仅 `:2942-2943` / `cmd_echo :3369` |
| **R2 — 路径 token 回退产出未引号 / 活 glob** | head 含通配符则**整条不加引号**；`\\?\` 的 `?` 逃逸不彻底 | H2 H7 (+中危) | `batch.py:2217-2227`（`:2225` 手写 `f'"{head}"/{tail}'`，`:2226` 放弃引号）；`utils.py:169-170` |
| **R3 — Windows 系统变量映射到 `/` 后仍拼 `\*`** | `%WINDIR%`/`%SystemDrive%` → `"/"`，再与 `\*` 相连 ⇒ `"/"/*` | H1 H11 | `rules.py:224/225/238/240`；`cmd_del :3423` |
| **R4 — `errorlevel` 条件拼接 `\|\| true` 守卫** | 守卫本意"未匹配不终止脚本"，却被拼进 `if` 条件 ⇒ 恒真 | H6 | `_errorlevel_condition batch.py:2148`；`_convert_simple :2820-2825/2832-2837`；`cmd_findstr :3685-3763` |
| **R5 — `for /r` 的 `find` 值域含 CWD 自身** | `find "$PWD" -type d` **第一个值 = 工作目录** | H4 | `_emit_for_r batch.py:2333`（`find "$PWD" -type d` `:2374`） |
| **R6 — `%%~n` 先剥扩展名再取末段（顺序倒置）** | 已在 Phase C 独立诊断并修复（本 session） | H5 | `_modifier batch.py:1250` |
| **R7 — 删除目标缺 `--` 且选项透传** | `rm` 无 `--`；`/a` `/p` 等开关被 `_split_switches` 吞或透传 | 中危 | `cmd_del :3424`（targets 无 `--`）；`_split_switches :3158-3170` |

> **R1 + R2 是同一族**：「**该转义却没转义**」。二者合计覆盖 H2/H3/H7 + 大量中危，
> 是本轮**结构性最严重**的问题 —— 它不是某条命令的 bug，而是**转义责任散落**在多个 handler 里，
> **没有任何一层能区分「变量展开插入的 `$()`」与「源里字面 `$()`」**（A-4 的原话）。

### 3.2 各报告对同一问题的措辞差异（去重依据）

| 现象 | A-1 措辞 | A-2 措辞 | A-4 措辞 | 判定 |
| :--- | :--- | :--- | :--- | :--- |
| `$()` 活执行 | 「字面 `$` 未转义」 | 「路径文本当 shell 代码」 | 「命令注入，6 个触发面」 | **同一根因 R1**，合并 |
| `\\?\` 的 `?` | 「已知类未真正消除」 | 「`?` 成活通配符」 | 「F6 另一触发面」 | **同一根因 R2**，合并 |
| 中间段通配符脱引号 | 「整条脱引号」 | 「词分割移走无关文件」 | 「裸 token」 | **同一根因 R2**，合并 |

## 5. Subagent 的自我更正（正面信号，予以采信）

> A-2 **主动推翻了自己类别里的一条"看起来像高危"的结论**，这是本轮质量最高的单个判断：

| 项 | 结论 |
| :--- | :--- |
| `copy` / `move` 无 `/y` 的静默覆盖 | ❌ **不算缺陷** —— MS 文档明确「批处理脚本内默认不提示」，`cp`/`mv` 对这两条**是忠实的** |
| 只有 `xcopy` 无 `/y` | ✅ **是真语义丢失**（xcopy 文档无「批处理例外」）⇒ 仅此一条记为 H10 |

**同类正面信号**：A-1 主动说明 `rm -rf "/"` 与 `rm -rf "/"/*` 的**保护差异**
（前者被 GNU preserve-root 拒绝、后者不受保护）—— 这个区分是 H1 定级的**关键**，且不是"更吓人"的方向。

## 6. 修复决策：**暂停，只报告**

### 6.1 判定

用户 Phase A 规则：

| 风险 | 规定行动 |
| :--- | :--- |
| 高 | 立即修 + 独立 commit |
| **高危且修复复杂** | **暂停，报告** ← **命中** |

### 6.2 为什么"修复复杂"成立（不是托词）

| # | 理由 |
| :-: | :--- |
| 1 | **面太宽**：11 条高危 → 7 个根因，横跨 **9 个** 核心函数（§0 末）。任一处都是 A1/053 邻域或块发射路径。 |
| 2 | **R1/R2 是结构性的**：不是改一个分支，而是要**重新划清"哪一层负责转义"**（A-4 明确指出当前"转义责任散落"）。这是设计级改动，不是补丁。 |
| 3 | **R1 的修复方向天然与 A1 冲突**：`_dq_preserving_substitutions` **是刻意保留 `$()`** 的（`:2188-2208`），因为变量展开需要它。要区分"展开插入的"与"源里字面的"，必须改 `_expand_vars` 的数据流 —— 正是 **A1 热路径**。 |
| 4 | **R3 的正确修法涉及"不发明映射"**：`%WINDIR%` 该映射成什么才既安全又不失真，属**产品决策**（现映射 `/` 是"朴素等价"） |
| 5 | **无 oracle 证据**：本轮 Phase B 的 oracle 才刚开始（§另文），这些修复**没有差分证据**支撑"无回归" |
| 6 | **上下文预算**：本 session 已完成 C 修复 + A 审查 + B 采集，按「上下文不足 → 完成当前阶段就停」应停 |

⇒ **本 session 不落地任何安全修复**，改为交付**优先级 backlog**（§6.3）。

### 6.3 建议的修复优先级（下一 session）

| 序 | 根因 | 理由 | 预估 |
| :-: | :--- | :--- | :--- |
| **1** | **R3**（`%WINDIR%`+`\*` → `rm -rf "/"/*`） | **唯一一个能销毁整机文件系统**的；且修法最局部（`rules.py` 映射 + `cmd_del` 拼 `\*` 处） | 小 |
| **2** | **R5**（`for /r` 首值 = CWD 自身） | **单条 bat 即可删掉整个工作树**；实测已复现；修法明确（`find -mindepth 1` 或排除 `$PWD`） | 小 |
| **3** | **R4**（`errorlevel` 恒真） | **静默误删**，实测已复现；修法明确（守卫移到条件外） | 小 |
| **4** | **R2**（路径 token 活 glob / 脱引号） | 影响面最大（del/move/copy/rd 全线），但修法可**先窄修 `\\?\` 与中间段通配** | 中 |

> 优先选择**降级为诚实 TODO**（不再产出静默错误的 bash），而不是试图做完美转换。
