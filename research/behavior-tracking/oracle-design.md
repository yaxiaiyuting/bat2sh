## 2. 目的与定位

### 2.1 要发现什么

**静默错误**：转换错了，但没有任何现有信号能说明它错了 ——
`bash -n` 通过、无 `# TODO`、`rc=0`，可行为与真机 `cmd.exe` 不同。

**不要**给每个样本打分。**要**把 W（真机）与 L（产物在 Linux 上跑）的差异分成三类，
把**第三类（不可归因）**暴露出来。

### 2.2 与既有 `tools/oracle/` 的关系（重要，避免重复造）

仓库**已有一个 oracle**：`tools/oracle/golden_harness.py`（v1.9.2 落盘，wine 作 W 侧，12 个构造用例）。
它已确立两条本设计必须继承的东西：

| 继承项 | 内容 | 出处 |
| :--- | :--- | :--- |
| **权威顺序** | `真机 cmd / 官方文档` **>** `wine` **>**（不可用） | `tools/oracle/README.md` |
| **归一化先例** | 行尾归一 + ANSI 剥离 + 行尾空白 rstrip + **丢弃空行** | `golden_harness.py:48-52` |

**本 session 的增量 = 把 W 侧从 wine 换成真机。** wine 是重实现，其 README 明确"只作初筛"、
列了两条 `UNRELIABLE_PROBES`（X5 文件句柄吞位、A8 findstr 多词切分）——这两类现在可以**真机判定**了。

**本设计对先例的一处修正**：golden_harness 的 `normalize()` **无条件丢弃空行**（`if line`）。
本设计**不采纳为默认**（§5 N4）——它会把"多/少一个空行"的缺陷一并抹掉，而这是可观测的真实差异。

### 2.3 与"五信号监控"的关系

本设施只做 **L3 输出效果层**（stdout/stderr/rc/文件系统），与 `collection-design.md` §2 的分层一致。
L1（API）/ L2（syscall）/ 注册表 / 进程 **不在本设计内**（§12 边界）。

## 3. 对比模型

### 3.1 W 与 L 的定义

```
W  =  真机 cmd.exe 执行原始 .bat         （既有设施：research/behavior-tracking/tools/collect.py）
L  =  bat2sh 产物 .sh 在 bwrap 沙箱执行   （本 session 新建：tools/collect_linux.py）
```

- W 侧：Windows 10/11 guest，`--network=isolated`（零出网），覆盖层回滚保证起点逐字节相同，
  `--workdir C:\poc\samples`，`< nul` 作 stdin，每轮强制把时钟设为 `2026-06-01 12:00:00`（UTC+8）。
- L 侧：bwrap `--unshare-all`（无网络）、`< /dev/null`、脚本目录 = 沙箱工作根、**不固定时钟**（§5 D7）。

### 3.2 对称性要求（**决定成败**）

| 维度 | W | L | 是否可对齐 |
| :--- | :--- | :--- | :--- |
| 工作目录 | `C:\poc\samples` | `<RUN>` | ✅ 映射即可 |
| **目录初始内容** | 只含上传的样本 | 只含转换产物 | ✅ **但产物必须沿用同一 basename**（见下） |
| stdin | `< nul` | `< /dev/null` | ✅ |
| 网络 | 链路 down | `--unshare-all` | ✅ |
| 时钟 | 固定 2026-06-01 | 宿主实时 | ❌ 只能形状化（D7/N8） |
| 清单范围 | `C:\poc`（默认） | `<RUN>` | ⚠️ **建议 W 改用 `--scope C:\poc\samples`** 使映射严格 1:1 |

#### 3.2.1 产物命名规则（**有证据，不是发明**）

L 侧转换产物**必须沿用 W 侧的 guest 文件名（含 `.bat` 扩展名）**，只是内容是 bash。

证据（实测）：`%~nx0` 被转换为 `$(basename "$0")`、`%~dp0` 为 `${SCRIPT_DIR}/`，
`for %%i in (*.bat)` 为 `for i in *.bat`：

```bat
echo name0=%~nx0        →   echo "name0=$(basename "$0")"
for %%i in (*.bat) do   →   for i in *.bat; do
```

⇒ 脚本**能观测到自己的文件名**，也**能观测到目录里有哪些 `.bat`**。
若把产物命名为 `X.sh`，则 W 的目录列表含 `X.bat`、L 的含 `X.sh`，
`for %%i in (*.bat)` 在两侧匹配数不同 —— **这是采集设施引入的假差异**。
沿用原名（`bash X.bat` 执行，内容为 bash）即可消除。

> 已知代价：`type X.bat` 之类的**自读**在 L 上读到的是产物而非源文件（→ D9，可归因）。

### 3.3 采集渠道（通道）

| 通道 | W 指纹字段 | L 指纹字段（同结构） | 判别力 |
| :--- | :--- | :--- | :--- |
| 退出码 | `execution.exit_code` | 同 | 高（0 vs 非 0 语义） |
| stdout | `stdout.text`（CP936 解码） | `stdout.text`（UTF-8 解码） | 高 |
| stderr | `stderr.text` | 同 | 高 |
| 文件/目录**名称集** | `filesystem.created/modified/deleted` + `created_dirs/deleted_dirs` | 同 | 高 |
| 文件**内容** | `filesystem.after_manifest[*].Hash`（原始字节 SHA256） | 同 + **两个额外哈希**（§5 N10/N11） | **最高**（抓"文件名对、内容错"） |

> **内容通道是本设计的核心增量。** 既有 wine harness 只比 stdout；既有 W 采集器只做名称差分。
> "文件建对了但内容错了"是**最典型的静默错误**，只有内容哈希能抓。

## 4. 结果三分类与判定算法

### 4.1 三分类

| 类 | 判据 | 行动 |
| :--- | :--- | :--- |
| **一致** | 所有通道在**最小归一化**（N1+N7）下即相等 | 无 |
| **可归因差异** | 需要**D-list 内**的规则才能相等，且所需规则**逐条有据** | 记录 |
| **不可归因差异** | 施加全部已定义规则后仍不等；或所需规则**不在 D-list** | **报告（潜在缺陷）** |

### 4.2 判定算法（最小规则集）

```
1. 规范化：把 W/L 指纹投影成 5 个通道的原始表示
2. 严格档 S：只应用 N1（行尾）+ N7（编码解码）→ 逐通道比较
     全等 → 【一致】，结束
3. 归因档 A：按 D-list 逐条尝试追加规则，**每种规则单独记录"是否被需要"**
     全等 → 【可归因】，报告 required_rules = {…}
4. 仍不等：
     对 stdout 单独做「多重集相等但顺序不同」检测 → 若是，标为【可归因/顺序】并指向 D4，**人工确认**
     否则 → 【不可归因】，输出逐通道 diff
5. 任何被启用的规则都写进报告的 normalization_applied[]，**包括它掩盖了什么**
```

**关键设计**：规则不是"一股脑全上"，而是**先不加、不够再加、每一加都留痕**。
这样"差异被哪条规则吃掉了"永远可见 —— 对抗"假一致"的唯一办法。

### 4.3 "不可归因"的处置（任务书 §4.4）

逐个分析，且**必须**落到下列之一：

| 结论 | 处置 |
| :--- | :--- |
| 是 bat2sh 缺陷 | 记录（含最小复现 + W/L 原始证据），**不在本 session 修**（研究设施纪律） |
| 是归一化规则不足 | **修正规则并重跑**（规则变更记入 §5 表 + 版本号） |
| 是新的已知差异 | **补充 D-list**（并说明为什么它是平台性的，而不是转换错误） |

## 5. 归一化规则（每条带理由）

**约定**：`[S]` = 严格档默认启用；`[A]` = 仅归因档；`[off]` = 默认关闭，需显式开启且必须记录。
每条规则的"有损性"指**它会掩盖哪一类真实缺陷**。

> ### ⚠️ 执行期修正（本节的 `[S]/[A]` 标注以本框为准）
>
> 本节是**用户确认的原始设计**。Phase 3 实测触发了 2 处修正（`oracle-result.md` §4 有完整理由）。
> 按纪律 2（主动披露偏离），此处**保留原文不改写**，只在此声明生效版本：
>
> | # | 规则 | 原标注 | **生效标注** | 触发原因 |
> | :-- | :--- | :--- | :--- | :--- |
> | **A1** | **N6**（路径分隔符） | `[A]` | **`[S]`** | W 的清单键恒用 `\`、L 恒用 `/` ⇒ 原标注下**任何写文件的样本都不可能判"一致"**，"一致"类成为空集、报告全部退化为"可归因"，**判别力反而下降**。`\` vs `/` 与 N1（CRLF vs LF）同性质。**N6 仍只对 `<WORK>` 前缀生效**，工作根之外的差异照旧暴露 |
> | **A2** | **N5**（工作根映射）作用域 | 仅路径 | **路径 + 文本** | L 的 stderr 含**每次运行都不同**的沙箱绝对路径（实测 `cat: '/tmp/bat2sh-oracle/copy-1790434237842/…'`）⇒ 任何含路径的错误信息**恒定假报不一致**。映射源取指纹自带的 `rollback.run_dir`，非猜测 |
>
> 另有 1 处**报告**修正（非规则）：文件内容比较按 `filesystem.known_artifacts`
> **排除采集器自己放进沙箱的产物**（W 是 `.bat`、L 是 bash，按构造就不同，属恒定噪声）。
>
> **修正没有放宽任何实质判定**：F4（盘符路径）仍被判为差异，
> 只是依据仓库文档（`2.x-roadmap-research.md:137,371`「盘符映射不做」）改判为**已知行为**而非**平台差异**。

### N1 `[S]` 行尾归一：`\r\n` → `\n`，孤立 `\r` → `\n`

- **理由**：cmd 控制台输出用 CRLF，bash 用 LF。这是**表示层**差异，不是脚本行为差异。
- **证据**：本次 W 采集 `stdout.text == 'source-alpha\r\n'`；L 侧 `echo` 产出 `\n`。
- **先例**：`tools/oracle/golden_harness.py:49` 同规则。
- **有损性**：低。

### N2 `[A]` 剥离 ANSI 转义序列 `\x1b\[[0-9;]*[A-Za-z]`

- **理由**：Windows 控制台程序可写颜色转义；bash 在**非 TTY** 下通常不写。QGA 捕获的是管道。
- **先例**：`golden_harness.py:50`。
- **有损性**：低（本批 Class A 样本不产生 ANSI）。

### N3 `[A]` 行尾空白 rstrip

- **理由**：cmd 内建命令输出定宽列并补空格（`dir` 的表格），`ls` 不补。
- **有损性**：**中** —— 会掩盖"多写了空格"。启用时记录。

### N4 `[off]` 丢弃空行

- **理由**：**不采纳为默认**。`golden_harness.py:52` 无条件丢弃空行，但那会把
  "多/少一个空行"的缺陷一并抹掉，而空行是可观测的真实差异。
- **处置**：默认关闭。若某样本**仅**剩空行差异，报告写"仅空行差异"，交人工。
- **有损性**：高。

### N5 `[S]` 工作根映射：W `C:\poc\samples` ↔ L `<RUN>` → 统一为 `<WORK>`

- **理由**：两侧沙箱的物理位置不同，是**采集设施的选择**，不是脚本行为。
- **证据**：W 指纹 `execution_workdir = "C:\\poc\\samples"`、`filesystem.scope = ["C:\\poc"]`。
- **有损性**：**中**。缓解措施：**映射只对 `<WORK>` 前缀生效**；任何映射后仍以盘符或 `/` 开头的路径
  **不参与映射**，原样对比 ⇒ "写到了工作根之外"这类缺陷仍会暴露。
  （实测：bat2sh 把 `C:\poc\x` 转成字面 `C:/poc/x`，在 Linux 上落到 `<RUN>/C:/poc/x`
  —— 这种"跑偏的写入"必须可见，不能映射掉。）

### N6 `[A]` 路径分隔符统一 `\` ↔ `/`（**仅在已识别的路径 token 内**）

- **理由**：平台路径分隔符差异。
- **有损性**：低-中（token 识别不完美时可能误改）。启用时记录。

### N7 `[S]` 文本编码解码：W 按 **CP936**、L 按 **UTF-8** 解码为 Unicode 后比较

- **理由**：字节层不同是编码差异，字符层才是行为。
- **证据**：W 指纹 `environment.console_codepage = 936`；`stdout.text` 已由采集器按 CP936 解码。
  语料 **110/151 是 GBK**（§9）。
- **有损性**：低-中。若 bat2sh 产出的中文成乱码，解码后仍不等 ⇒ 仍能发现。

### N8 `[A]` 时间戳**形状化**（值盲、形敏感）

- **理由**：W 时钟被固定为 `2026-06-01 12:00:00`（`fixed_time.ok=true`），L 是宿主实时，
  **值必然不同**；但**格式**错误是真缺陷。
- **规则**：把 `\d{4}[-/]\d{1,2}[-/]\d{1,2}`、`\d{1,2}:\d{2}(:\d{2})?`、`周一`…`周日`、`Mon`…`Sun`
  替换为形状标记 `<DATE>` / `<TIME>` / `<DOW>`，**比较替换后的串**（形状不同仍然报差异）。
- **适用条件**：仅当样本静态含 `%date%`/`%time%` 时才启用（分类器已能识别）。
- **有损性**：中（掩盖日期值错误）。

### N9 `[off]` 随机数：`%random%` 派生值 → `<N>`

- **理由**：`%random%` 两侧不可能相同。
- **处置**：默认**关闭**。含随机数的样本应逐个看，而不是一键抹平。
- **有损性**：中。

### N10 `[S]` 文件内容：**行尾归一后的哈希**

- **规则**：L 采集器对每个文件额外算 `hash_lf_to_crlf = sha256(内容.LF→CRLF)`；
  判据 `W.Hash == L.hash_lf_to_crlf`。
- **理由**：cmd 的 `echo x>f` 落盘 **CRLF**，bash 的 `echo x >f` 落盘 **LF**。
  这是**产物行尾**的平台差异（与 N1 同源，但作用于文件而非 stdout）。
- **精确性**：哈希相等是**强判据** —— 它精确陈述"L 的内容 = W 的内容（模行尾）"，不是"差不多"。
- **有损性**：会掩盖"唯一差异就是行尾"的缺陷。启用时记录。

### N11 `[S]` 文件内容：**CP936 + 行尾**双重归一后的哈希

- **规则**：L 采集器另算 `hash_cp936_crlf = sha256(utf8解码(内容) → cp936 编码 → LF→CRLF)`；
  判据 `W.Hash == L.hash_cp936_crlf`。
- **理由**：语料 **110/151 是 GBK**。W 上 `echo 中文>f.txt` 落盘是 **CP936 字节**，
  L 上是 **UTF-8 字节**。不做此规则，**所有中文文本样本都会假报不一致**。
- **适用条件**：仅当 UTF-8 解码成功**且**字符在 CP936 中可编码时才计算；
  不可编码 → 规则**不适用**（不产生假匹配）。
- **有损性**：中（掩盖编码缺陷）。当"只有 N11 能消除差异"时，报告须显式写明
  **差异 = 编码（CP936 vs UTF-8）**，让人看见它被吃掉了。

### N12 `[A]` 退出码宽度：`W.rc & 0xFF == L.rc & 0xFF`（且 `W.rc` 不在 0..255）

- **理由**：Windows 退出码是 32 位，POSIX 是 8 位（`exit /b -1` → W 4294967295 / L 255）。
- **有损性**：低。启用时记录。

### N13 `[诊断]` `set -euo pipefail` 归因重跑（**不是归一化**）

- **规则**：若 L 提前中止而 W 继续，把 L 产物做一次"`set +e` 前置"的诊断性重跑；
  若重跑结果与 W 一致 ⇒ **证据**表明差异源于 D5（`set -e` 早退 vs cmd 继续）。
- **为何放在这里**：它是**获取证据**的手段，不是抹平差异的规则。重跑结果**不替换**正式 L 指纹。

## 6. 已知平台差异清单（D-list，分类的基础）

**用法**：只有 D-list 内的条目才能支撑"可归因"判定；每条须写清**为什么它是平台性的**。

| # | 差异 | 例子 | 依赖规则 |
| :-- | :--- | :--- | :--- |
| **D1** | 路径分隔符 | `C:\poc\x` vs `<WORK>/x` | N6 |
| **D2** | 行尾 | stdout 与文本文件 CRLF vs LF | N1, N10 |
| **D3** | 控制台代码页 | CP936 vs UTF-8 字节 | N7, N11 |
| **D4** | 目录列举**顺序** | `dir` 本地化排序 vs `ls` locale collation | 顺序子分类（§4.2 步 4） |
| **D5** | `set -euo pipefail` **早退** | L 在某条失败命令处中止，cmd 继续执行 | N13（需证据） |
| **D6** | 退出码宽度 | 32 位 vs 8 位 | N12 |
| **D7** | 时钟 | W 固定 `2026-06-01`；L 宿主实时 | N8 |
| **D8** | `%~dp0` 结尾分隔符 | W 结尾 `\`，L 结尾 `/` | N6 |
| **D9** | 自读产物 | `type X.bat` 在 L 上读到 bash 而非 bat | 无规则，直接说明 |
| **D10** | 目录列举**格式** | `dir` 带表头/汇总/字节数；`ls -1` 只有名字 | 无规则（**不是** N3 能解决的，须逐例确认） |
| **D11** | 不存在的外部命令 | `nconvert`/`CSty` 缺失 → W 报"不是内部或外部命令"，L 报 `command not found` | 无规则（stderr 文本不同但**语义相同**；须逐例确认） |
| **D12** | 大小写敏感性 | W 不区分，L 区分 | 无规则（**故意不归一**，见下） |
| **D13** | 不存在的设备/伪文件 | `type nul` → `:` | 无规则 |
| **D14** | `ping` 作延时惯用法 | `ping -n 2 127.0.0.1>nul` 被转成 `ping -c 2 127.0.0.1` | 无规则（**语义近似但不等价**，须逐例确认） |

### 6.1 **不构成归因理由**的项（防滥用）

| 不能当理由的东西 | 为什么 |
| :--- | :--- |
| **"命令名不同（`dir` vs `ls`）"** | 命令名映射**正是被检验的对象**。映射后行为不等 = 缺陷，不是"平台差异"。任务书 §2.4 举它作例子，本设计**明确不采纳为归因依据** |
| "产物看起来合理" | 无判据 |
| "Linux 就是这样" | 必须落到具体 D 条目 |
| "wine 也这样" | 权威顺序：真机 > wine |
| "样本太怪" | 怪样本恰是静默错误的富矿 |

### 6.2 **故意不归一**的两项（保留判别力）

| 项 | 为什么不归一 |
| :--- | :--- |
| **D12 大小写** | W 上 `A.txt` 与 `a.txt` 是同一文件，L 上是两个。这是**真实的行为分歧**，应被看见 |
| **列举顺序（D4）** | 不预先排序抹平，而是"先检测、后归因"（多重集相等 + 顺序不同 ⇒ 单独标注，人工确认）。预先排序会掩盖真实顺序缺陷 |

## 7. L 侧采集设施设计（`tools/collect_linux.py` 规格）

### 7.1 目录布局

```
<RUN>/                        沙箱工作根 ≡ W 的 C:\poc\samples（每次全新）
  └── <guest_name>            转换产物，**沿用 W 侧文件名（含 .bat）**，内容是 bash
```

清单快照：`<RUN>` 递归（对应 W 的 `--scope C:\poc\samples`），条目字段与 W 对齐：
`{FullName, Length, Hash, hash_lf_to_crlf, hash_cp936_crlf, mode, is_dir}`。

### 7.2 执行

```
bwrap --unshare-all --die-with-parent \
      --ro-bind /usr /usr --ro-bind /etc /etc \
      --symlink usr/bin /bin --symlink usr/lib /lib --symlink usr/lib64 /lib64 \
      --proc /proc --dev /dev --tmpfs /tmp \
      --bind <RUN> <RUN> --chdir <RUN> \
      /bin/bash <RUN>/<guest_name> < /dev/null
```

- `--unshare-all` = 无网络 ≡ W 的 `isolated`
- stdin `/dev/null` ≡ W 的 `< nul`
- `--die-with-parent` 防泄漏
- **`--symlink usr/*` 必需**（Arch 的 `/bin`、`/lib` 是符号链接；不加则 `execvp` 失败 —— §1 实测）

### 7.3 输出（与 W **同结构**）

复用 W 的 schema v4 骨架：`schema_version / harness / script / environment / rollback / execution /
stdout / stderr / filesystem / process / network / timings / notes`，其中：

| 字段 | L 侧填法 |
| :--- | :--- |
| `harness.git_head` | 本仓库 HEAD（锁定可比性） |
| `script.name/sha256/size` | **原始 .bat** 的名字/哈希/大小（与 W 逐字段可比） |
| `script.guest_path` | `<RUN>/<guest_name>`（映射后 = W 的同名字段） |
| `environment.console_codepage` | `65001`（UTF-8），显式声明 ≠ 936 |
| `rollback` | `method: "tmpdir-recreate"`（L 侧靠"每次全新目录"而非 qcow2 覆盖层） |
| `execution.argv` | `["bash", "<RUN>/<guest_name>"]` + `stdin: "/dev/null"` |
| `filesystem.blind_spots` | 与 W **同一组** + `"linux-side-no-registry"` |
| `network` | `{mode:"isolated", isolation_method:"bwrap-unshare-all", egress_frames:0}` |
| `notes[]` | **必填**：`clock_not_fixed`（L 无法固定时钟，D7） |

**可独立运行**（任务书 §3.2）：`python3 tools/collect_linux.py --script X.bat --output Y.json`
（自己调 `bat2sh` 做转换，或 `--artifact X.sh` 直接给产物）。

> 也意味着：**纯差分 oracle 的可判定覆盖面天然很小**，想扩大覆盖必须先扩大

## 11. 复杂度评估（任务书 §六"可在设计中标注"）

**坦率评估：本设计偏高复杂度。** 12 条归一化规则 + 14 条 D-list + 5 个通道。
主要复杂度来自**中文语料的编码维度**（N7/N11）与**时钟不可对齐**（N8/D7）。

建议**分期**，只做 Tier 1+2：

| Tier | 内容 | 规则 | 判断力 | 建议 |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1** | rc + stdout/stderr + 文件**名**集 + 文件**内容** | N1, N5, N7, N10, N11 | **核心**：能抓"文件名对、内容错" | ✅ **必做** |
| **Tier 2** | 归因精度 | N2, N3, N6, N12, 顺序子分类(D4) | 把差异归到具体 D 条目 | ✅ 建议做 |
| **Tier 3** | 诊断增强 | N8（时间形状化）, N9, N13（`set -e` 重跑）, strace 辅助 | 处理 B 类与"不可归因"深挖 | ⏸️ **仅在实际出现时再做** |

**可以砍的**：N8/N9（本批 5 个样本**都不读时间/随机数**）⇒ Phase 3 **完全不实现**，
等 B 类样本进来再说。这一刀砍掉约 1/3 的规则量。

**不可以砍的**：N5/N10/N11。没有它们，"纯文件操作"样本会**全部假报不一致**。

## 12. 能力边界（本 oracle **看不见**什么）

必须写进设施文档，防止下游把"没看到差异"误读为"转换正确"：

| 看不见 | 原因 | 后果 |
| :--- | :--- | :--- |
| **读操作** | 两侧都是净差分 | "读错文件但输出相同"的缺陷**不可见** |
| **瞬时副作用** | 净差分（`batch-result.md` §4.3 已实证：`a.tmp` 建后即删不可见） | 同上 |
| **仅元数据写入** | 清单只收 size+hash | `attrib`/时间戳类行为不可见 |
| **注册表 / 服务 / 进程 / 网络** | 不在 L3 范围 | 143 个 C 类样本的关键行为缺失 |
| **`%ERRORLEVEL%` 语义细节** | 只采到进程退出码 | 中间命令的 rc 传播不可见 |
| **L1/L2（API/syscall）** | 无插桩 | 无法回答"用了哪个系统调用" |
| **W 侧自身的盲区** | W 采集器同样只做净差分 | **两侧盲区相同 ⇒ 共同盲区里的缺陷对 oracle 完全隐形**（最危险的一条） |

> **最后一条是本设计的根本限制**：oracle 只能发现"**在可观测通道上表现出来**"的转换错误。
> 它把"静默错误"缩小到"可观测通道上的静默错误"，而不是消除它。
