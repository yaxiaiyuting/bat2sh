## 3. 本 session 最有价值的三件事

### 3.1 🔴 J1 判据抓出了它自己的测试设计缺陷

第一次 A/B 两轮的 `baseline_manifest_hash` 不同。根因：baseline 清单在**上传样本之后**采集，
天然含各自的上传文件 → 两次"起点"必然不同。

**如果当初用的是朴素的差分判据，这个缺陷会完全不可见**（差分两次都是干净的）。
这直接印证了设计阶段的核心判断：

> **清单差分是自归一化的，无法证明隔离。** 回滚失败时，残留文件在 before/after 中
> 都存在且哈希相同 → 落进 `unchanged` → **差分里看不见** → 系统性假通过。

→ 必须用 **J1（起点同一性）+ J2（绝对清单无污染）+ J3（样本有效性防平凡成立）**。

### 3.2 🔴 一次被受控实验推翻的因果推断

首轮采集发现"首次文件清单耗时 51 s"，我归因为"Windows 启动 I/O 争用"，
并把 `--settle-ms` 从 0 改成 10000，写下"静置不是成本而是净收益"。

**受控实验推翻了它**：真正的根因是 **PowerShell `Get-ChildItem -Path` 收到不存在的路径
会产生 ~30–40 s 固定开销**。

| manifest 范围 | 耗时 |
| :--- | ---: |
| `C:\poc` | 2.7 s |
| `C:\poc` + **不存在的** `C:\iso-probe` | **39.7 s** |

**这个坑在本场景是必然发生的**：探针目录 `C:\iso-probe` 正是被回滚掉的，
所以每次**基线清单**时它都不存在 —— **回滚越干净，bug 越必然触发**。

修复（先 `Test-Path` 过滤）后首次清单从 43 s 降到 3.7–4.4 s；
重测 settle 得出**相反结论**：settle=0 总周期更短（21.1 s vs 34.7 s），默认值已改回 0。

> **教训**：把两个同时变化的量（settle、scope 是否含不存在路径）之间的**相关性当成了因果**。
> "看起来合理的机制解释"极具欺骗性 —— 它让错误结论显得很有道理。
> 纠错靠**单变量受控实验**，不是更仔细地思考。

### 3.3 ✅ 覆盖层让「关机路径」与「确定性」解耦

```\n写入只落覆盖层 → base 永远只读 → base 的 NTFS 永远干净\n→ 每次启动都从同一份干净 base 开始 → 与上一次怎么关机无关\n```

**推论（实测证实）**：可以用 **`virsh destroy` 硬断电**回滚（442 ms），
**不必等 Windows 优雅关机** —— 脏状态落在**即将被丢弃**的覆盖层里。
优雅关机只在**建立基线那一次**必要。

这条在设计阶段不易看出（B/D 方案同样受益，但 C 的 O(1) 回滚让它最显著）。
