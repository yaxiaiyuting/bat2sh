## 3. 逐条分析

### 3.1 `w1` —— **R4：`if errorlevel` 条件恒真 ⇒ 静默误删** ✅ 真机确认

| | W（cmd） | L（产物） |
| :--- | :--- | :--- |
| rc | 0 | 0 |
| stderr | 空 | 空 |
| `fs_names.created` | `haystack.txt`, **`keep.txt`** | 仅 `haystack.txt` |
| `fs_content.only_in_w` | **`keep.txt`** | — |

**语义**：`findstr "needle" haystack.txt` **命中了**（haystack 确实含 needle）⇒ cmd 的
`if errorlevel 1` 为**假** ⇒ **不删 `keep.txt`**。
而产物是 `if ! grep … || true; then rm -f "keep.txt"; fi` ⇒ **恒真** ⇒ **删掉**。

⇒ **真实缺陷，完全静默（rc=0 / stderr 空 / 无 TODO），后果 = 数据丢失。**
**这是 Phase A `security-audit-misc.md` 高危 #1 的真机确认**，且与主 session 在 Linux 侧的独立复现（§Phase A §4）**完全一致**。

### 3.2 `w2` —— **H8：重定向目标当活 glob ⇒ 静默覆盖** ✅ 真机确认

| | W | L |
| :--- | :--- | :--- |
| rc | 0 | 0 |
| stderr | **「文件名、目录名或卷标语法不正确。」** | **空** |
| `fs_content.differs` | — | **`log1.txt` 内容被改写** |

**语义**：`echo replaced > log?.txt` —— cmd 把 `log?.txt` 当**字面文件名**，
`?` 在 Windows 文件名中非法 ⇒ **明确报错、不动任何文件**。
产物 `echo "replaced" >log?.txt` ⇒ bash 做 glob ⇒ **覆盖了无关的 `log1.txt`**。

⇒ **真实缺陷：cmd 拒绝，L 静默破坏数据。**

### 3.3 `w3` —— **R1：字面 `$()` 变活命令替换** ✅ 真机确认

| | W | L |
| :--- | :--- | :--- |
| `out3.txt` 长度 | **18 B** | **9 B** |
| `out3.txt` 内容 | 字面 `$(echo INJECTED)` + CRLF | **`INJECTED`** + LF |

**语义**：`set "P=$(echo INJECTED)"` —— cmd 里 `$` 是**普通字符**，`P` = **字面量**；
产物 `P="$(echo INJECTED)"` ⇒ bash **执行了命令替换**。

⇒ **真实缺陷：字面量被执行**。本例命令无害，但**任意命令可注入**。
**这是 Phase A R1 的真机确认**（Phase A 中由 4 个 subagent 独立报出）。

### 3.4 `w5` —— **`del /s` 递归删除不完整**（**oracle 新发现**）

| | W | L |
| :--- | :--- | :--- |
| stdout | `删除文件 - C:\poc\samples\root.tmp`<br>`删除文件 - C:\poc\samples\sub\x.tmp`<br>`done` | `done` |
| `fs_content.only_in_l` | — | **`sub/x.tmp` 残留** |

⇒ **真实缺陷**：cmd 的 `del /s` **递归**删掉子目录里的 `x.tmp`；
产物**没有递归** ⇒ **该删的没删**（残留）。
（Phase A 的 del 审查把 `/s` 相关项列为中危；**oracle 在此将其确认为真**。）

### 3.5 `w6` —— **`set /a` 里 `%n%*1024` ⇒ 脚本中止** ✅ 真机确认

| | W | L |
| :--- | :--- | :--- |
| rc | **0** | **1** |
| stdout | `5120` + `done` | **空** |
| stderr | 空 | `line 7: %n102…` 语法错 |

**语义**：`set /a size=%n%*1024` —— cmd 得 `5120`；产物 `$(( %n$*1024 ))` **语法错误**，
在 `set -euo pipefail` 下**整个脚本中止**。

⇒ **真实缺陷：脚本中途死掉，且此前副作用已发生**（半执行状态）。
**这是 Phase A misc 中危项的真机确认**，且后果比预估更重（**整个脚本中止**，不只是这一行错）。

### 3.6 `w4` —— **Phase C 的 `%%~n` 修复被真机差分验证** ✅ **正面结果**

| | W | L |
| :--- | :--- | :--- |
| rc | 0 | 0 |
| 全部通道 | — | **✅ 一致** |

样本在**含点祖先**（`my.project\samples`）下跑 `for /r %%i in (.) do @echo %%~ni`。
修复前该场景产 `my`/`my`（Phase C §2.1 实测）；**修复后 W 与 L 完全一致**。

⇒ **本 session 的 `_modifier` 修复通过真机差分 oracle**，不是只过了单测。

### 3.7 `w7` —— `xcopy` 仅 **stdout 保真度**差异（**非数据缺陷，低**）

| 通道 | 结果 |
| :--- | :--- |
| `fs_names` | ✅ **两侧完全相同**（4 文件 + 4 目录，逐项同名） |
| `fs_content` | ✅ **attributed**（比较 4 个文件，`differs=[]`，**逐字节一致**） |
| `stdout` | ❌ W 列 `src\a.txt`/`src\deep\b.txt`/「复制了 2 个文件」；L **无输出** |

⇒ **文件操作本身正确**，只是 `cp -r` 不如 `xcopy` 啰嗦。
**定级：低（表示层）** —— ⚠️ **不应当作数据风险报告**。

### 3.8 `w9` —— 错误可见性差异（**低**）

⇒ 文件系统状态一致，**仅错误可见性差异**。**定级：低**。

### 3.9 `w11` —— **源脚本自身在 cmd 下就是坏的** ⇒ **不可归因于 bat2sh**

| | W | L |
| :--- | :--- | :--- |
| rc | **255** | 0 |
| stderr | **「此时不应有 (goto。」**（cmd 语法错误） | 空 |

⇒ W 侧**源 `.bat` 本身就无法在 cmd 下解析**。**差分对 bat2sh 无鉴别力**。
**诚实分类：不可归因（W 侧源缺陷），不计入 bat2sh 缺陷。**

### 3.10 `w12` —— 退出码被 `|| true` 吞掉（**中**）

| | W | L |
| :--- | :--- | :--- |
| rc | **1** | **0** |
| stderr | `FINDSTR: 无法打开 1.txt` | `grep: 1.txt: No such file or directory` |

⇒ 两侧**都检测到文件缺失**，但 **L 的退出码被 `|| true` 守卫改写为 0**。
调用方若依赖 `%errorlevel%` 会走错分支。**与 R4 同根因**（守卫语义）。**定级：中**。

### 3.11 `w13` —— `for /f` 缺输入文件时错误被吞（**中**）

| | W | L |
| :--- | :--- | :--- |
| rc | **2** | **0** |
| stderr | 「系统找不到文件 a.txt。」 | **空** |

⇒ cmd **明确失败**；产物**静默成功**。**定级：中**（失败被吞 ⇒ 调用方无法察觉）。

### 3.12 `w14` —— **H4：`for /r` + `rd` 自删** ✅ 真机确认 **+ 关键更正**

| | W（cmd） | L（产物） |
| :--- | :--- | :--- |
| rc | **1** | **1** |
| stderr | 「**另一个程序正在使用此文件，进程无法访问。**」<br>「找不到批处理文件。」 | `rm: cannot remove '…/samples': **Device or resource busy**` |
| `fs_names` 删除项 | **{} ← 一项都没删** | **`w14.bat`（正在运行的脚本本身）** |

**这是本批最重要的单个结果**：

1. **确认 H4 是真缺陷** —— `for /r %%i in (.) do rd /s /q "%%i"` 的产物会**删掉正在运行的脚本**。
2. **更正 Phase A 的存疑** —— A-3 当时标注 `[cmd 侧未实测]`：cmd 是否会自删？
   **真机答案：不会。** cmd 因「文件正在使用」**拒绝删除，最终一项都没删**（`fs_names` 为空）。
   ⇒ **L 严格比 cmd 更具破坏性**，这是**行为偏差**，不是"两边都删所以无所谓"。
3. 产物侧 `rm` 对 CWD 本身也失败（`Device or resource busy`），但**成功删掉了脚本文件** ——
   即**部分执行**，留下更糟的中间状态。

## 4. 仪器纠正（主 session 自查，已重跑）

见 `oracle-samples-v2.md` §4.1。摘要：

定位后**丢弃全部首次 W 指纹、以正确 scope 重采 15 个**，本文件所有数据来自重采后口径。

**纠正前 → 纠正后**：`poc01` 由「不可归因（6 个 only_in_w 全是设施残留）」→ **「一致」** ✅。
