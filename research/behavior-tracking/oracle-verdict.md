## 2. 这一轮**没有**证明什么（防过度解读）

| 未证明 | 说明 |
| :--- | :--- |
| **覆盖率** | 只跑了 **5 个样本**。151 语料里 A 类只有 **4 个（2.6%）**，纯差分 oracle 的**可判定面天然极小** |
| **F1/F2/F3 的完整波及面** | 波及面是**静态模式扫描**的结果，不等于"每个命中文件都会错" —— 需逐个跑 oracle 才算数 |
| **bat2sh 整体的正确率** | 5 个样本里 4 个含缺陷，**不能**外推成"80% 的转换是错的"。这 5 个是**按覆盖度挑的**，不是随机抽样 |
| **回归保护** | oracle 的 W 侧每样本 **40–80 s**（冷启动+回滚+QGA）⇒ **不适合**当回归门。它定位是**深度抽检**，不是 CI 门禁 |
| **两侧共同盲区** | W 与 L 都是净差分。**读操作、瞬时副作用、仅元数据写入**在两侧**同时不可见** ⇒ 只在这些通道表现的转换错误，oracle **结构上发现不了** |

## 4. 方法论收获（可复用的部分）

1. **"最小规则集 + 规则留痕"是对抗假一致的关键。**
   先只加表示层规则，不够再加，每加一条都记录**它掩盖了什么**。
   本轮 4 次规则启用（N10×3、N11×1）全部可见，无一次静默抹平。

2. **"精确哈希"胜过"聪明的比较"。**
   N10/N11 不是模糊匹配，而是"`sha256(LF→CRLF(内容)) == W.Hash`"这类**可证等价陈述**。
   V2 的 138 B vs 202 B 因此能被**证明**为编码差异而非内容差异。

3. **诊断性重跑 > 猜测归因。**
   N13（中和 `set -e` 再跑）把"级联后果（D5）"与"根因（F1）"**用证据分开**，
   而不是靠人判断。这一条应推广到其它可疑规则。

4. **"命令位置 ∉ 内建白名单"胜过扩展名清单。**
   扩展名清单会**双向出错**：把 `del 模块\x.dll` 误判成外部程序，
   又漏掉 `CSty /chide`（无扩展名）。命令位置判据同时避开两类错误。

5. **对称性要从"目录名"这一级就开始管。**
   V5 的工作根命名（`samples` vs `run`）会直接制造假差异。
   采集设施的**每一个**自由参数都可能是假差异源。

## 6. 一句话结论

> **路 A 走得通，而且第一轮就打中了靶心。**
> 5 个"纯文件操作"样本里，**3 个暴露出独立的转换缺陷，其中 2 个完全静默**
> —— 它们被仓库既有的语料仪器判为"**功能完好（严格）**"，因为那个仪器只问
> "跑通了吗"，而 oracle 问的是"**和真机做的一样吗**"。
>
> 同时要说清代价：纯差分 oracle 的可判定面**天然只有 2.6%**（A 类 4/151），
> 且两侧盲区相同 ⇒ 它**缩小**而**不消除**"静默错误"的疆域。
> 它的价值不在覆盖率，而在**把差异逼到只剩转换错误这一种解释**。
