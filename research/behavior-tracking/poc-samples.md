# PoC 样本选取

> 时间：2026-09-26 · 状态：**已定稿，待 VM 就绪后执行**
> 目标：为「输出效果层」最小 PoC（§4.3）选取 1–2 个简单 `.bat`，满足**无交互 / 无环境依赖 / 行为明确**。

## 1. 选择标准

| # | 标准 | 理由 |
| :-- | :--- | :--- |
| C1 | **无交互** | `guest-exec` 不提供 stdin 通道；任何 `pause` / `set /p` 都会挂住或需特殊处理 |
| C2 | **无环境依赖** | 不依赖特定盘符（`E:\`）、不依赖外部程序（`adb`/`cscript`）、不依赖网络 |
| C3 | **行为明确** | 输出/副作用可预先推断，便于人工核对「指纹是否可信」 |
| C4 | **非破坏性** | 不写注册表、不改系统设置、不删用户 —— 即便快照可回滚，首次 PoC 也不该引入不可控噪声 |
| C5 | **许可干净** | 能入仓的优先；无许可语料**只引用不入仓** |

| `非常批处理`（2014 中文批处理合集） | `~/下载/非常批处理/` | — | **无许可** → 不入仓 |

### 2.1 量化扫描（`bat-master` + `非常批处理`，共 218 个 `.bat`/`.cmd`）

| 指标 | 数量 | 占比 | 对 PoC 的影响 |
| :--- | ---: | ---: | :--- |
| 含 `pause` 或 `set /p`（**交互**） | **117** | **53.7 %** | **违反 C1** —— 超过一半语料无法直接非交互执行 |
| 含 `wmic`/`reg add|delete`/`sc config`/`net user`/`shutdown`/`format`/`diskpart`（**环境依赖或破坏性**） | **52** | **23.9 %** | **违反 C2/C4** |

> **结论 1（对采集框架的要求）**：真实语料**过半是交互式**的。这是 2014 年代「双击运行」批处理的普遍形态（结尾 `pause` 防闪退）。
> 采集框架**必须**处理交互，否则覆盖率直接砍半。最小可用解法见 §4。

> **结论 2（对采集框架的要求）**：近 1/4 语料会**修改系统状态**（注册表、服务、用户账户）。
> 这使得**「快照回滚」不是优化项而是必需项**——否则第二个样本就被第一个污染。

## 3. 选定样本

### P1 — `poc-01-stdout.bat`（自建，入仓）

**用途**：证明最小通路 —— 传脚本 → 执行 → 捕获 stdout / stderr / 退出码。

```bat
@echo off
echo POC-01-START
echo plain line
echo tab	separated
echo caret ^& ampersand
echo percent %% literal
echo POC-01-END
exit /b 7
```

| 覆盖点 | 说明 |
| :--- | :--- |
| 多行 stdout | 验证捕获完整性（不丢行、不乱序） |
| 特殊字符 | `&`、`%`、Tab —— 验证无 shell 二次解释、无转义损坏 |
| **非零退出码 `7`** | 验证 `exit_code` 字段真实反映脚本意图，而非被 `cmd.exe` 吞掉 |
| C1–C5 | 全部满足 |

> **为什么自建而非选语料**：仓库内 9 个夹具无一适合；外部语料无许可不能入仓。
> 自建样本是**唯一可入仓、可复现、许可干净**的选择，且能精确控制覆盖点。

### P2 — `poc-02-fileops.bat`（自建，入仓）

**用途**：证明**文件系统差分**通路（写 / 读 / 复制 / 删除）。

```bat
@echo off
setlocal
set "WORK=%~dp0work"
if not exist "%WORK%" mkdir "%WORK%"
echo alpha>"%WORK%\a.txt"
echo beta>"%WORK%\b.txt"
copy /y "%WORK%\a.txt" "%WORK%\c.txt" >nul
type "%WORK%\b.txt"
del "%WORK%\b.txt"
endlocal
exit /b 0
```

预期差分（执行前 → 执行后）：

| 路径 | 变化 | 可被 diff 观测？ |
| :--- | :--- | :--- |
| `work/` | 新建目录 | ✅ |
| `work/a.txt` | 新建（内容 `alpha`） | ✅ |
| `work/b.txt` | 新建后**删除**（净变化 = 无） | ⚠️ **净差分看不到** —— 见 §5 |
| `work/c.txt` | 新建（复制自 a.txt） | ✅ |
| `work/a.txt` 被 `copy` **读取** | 读操作 | ❌ **净差分看不到** |

| 覆盖点 | 说明 |
| :--- | :--- |
| 目录创建 / 文件写 / 文件复制 / 文件删除 | 四种副作用 |
| stdout（`type` 输出 `beta`） | 与 P1 互补 |
| C1–C5 | 全部满足 |

## 4. 交互性处理方案（P3 及 53.7% 语料的前置条件）

`pause` 从 stdin 读一个键；**stdin 在 EOF 时 `pause` 立即返回**。因此：

```bat
cmd.exe /c "C:\poc\call-1.bat" < nul
```

`guest-exec` **不支持** stdin 重定向参数，但可在**命令行内部**做重定向（如上，`cmd /c` 的整条命令串里带 `< nul`）。

| 方案 | 做法 | 评价 |
| :--- | :--- | :--- |
| **S1（推荐）** | `cmd /c "script.bat" < nul` | 一行解决；`pause` 打印提示后立即返回，行为可预测 |
| S2 | 执行前用 `more`/`findstr` 剥离 `pause` 行 | **篡改被测对象**，破坏「行为真值」语义 → 不用 |
| S3 | 提供 stdin 管道（`guest-exec` 无此能力） | 需自建 guest 侧 runner；留待 API/syscall 层 session |

> **本 PoC 采用 S1。** S1 的副作用：stdout 会多出一行 `请按任意键继续. . .`（本地化文本），
> 指纹归一化时需按行白名单剔除。

## 5. 净差分的能力边界（必须预先声明）

「执行前 / 执行后」全量快照对比是 **净差分**，它**只能看到最终状态变化**，看不到过程：

| 不可见的行为 | 例子 | 影响的层 |
| :--- | :--- | :--- |
| **读操作** | `type`、`copy` 的源文件读取、`if exist` 探测 | L2 系统调用 |
| **瞬时副作用** | 建了又删的文件（P2 的 `b.txt`）、临时文件 | L2 |
| **同内容覆写** | 内容不变的重写（mtime 可能变） | L2 |
| **纯内存计算** | P3 的递归（无任何文件副作用） | L1 API |

> **这是本 PoC 的天花板，不是 bug。** 要跨过它需要：
> ① 打开 NTFS last-access 时间（`fsutil behavior set disablelastaccess 0`）→ 可观测部分读；
> ② 对象访问审计（`auditpol`）→ 可观测打开/读取；
> ③ 文件系统过滤驱动 / minifilter → 完整 L2；
> ④ ETW / API hook → L1。
>
> ①②**无需写内核代码**，是本 PoC 之后**性价比最高的下一步**；③④ 属于下一 session 的 API/syscall 层。

## 6. 编码问题（预期会遇到的坑）

| 事实 | 影响 |
| :--- | :--- |
| 语料 218 个文件中大量为 **GBK/CP936**（v1.4.1 统计：107/151 为 GBK） | 脚本正文按 GBK 存盘 |
| `cmd.exe` 控制台默认代码页 = 系统区域设置（zh-CN → **CP936**） | GBK 脚本 → 输出正常 |
| 但 `tests/fixtures/` 的夹具是 **UTF-8（部分带 BOM）** | UTF-8 正文在 CP936 控制台下 → **乱码输出** |
| `guest-exec` 返回 **base64** 编码的原始字节 | 宿主侧须**显式按正确代码页解码**，否则指纹里全是乱码 |

**处置**：
1. PoC 的 P1/P2 用**纯 ASCII** 编写，先隔离「通路是否通」与「编码是否正确」两个问题（**本 session 只验证前者**）。
2. 编码作为**独立变量**留到下一轮：P3（GBK）执行前先 `chcp 936`，并把原始 base64 与解码结果**双双存档**，避免不可逆的有损转换。
3. 指纹 JSON 中 stdout **必须存 base64 原文**，解码文本仅作人类可读附注。
