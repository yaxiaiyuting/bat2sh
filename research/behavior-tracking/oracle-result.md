## 2. 可归因差异（逐条）

### 2.1 V2 —— 产物编码与行尾（D3 + D2）

| 哈希 | W | L |
| :--- | :--- | :--- |
| `Hash`（原始字节） | `49F6850A…` | `A6074FE0…` ✗ |
| `hash_lf_to_crlf` | — | `8E18B4AA…` ✗ |
| **`hash_cp936_crlf`** | — | **`49F6850A…`** ✅ **与 W 相等** |

判据链：`W.Hash == L.Hash`❌ → `W.Hash == L.hash_lf_to_crlf`❌ → **`W.Hash == L.hash_cp936_crlf` ✅**

**含义（精确陈述）**：L 产出的 `a.txt` 与 W 产出的 `a.txt` **逐字节相同**，
差异仅为 UTF-8→CP936 编码与 LF→CRLF 行尾 —— 都属于**平台表示层**（D3 / D2），
不改变文件内容这一行为事实。**故判可归因。**

> ⚠️ 报告里明确记录了"**N11 掩盖了 CP936 vs UTF-8 的字节差**"。
> 若 bat2sh 把中文写成乱码，`hash_cp936_crlf` 不会命中 ⇒ 仍会被判不可归因。

## 3. 不可归因差异（逐个分析）

### 3.1 **F1 —— `type` 命令的 `\` 未转换**（V3、V4、`other.bat`）

**现象**（V4）：

| | W | L |
| :--- | :--- | :--- |
| rc | 0 | **1** |
| stdout | `source-alpha\r\n` | **`''`** |
| stderr | `''` | `cat: '…/work\c.txt': No such file or directory` |
| 副作用 | `work/b.txt` 被删（V3） | **`b.txt` 残留** |

**根因（最小复现，已确认）**：同一个脚本、同一个 `\`，**只有 `type` 不转换**：

```bat
set "W=%~dp0sub"
mkdir "%W%"              →  mkdir -p "${W}"                    ✅ \ → /
echo data>"%W%\f.txt"    →  echo "data" >"${W}/f.txt"          ✅ \ → /
copy /y "%W%\f.txt" …    →  cp -f "${W}/f.txt" …               ✅ \ → /
type "%W%\f.txt"         →  cat "${W}\f.txt"                   ❌ \ 保留
del "%W%\f.txt"          →  rm -f "${W}/f.txt"                 ✅ \ → /
if exist "%W%\f.txt"     →  if [ -e "${W}/f.txt" ]             ✅ \ → /
dir /b "%W%"             →  ls -1 "${W}"                       ✅ \ → /
findstr "data" "%W%\g"   →  grep "data" "${W}/g.txt" || true   ✅ \ → /
```

`cat "${W}\f.txt"` 在 bash 里是**字面文件名** `…/sub\f.txt`（反斜杠是合法文件名字符）⇒ 必然找不到。

**影响链**（V3 完整展示了级联）：

```
type 失败 → stdout 空
         → set -euo pipefail 触发提前中止      ← D5（可归因部分）
         → 后续 del 未执行 → work/b.txt 残留   ← 级联后果
```

**N13 诊断重跑（中和 `set -e`）把两部分分开了**：

| | rc | fs 名称 | stdout | 结论 |
| :--- | :--- | :--- | :--- | :--- |
| W | 0 | `work/a.txt` `work/c.txt` | `beta` | 基准 |
| L（正式） | 1 | `work/a.txt` `work/b.txt` `work/c.txt` | `` | 混合 |
| **L（N13 诊断）** | **0 ✅** | **一致 ✅** | **`` ❌** | 级联 = D5；**残留差异 = F1** |

⇒ **级联部分归因于 D5（`set -e` vs cmd 继续），但 F1 本身是真实缺陷**，`set -e` 只是放大了它的后果。

**是否静默**：**半静默**。stderr 有 `cat: … No such file`，但
① 退出码被污染（0 → 1）、② 后续操作被静默跳过、③ 脚本本身**无 `# TODO`**。

**波及面（151 语料静态扫描）**：`type` 出现于 **8** 个文件；其中路径带 `\` 的 **2** 个。

### 3.2 **F2 —— `for /d` 集合的末元素被当成通配符**（V1）

**现象**：W 建 3 个目录，L 只建 2 个 —— **`其他` 静默消失**。

| | |
| :--- | :--- |
| rc | **0（两侧都是 0）** |
| stdout / stderr | **两侧都为空** |
| `# TODO` | **无** |

**根因（最小复现，已确认）**：

```bat
for /d %%i in (aa,bb,cc) do md %%i
```
```bash
shopt -s nullglob                      # ← bat2sh 自动加
for i in aa bb cc/*/; do               # ← 末元素被追加 /*/
    mkdir -p ${i}                      # ← 且未加引号
done
```

**位置依赖性已实测**（4 组）：

| 源集合 | 生成 |
| :--- | :--- |
| `(aa)` | `for i in aa/*/; do` |
| `(aa,bb)` | `for i in aa bb/*/; do` |
| `(aa,bb,cc)` | `for i in aa bb cc/*/; do` |
| `(aa,bb,cc,dd)` | `for i in aa bb cc dd/*/; do` |

⇒ **总是最后一个元素**被追加 `/*/`。配合 `shopt -s nullglob`，若该 glob 不匹配任何目录，
整个词**被静默删除**，循环体不执行。

> 反向也会错：若 `cc/` 下**确有**子目录，`cc/*/` 会匹配它们并 `mkdir -p`，
> 于是建出**源脚本从未要求的目录**。两种方向都是错的。

**对照**：同形但无 `/d` 的 `for %%i in (aa,bb,cc)` **转换正确**（`for i in aa bb cc`）
⇒ 缺陷**特定于 `for /d`**。

**是否静默**：**完全静默**（rc=0、stdout/stderr 全空、无 TODO）—— 用户不会知道少建了一个目录。

**波及面**：`for /d` 出现于 **2** 个文件；其中带逗号列表的 **1** 个（V1）。

### 3.3 **F3 —— `for /r` + `%%~ni` 产出错误文件名**（V5）

**现象**：W 建 `samples.txt`（以工作根目录名为名），L 建出一个**字面文件名** `.\.txt`。

| | |
| :--- | :--- |
| rc | **0（两侧都是 0）** |
| stdout / stderr | **两侧都为空** |
| `# TODO` | **无** |

**根因**（产物第 9 行，`od -c` 实证含 `\ \ $ (`）：

```bat
for /r %%i in (.) do ( cd.>"%%i\%%~ni.txt" )
```
```bash
while IFS= read -r i; do
    cd "." >"${i:-}\\$(basename "${i%.*}").txt"
done < <(find . -type d)
```

三处偏差：
1. `%%i` → `${i:-}`（多了"默认为空"）；
2. `%%~ni` → `\\$(basename "${i%.*}")` —— `\\` 在双引号内成为**字面反斜杠**；
3. `$(basename …)` 因 `${i%.*}` 在 `i="."` 时**整体被剥空**而展开为空。

净效果：`. ` + `\` + `` + `.txt` = **`.\.txt`**（6 字符，`od -c` 实测 `. \ . t x t`）。

**是否静默**：**完全静默**（rc=0、stdout/stderr 全空、无 TODO）。

**波及面**：`for /r` 出现于 **6** 个文件；`%%~n` 系列（`~n`/`~nx`/`~dp` 等）出现于 **12** 个文件。

### 3.4 **F4 —— `C:\…` 绝对路径变成 cwd 相对的 `C:/…`**（V4）

**现象**：`mkdir "C:\iso-probe"` → `mkdir -p "C:/iso-probe"`，
在 Linux 上落到 **`<工作根>/C:/iso-probe/`**（把 `C:` 当普通目录名，相对 cwd）。

| | W | L |
| :--- | :--- | :--- |
| 落点 | `C:\iso-probe\from-a.txt`（**工作根之外**，绝对路径） | `<工作根>/C:/iso-probe/from-a.txt`（**工作根之内**，相对路径） |
| 是否可见 | W scope 未含 `C:\iso-probe` ⇒ 指纹里不可见 | 在清单范围内 ⇒ 可见 |

**判决：不是静默缺陷，登记为已知行为。** 依据（**只读仓库文档，非猜测**）：

> `docs/2.x-roadmap-research.md:137` —— 「盘符 (`C:\`) → 挂载点 | **不做 / 保持 backlog** |
> 集成净损 **6 strict** + 挂载点不可静态判定」
> 同文件 `:371` —— 「6 不发明映射 | … 盘符/UNC → 不做」

即 **bat2sh 有意不做盘符映射**。故这是**已决定的产品行为**，不是"没人知道的转换错误"。

⇒ 按 `oracle-design.md` §4.3，补入 D-list 作 **D15**（见 §5）。

> ⚠️ 残留风险（**留待产品侧决定，本 session 不修**）：该行为对用户**无任何告警** ——
> 一个把日志写到 `C:\logs\` 的脚本，在 Linux 上会静默写进 `./C:/logs/`。
> v2.10.0 已为 LF-only 行尾与 `start` 模态框加过告警，此处是否也该加，属产品决策。

**归因尺度说明**：F4 **没有**被判为"平台差异"就此放过 ——
按 `oracle-design.md` §6.1，路径映射与命令名映射**同属被检验对象**。
之所以最终算"已知"，是因为**仓库里有明确的不做决定**，而不是因为"Linux 就是这样"。

## 4. 归一化规则的漏洞与修正（任务书 §4.3）

设计明确规定：**归一化规则的漏洞 → 修正规则，重跑**。本轮修了 2 处，均**主动披露**：

| # | 修正 | 原设计 | 改成 | 触发原因 | 代价 / 保留的判别力 |
| :-- | :--- | :--- | :--- | :--- | :--- |
| **A1** | **N6 升入严格档** | N6（路径分隔符）在**归因档** | N6 进**严格档**（`STRICT_RULES`） | 实测：W 的清单键恒用 `\`、L 恒用 `/` ⇒ **任何写文件的样本都不可能判"一致"**，"一致"类变成空集，报告全部退化为"可归因"，判别力反而下降 | `\` vs `/` 与 N1（CRLF vs LF）**同性质**（平台表示层约定，不改变"指向哪个文件"）。**N6 仍只对 `<WORK>` 前缀生效** —— 工作根之外的差异（F4）**照旧暴露** |
| **A2** | **N5 也作用于文本通道** | N5 只映射路径 | N5 同时映射 stdout/stderr 中出现的**工作根绝对路径** | L 的 stderr 含**每次运行都不同**的沙箱路径（`/tmp/bat2sh-oracle/copy-1790434237842/samples/…`）⇒ 任何含路径的错误信息**恒定假报不一致** | 映射源取 `rollback.run_dir`（指纹自带，非猜测）；只替换该前缀 |

另修一处**报告缺陷**（非规则）：文件内容比较原先包含了**采集器自己放进沙箱的产物**
（W 是 `.bat`、L 是 bash），二者**按构造就不同**，属恒定噪声。
改为按 `filesystem.known_artifacts` **排除**（与 `created` 的既有口径一致）。

> ⚠️ **A1 是对用户已确认设计的偏离**，按纪律 2 主动披露。
> 用户确认的版本见 `oracle-design.md` §5；本文档与 `compare.py` 的注释记录了偏离理由。
> **它没有放宽对 F4 的判定**（F4 仍被判为差异，只是依据文档改判为"已知行为"而非"平台差异"）。

### 6.1 与既有测量仪器 `measure.py` 的对照（**"静默"一词的实证**）

把 4 个样本丢给仓库既有的语料仪器（`tools/corpus-analysis/measure.py`，
口径 = `ConvertSettings(bash_check=False)` + bwrap + 「`rc==0` 且无 TODO」= **功能完好（严格）**）：

```bash
python3 tools/corpus-analysis/measure.py --corpus /tmp/silent-check --out /tmp/silent-check-out --json
# {"corpus": 4, "syntax_ok": 4, "rc0": 2, "strict": 2, "degraded": 0, "crash": 0, …}
```

| 样本 | 既有仪器 | oracle 判定 | 是否一致 |
| :--- | :--- | :--- | :--- |
| **V1** `快速创建文件夹.bat` | `rc=0` `todo=0` ⇒ **严格通过** ✅ | ❌ **少建一个目录** | **不一致** |
| **V5** `以文件夹名为名建立文本文件.cmd` | `rc=0` `todo=0` ⇒ **严格通过** ✅ | ❌ **产物文件名完全错误** | **不一致** |
| V3 `poc-02-fileops.bat` | `rc=1` | ❌ 读失败 + 删除被跳过 | 一致（都报错） |
| V4 `copy.bat` | `rc=1` | ❌ 读失败 + 路径落错 | 一致（都报错） |

> **V1 与 V5 被既有仪器判为"功能完好（严格）"，但行为是错的。**
> 这正是本 session 要找的**第三类不一致**：不是语法错误、不是 TODO、不是崩溃、不是超时，
> 而是**跑得通、看起来对、结果错**。既有的 `rc0/strict` 指标**结构上无法**发现它们 ——
> 因为指标只问"跑通了吗"，而 oracle 问的是"**和真机做的一样吗**"。

> ⚠️ **反过来也要说清**：这不意味着 `measure.py` 有缺陷。它的口径是**静态可量产**的
> （151 语料全跑一遍的成本可接受），而 oracle 的 W 侧每样本需约 **40–80 s**
> （冷启动 + 回滚 + QEMU 代理）。两者是**不同成本档位的仪器**，oracle 不能替代前者做回归门。
